# AutoPets 화면 점검

기준은 모두 `docs/development/ux-review/`에 있어요. 먼저 그 폴더의 README.md를 읽고, 그 순서를 따라요. 이 파일은 순서를 요약할 뿐 기준을 새로 만들지 않아요.

1. **범위**: 사용자가 말한 화면이나 바뀐 파일, 그리고 그 화면에서 사용자가 하려는 일 한 가지를 정해요. 바뀐 파일은 `git diff --name-only origin/main...`으로 찾을 수 있어요.
2. **자동 점검**: `pnpm ux:check --files <범위의 파일...> --all --json`. 화면 이미지가 필요하면 `pnpm test:ui`가 남긴 `work/after-*.png`를 쓰거나 `pnpm dev`로 띄워요. 사용자의 데스크톱을 조작하지 말고, 헤드리스로 찍어요.
3. **다섯 관점을 따로**: `docs/development/ux-review/personas/`의 다섯 파일을 각각 하나의 하위 에이전트에 맡겨요. 각 에이전트에는 그 관점 파일 경로, 범위, 목표 일, 자동 점검 결과, 화면 이미지 경로만 주고, 다른 관점의 결과는 주지 않아요.
   - Claude Code: `ux-first-timer`, `ux-copy-editor`, `ux-trimmer`, `ux-measurer`, `ux-honesty` 에이전트.
   - Codex: 같은 다섯 파일로 하위 작업 다섯 개. 읽고 보고만 하는 일이라 가벼운 설정이면 충분해요.
4. **합치기**: 같은 문제는 묶고, 두 관점 이상이 짚었거나 숫자로 확인된 것을 위로. 정직 관점과 부딪히는 제안은 버려요. 우선순위는 막힘 → 잘못된 상태 → 불필요한 조작 → 보기 좋음.
5. **고치기(요청받았을 때만)**: 담당 범위 안에서만(`pnpm ui:scope <담당> <파일...>`). 흐름·데이터·연결 방식을 바꾸는 제거는 `회의 필요`로 남기고 고치지 않아요. 고친 뒤 `pnpm ux:check`, 관련 UI 검사, 숫자 재기를 다시 해요. 문구가 줄어 기준선 항목이 없어졌으면 `pnpm ux:check --update-baseline`.
6. **보고**: `docs/development/ux-review/report-template.md` 양식으로. 근거 수준(합성 검사 / 실제 실행 / 디자인 예시)과 숫자를 잰 방법을 꼭 적어요.

지킬 것: 점검은 사람의 검토를 대신하지 않아요. 개인 경로·대화 내용·계정 정보를 보고서와 이미지에 넣지 않아요. 다른 담당의 파일은 합의 없이 고치지 않아요.
