# 한 번 호출로 시작 — 구현과 검수

시작 도구: `integrations/codex/bootstrap`. 화면: 기존 연결 설정과 대기 펫. 앱 연결: 인증된 `GET/POST /v1/setup`, 화면 명령 `get_setup_state`. 설치 상태는 기존 업무 DB와 별도의 `setup-state-v1.json`에 저장합니다. 저장소의 기본 도움 정책은 바꾸지 않고 사용자가 시작 도구를 실행한 경우만 새 채팅 기본값을 켭니다. 기존 채팅과 직접 설정한 기본값은 보존합니다.

`SetupState`는 앱 준비, 채팅 연결, 자동 도움 전달, 모델/추론/제출 보호를 구분합니다. 실제 자동 도움 capability는 그대로 미검증입니다. `InstallManifest`는 버전·파일 해시·앱 경로·소유 훅·소유 스킬·완료 단계를 기록합니다. 연결 token, 프롬프트, 도구 출력은 기록하지 않습니다.

사용자 연결은 고정 runner를 사용합니다. 관측과 준비는 별도 핸들러입니다. 채팅 ID 해시별 설정에 작업 경로를 바인딩하고 다른 채팅의 기록을 가져오지 않습니다. 기존 프로젝트 어댑터와 사용자 어댑터는 같은 제출의 중복을 제거합니다. 이미 배포된 옛 어댑터는 해당 배포 버전으로 갱신해야 하며, 자동으로 프로젝트를 뒤져 수정하지 않습니다.

## 자동 검사

- Node: 첫 시작·재호출·부분 복구·취소·다른 버전 유지·소유권·동시 호출·해시 변조·경로 이탈·두 채팅 분리·중복 지침/보류.
- Rust: 인증된 시작 API, 가짜 세션 미생성, 기존 채팅 보존, 새 기본값, 끄기 유지, 재시작 후 검증 상태.
- 화면: 설치와 채팅 연결의 구별, 미검증 보호 표시, 대기 펫의 종료 메뉴.
- Windows CI: 임시 Codex 프로필과 별도 데이터 경로에서 NSIS 설치·번들 Node 실행·인증 브리지·재호출·연결 제거·종료 후 훅 미재실행. 개발자의 실제 프로필을 쓰지 않습니다.

## 별도 실제 환경 관문

공개 릴리스, 서명/실행 허용, Codex 훅 신뢰 화면, 같은 채팅의 훅 재로딩, 두 새 채팅 전달, 실제 모델/추론/Plan 보호는 별도 검증입니다. CI 앱 실행은 이 관문을 통과시키지 않습니다. 최초 호출 비용과 확인할 수 없는 토큰 절감량은 추정하지 않습니다.

공개 채널은 관문 통과 전 `publicRelease: null`을 유지합니다. 설치 링크는 이 상태를 숨기지 않습니다.
