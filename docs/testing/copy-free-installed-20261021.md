# 복붙 없는 기본 흐름 — 설치형 검사

2026-10-21. **기존 Codex 채팅 연결 → 설치 앱에서 펫 적용 → 같은 채팅의 계획·구현 → 결과 복귀·재시작 복구**를 전용 B에서 확인했다. 펫 ID, 역할 지침, 스킬·모델 설정을 요청문에 붙여넣지 않았다.

이번 요청은 승인받은 시험 채팅에 Codex의 메시지 도구로 전달했다. **직접 타이핑한 일반 입력이나 자동 훅의 새 검증은 아니다.** 설정 적용은 실제 설치 앱의 버튼으로 수행했으며, 앱이 요청문을 자동 전송한 것은 아니다.

## 재현한 흐름

1. 앱이 종료된 상태에서 B에 `AutoPets 스킬로 제작 펫 연결해줘. 지금은 연결만 하고, 새 펫 작업은 실행하지 마.`를 전달했다.
2. 설치된 스킬이 현재 작업 ID·폴더를 확인하고 `pet.mjs connect`를 실행했다. 앱과 오버레이가 열리고 인증된 로컬 통신이 준비됐다. 새 하위 작업은 0회였다.
3. 앱에서 **펫 고르기 → 웹페이지 만들기 → 이 펫으로 → 가볍게 → B 선택 → 이 채팅에 펫 적용**을 수행했다. 저장 후 재조회에서 B의 기존 표준 설정이 가볍게로 바뀌었다. A와 실행 요청 수는 그대로였다.
4. **Codex 작업 열기**로 B에 돌아가 가상 학과 행사 페이지의 계획만 요청했다. 앱 입력·복사 버튼은 사용하지 않았다.
5. 계획을 검토한 뒤 같은 채팅에 구현을 요청했다. 새 `autopets-copy-free-demo` 폴더만 사용하도록 했다.
6. 앱의 **결과 보러 가기**로 B를 열었다. 화면의 전용 채팅명과 도구로 확인한 대상이 일치하고 입력창은 비어 있었다.
7. 앱 메뉴로 정상 종료한 뒤 재실행했다. B에 상태 확인만 요청해 같은 결과를 복구했다.

## 지침·스킬·라우팅의 증거 수준

- 준비 응답에 저장한 역할·계획 지침, 고정 스킬과 읽기 도구가 존재했다.
- 계획·구현의 실제 자식이 `frontend-design` 버전 `41bbe19d1a1a7eaab5e7bb9050a417e5c6cffc8f`를 읽은 반환 내용과 해시를 대조했다.
- native 위임 인수와 자식 실행 기록이 모두 `gpt-6-luna / low`, 별도 문맥(`fork none`)으로 일치했다. 이것은 호스트 실행 요청 기록이며 서버 내부 처리 모델까지 증명하는 것은 아니다.
- 최초 메시지가 자식의 첫 모델 출력 전에 전달된 것은 확인했다. 다만 기록의 메시지가 암호화되어 **준비한 지침 전체와 최초 전달 평문의 일치는 독립 검증하지 못했다.**
- 계획 중 변경 없음, 명시적 구현 요청 후 변경이라는 응답 이행은 확인했다. 실제 Plan 모드의 강제 제한으로 표시하지 않는다.
- 시험 부모도 낮은 설정으로 실행했지만 이는 검사 도구의 지정이다. **AutoPets의 부모 모델 제어 성공으로 계산하지 않는다.**

## 생성 결과의 별도 검사

실제 결과 HTML을 브라우저에서 열어 1366·992·390·320px를 검사했다. 가로 넘침, JavaScript 오류, 외부 요청은 0건이었다. 내부 링크, Tab/Enter, 본문 바로가기, 모바일 메뉴, 폼의 정상·오류 입력을 확인했다. 신청은 화면용 데모이며 네트워크 전송·저장은 없었다.

품질 한계도 남았다. 제목이 단어 중간에서 부자연스럽게 줄바꿈되고, 이름에 공백만 넣어도 데모 제출이 가능했다. 모바일 메뉴의 Esc 닫기도 없다. 시험 결과 원본은 수정하지 않았다. **연결·라우팅의 통과와 결과물의 완성도는 별도다.**
