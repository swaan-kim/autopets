# 1단계 — 설치와 앱 기본 작동

2026-09-25. 별도 Windows 개발 검증과, 이후 사용자가 조작을 허용해 수행한 현재 PC 검증을 모았다. 이번 범위는 설치·화면 표시·재호출·정상 종료·데이터 보존·제거·재설치다. AI 연결 활성화, 모델 라우팅, 펫 오버레이 상세 동작은 포함하지 않는다.

## 현재 판정

**현재 PC 기준 1단계 통과.** 별도 Windows에서 검증한 설치본으로 현재 PC의 설치 → 실제 창 표시 → 재호출 → X 숨김·복원 → 실제 종료 버튼 → 재시작 → 제거 → 재설치 → 실제 앱 재실행을 완료했다. 기존 DB·펫 위치·AI 설정을 보존했고, 앱을 실행해 사용할 수 있게 남겼다. [현재 PC 상세 기록](current-pc-lifecycle.md)에 백업·실측·도구 오류·판정 한계를 분리해 기록했다.

아래 CI 실측값은 별도 Windows의 기록이다. 현재 PC의 설치 28.220초·제거 3.926초·재설치 16.374초와 구분한다. 현재 PC 성공을 개발 도구·런타임 없는 다른 PC의 설치 성공이나 공개 배포 완료로 확대하지 않는다.

## 최종 설치본과 실행 증거

- 설치본 소스: `5bc20b01f5a56ed469e18fb9da4bdcaa6168646d`, AutoPets 0.1.0. [Windows 빌드 및 연속 검사](https://github.com/swaan-kim/autopets/actions/runs/36117429432) 모두 성공.
- 설치기 SHA256: `9fcf14403b9b01fbb4655f078aefa6549cbcb0ef18b590d0375318585129eba1`. 243,253,316 bytes, 약 232MiB. 서명 상태 `NotSigned`를 CI 및 로컬 파일 조회로 확인했다. 이후 현재 PC에도 같은 해시의 설치본을 설치·제거·재설치했다.
- 최종 검사 도구: `7814d079ed0656b06b344bf6f66e95aa02d1a34d`. 같은 설치본으로 [보완한 검사 도구의 최종 실행](https://github.com/swaan-kim/autopets/actions/runs/36119545084)도 성공. 이 도구 커밋과 설치본 소스 사이에 제품 코드 변경은 없다.
- Node 160개, Rust 101개 통과. Rust의 별도 설치 fixture 1개는 일반 검사에서 제외되며, 이번 연속 검사는 설치된 앱의 API로 실제 테스트 기록을 생성한다. 프런트엔드 빌드·렌더링 검사·PowerShell 구문 검사도 통과했다.
- 빌드 Job은 16분 10초, 최종 연속 검사 Job은 2분 8초. 개발 작업 시간이며 설치 시간과 구분한다.

아래 실측값은 마지막 실행 기준이며 기계·부하에 따라 달라질 수 있다. 설치 시간은 별도 검사 프로세스 안에서 설치기 호출부터 하위 프로세스를 포함한 완료까지 잰다. 종료 시간은 실제 종료 버튼 InvokePattern 호출 직전 시각부터 앱 프로세스 종료까지다.

설치한 앱을 다시 사용할 수 있고 정상 종료된 상태로 CI 검사를 마쳤다. 임시 CI 환경은 작업 종료 후 폐기된다. 이후 현재 PC에는 같은 수정본을 재설치해 실행 중인 상태로 남겼다. CI와 현재 PC 모두 실제 종료 버튼과 재설치 후 화면을 확인했다.

## 확인된 문제와 변경

이전 설치본을 1024×768 Windows 화면에서 실행했을 때 창 외곽이 1044×788로 보고됐고, 종료 버튼까지 스크롤해야 했다. 같은 종료 접근성 문제를 렌더링 검사에서도 재현했다. 960×640 뷰포트에서 버튼 위쪽 좌표가 약 988px로 화면 아래에 있었고, 700px 이하 너비에서는 기존 CSS가 종료 영역을 숨겼다.

- 처음 창을 표시하기 전에 모니터 작업 영역·배율·실제 창 테두리를 반영해 크기와 위치를 조절한다. 작업 표시줄 공간을 침범하지 않게 여백을 둔다. 작은 작업 영역에서는 최소 창 크기도 줄인다.
- 사이드바를 화면 높이에 맞추고 짧은 화면에서 간격을 줄였다. 좁은 화면에서도 `AutoPets 종료`를 유지한다. 본문 스크롤과 종료 버튼 접근을 분리했다.
- 960×640, 912×449, 640×480 렌더링 검사에서 스크롤 없이 종료 버튼이 화면 안에 있고 호출 가능한지 확인한다. 912×449에서 버튼 아래쪽이 약 3px 잘리는 경우도 재현해, 높이가 아주 낮을 때 보조 설명과 버전 문구를 접도록 보완했다. 100%·200% 배율의 창 크기 계산도 Rust 검사에 포함했다. 배율 계산 검사와 실제 고배율 Windows 화면 검사는 구분한다.

크기 계산에는 Tauri의 [모니터 작업 영역](https://docs.rs/tauri/latest/tauri/window/struct.Monitor.html#method.work_area)과 [창 크기 API](https://docs.rs/tauri/latest/tauri/webview/struct.WebviewWindow.html#method.set_min_size)를 사용한다. 공개 API·앱 식별자·데이터 경로·데이터 형식은 변경하지 않았다.

## 연속 검사의 범위

전용 workflow는 빌드 작업과 설치 검사용 Windows 작업을 분리한다. 설치 검사는 같은 실행에서 생성한 설치기의 커밋과 SHA256을 확인한 뒤 실행한다. 설치 검사용 PATH에서 Node·npm·pnpm·Rust·Git·Python을 제거하고, 해당 도구를 명령으로 찾을 수 없음을 검사한다. 앱과 설치기의 보조 런타임은 설치본에 포함된 Node를 사용한다.

1. 새 설치: 현재 사용자 설치 등록, 실행 파일, 바로가기, 번들 파일 무결성을 확인한다.
2. 실제 창: 작업 영역 안에 창과 종료 버튼이 보이는지 확인한다.
3. 반복 호출: 같은 프로세스와 창을 유지하며, X로 숨긴 뒤 다시 열 수 있는지 확인한다.
4. 데이터 생성: 기존 API로 테스트 기록·설정·펫 배정을 저장하고, 테스트 위치 파일을 사용한다.
5. 정상 종료와 재시작: 실제 종료 버튼으로 프로세스·TCP·연결 파일이 정리되고 저장소를 다시 읽을 수 있는지 확인한다.
6. 덮어설치: 같은 버전 설치기를 다시 실행해 기록과 설정이 유지되는지 확인한다.
7. 제거: 프로그램 폴더·설치 등록·바로가기·앱 및 번들 프로세스가 남지 않는지 확인한다. 보존 데이터 파일은 직전 해시와 비교한다.
8. 재설치 후 실행: 동일 설치기·실행 파일 해시를 확인하고 실제 앱을 열어 기록·설정·위치 내용을 재검사한 뒤 정상 종료한다.

검사는 사용자 데이터 대신 명시적인 테스트 기록을 사용한다. 데이터 파일 비교에서 WebView 캐시는 제외한다. 위치 검사는 좌표 파일 내용 보존이며 모든 펫의 화면 좌표·드래그·모니터 이동을 검증한 것은 아니다. AI 설정 파일의 전후 해시도 확인한다. 앱 강제 종료·보안 설정 변경·수동 잔여물 삭제를 성공 조건에 사용하지 않는다.

## 검사 도구에서 발생한 대기와 보완

[첫 실행](https://github.com/swaan-kim/autopets/actions/runs/36115782894)과 [중간 재검사](https://github.com/swaan-kim/autopets/actions/runs/36119015091)는 검사 도중 긴 대기가 발생해 취소했다. 첫 실행에는 재시작 후 종료 버튼 캡처까지 남았지만 완료 JSON은 없었다. 이 두 실행을 성공으로 계산하지 않는다. 대기의 정확한 원인은 확정하지 못했으며 제품의 설치 실패나 데이터 손상으로 단정하지 않는다. 같은 첫 설치본은 [별도 재검사](https://github.com/swaan-kim/autopets/actions/runs/36117941227)에서 연속 검사를 통과했고, 최종 설치본은 위 두 성공 실행에서 검증됐다.

검사 도구의 무기한 대기를 줄이기 위해 설치기는 별도 PowerShell 작업에서 실행하면서 120초 제한을 적용했다. 종료 버튼 호출도 별도 UI Automation 검사 프로세스에서 수행하고, 부모 검사가 앱 PID의 정상 종료를 15초 이내에 독립적으로 관찰한다. [Microsoft의 InvokePattern 설명](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.invokepattern.invoke?view=windowsdesktop-9.0#remarks)도 호출의 반환 여부가 UI Automation 공급자 구현에 달려 있음을 설명한다. 이 문서는 가능한 대기 경로에 대한 근거이며, 이번 대기의 원인을 확정하는 증거는 아니다.

검사 보조 프로세스가 남으면 그 프로세스만 회수하도록 했고, 앱을 강제로 종료하는 코드는 추가하지 않았다. 최종 성공 실행은 앱 강제 종료가 없었고, 세 번의 종료 모두 보조 프로세스 강제 회수도 필요하지 않았다. 앱 프로세스·종료 코드·TCP·연결 파일 검사와 실제 버튼 호출 시각 기록을 함께 남긴다.

| 항목 | 증거 | 해석 |

| 현재 PC 백업·기존 위치 설치 | 초기 원본 292파일 백업 이후, 이번 검사 전 406파일 새 백업. 수정본 설치 28.220초·코드 0 | [현재 PC 검사](current-pc-lifecycle.md) |

| 기존 설치본 제거·재설치 | [설치 왕복 검사](installer-roundtrip.md) | 별도 Windows CI |
| 기존 설치본 창·종료 버튼 | [실제 창 검사](native-window-lifecycle.md) | 별도 Windows CI, 작은 화면 제약 발견 |

| 개발 도구 없는 일반 PC | 미검증 | PATH에서 개발 도구가 없는 것과 운영체제에 개발 도구가 설치되지 않은 것은 다름 |
| 비상승 권한의 현재 PC | 관리자 승인·재시작·수동 런타임 설치 없이 완료 | 사전 설치된 WebView가 있는 현재 환경의 결과 |

최종 검사 계정은 관리자 권한이었다. CI에서 재부팅 없이 전체 과정이 끝났지만, 일반 PC의 관리자 승인·재시작 요구가 없다는 증거로 확대하지 않는다. 개발 도구와 Windows 보안 설정은 삭제하거나 완화하지 않았다.

설치기의 용량과 실행 시간은 관측값으로 보고한다. 가벼운 설치의 합격 기준이나 서명된 공개 배포 완료를 뜻하지 않는다. 이 단계에서 기능 지원표를 확대하거나 AI 연결·모델 라우팅 단계로 자동 진행하지 않는다.
