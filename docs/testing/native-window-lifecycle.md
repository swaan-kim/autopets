# 설치본의 창·재호출·정상 종료 검증

후속 수정본의 통합 결과는 [1단계 설치·기본 작동](stage-one.md)에 기록했다. 아래는 기존 설치본을 검사한 당시의 기록이다.

2026-09-25, 1번 설치 기본 작동 구간의 하위 검사. **별도 Windows CI에서 실제 설치본의 창 표시·재호출·X 숨김·종료 버튼·재시작 후 데이터 보존을 통과했다.** 사용자 PC의 앱·마우스·키보드·사용 중인 콘솔은 조작하지 않았다.

## 대상과 방법

- 기존 [Windows 빌드 산출물](https://github.com/swaan-kim/autopets/actions/runs/35863282348), artifact `10752596469`의 동일한 `AutoPets_0.1.0_x64-setup.exe`를 설치했다. 새 제품 빌드를 만들지 않았다.
- 제품 소스: `db06cb964be9824d8a975710f055fcfc1a1d0ed3`. PR 병합 빌드: `8b39f29f4bb373fda2637f65fa3af988883cb3b0`.
- 설치기: 244,097,822 bytes. SHA256 `aedd45bc8cb71e8ffa5b338c6c3fb9ec8b2e811663b79da8710b7a8cab85c5da`. 기존 검증 서명 상태 `NotSigned`.
- 검사 스크립트는 지정 저장소의 GitHub-hosted Windows에서만 실행한다. 기존 앱·데이터가 있거나 앱 경로를 환경 변수로 변경하면 실패시킨다.
- 실제 설치된 EXE를 실행하고, 해당 PID의 주 창으로 범위를 제한해 Windows UI Automation으로 화면 컨트롤을 찾았다. 제목 표시줄 X와 실제 `AutoPets 종료` 버튼의 [InvokePattern](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/invoke-a-control-using-ui-automation)을 호출했다. 제품 내부 종료 함수를 직접 호출하거나 프로세스를 강제 종료하지 않았다.
- 종료 버튼은 스크롤 후 화면 작업 영역 안에 보이는지 확인하고 캡처했다. 접근성 컨트롤 호출과 화면 캡처에 의한 검사이며, 사람이 마우스로 수행한 검사는 아니다.
- 테스트 채팅 1개·이벤트 1개·작업 설정 1개·펫 배정을 기존 로컬 통신 API로 저장했다. 완료 기준, 알림 방식, 7분 알림 값과 사용자 지정 위치 파일을 사용했다. 실제 AI 연결이나 훅은 활성화하지 않았다.
- 종료 후와 재실행 후에 번들 Node로 SQLite를 읽기 전용으로 열어 논리 데이터와 위치 파일 내용을 비교했다. 연결 토큰·연결 파일은 산출물에 포함하지 않았다.

## 실행 기록과 검사 보완

- 최종 검사 코드: `149557fb202bb5c1dc66c611437f1bdb98209e2d`.
- [최종 Windows CI](https://github.com/swaan-kim/autopets/actions/runs/36114478569) 성공. 다운로드·설치·화면 검사·산출물 업로드를 포함한 Job 소요 시간은 1분 16초.
- 로컬 Node 회귀 검사 160개, PowerShell 구문 검사와 Node 스크립트 구문 검사 통과. 제품 Rust·프런트엔드 코드 변경이 없어 새 제품 빌드는 수행하지 않았다.
- CI 산출물 `native-window-lifecycle-evidence`에 단계별 JSON, 테스트 데이터 비교 결과, 화면 캡처 5개를 보관했다. 최종 종료 버튼 및 재시작 화면 캡처도 직접 확인했다.
- [첫 실행](https://github.com/swaan-kim/autopets/actions/runs/36114043904)은 정상 종료까지 성공한 뒤, 검사 코드가 새 설치에 위치 파일이 항상 있다고 가정해 실패했다. 펫을 이동하지 않은 새 설치에는 해당 파일이 없을 수 있으므로, 명시적인 테스트 좌표를 먼저 저장하도록 검사 준비를 수정했다. 종료 버튼도 화면 안으로 스크롤된 뒤 호출하도록 검사를 강화했다.
- 재현된 제품 기능 결함은 없어 제품 코드·공개 API·데이터 형식을 변경하지 않았다. 변경물은 전용 CI·검사 스크립트·결과 기록이다.

## 화면 제약과 미검증 범위

CI 화면은 1024×768이고 창의 외곽 경계는 1044×788로 보고됐다. 캡처는 화면과 교차하는 1024×768 영역만 포함한다. 작은 화면에서 전체 페이지가 한 번에 보이지 않으며, 종료 버튼까지 스크롤해야 했다. 스크롤 후 종료 버튼이 실제 화면 안에 표시되는 것은 확인했다. 작은 화면 배치는 개선 후보로 남기며 전체 UI·오버레이 품질 통과로 확대하지 않는다.

앞선 [내부 종료·데이터 재읽기](internal-lifecycle.md), [설치·제거·재설치](installer-roundtrip.md)와 이번 결과를 합치면 별도 Windows CI에서 설치본의 기본 수명 주기에 대한 증거가 확보됐다. 각각 독립된 CI 검사이며 사용자 PC에서 전체 과정을 연속 수행한 결과는 아니다.

현재 PC의 실제 창 조작·종료·제거·재설치, 개발 도구 없는 일반 PC, 다운로드 보안 경고·일반 사용자 권한·추가 런타임 요구는 여전히 별도 검증 대상이다. 현재 PC 기준의 **1번 구간 전체 통과로 표시하지 않는다.**

이번 소구간에서 멈춘다. AI 연결·모델 라우팅·펫 오버레이 상세 동작 등 다음 기능 구간으로 자동 진행하지 않는다.
