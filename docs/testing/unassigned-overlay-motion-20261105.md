# 연결 전 오버레이의 대기 동작 · 2026-11-05

Issue #31, 담당·통합 @swaan-kim. 기존 공유 `bbebf83411d892661504a812ad998cd7956f7efc`를 기준으로 확인한 후속이며 최종 소스는 PR #32 head를 따른다. 기존 작업/완료 중 상호작용 수정과 같은 브랜치에서 진행한다.

## 재현과 변경

작업이 배정되지 않은 오버레이는 기존 `Pet`을 `paused`로 그려 첫 연결 전부터 정지 이미지였다. 180×230·배율 1·축소 동작 꺼짐의 합성 초기 상태에서 실행 중 애니메이션 0·정지 스프라이트 1·Companion 0을 확인했고 pointerdown 후에도 같았다. 새 회귀 검사는 이 상태에서 실패했다.

작업이 없는 경우에만 기존 `CompanionPet`의 idle 표현을 사용한다. 기존 강아지 자산으로 호흡·눈깜박임·대기 동작을 재생하고 터치/Enter/Space에 인사한다. 역할·작업 배정이나 AI 호출은 없다. 기존 이름·상태 문구·이동·메뉴·숨기기·종료 동작을 유지하고 활성/알 수 없는 기존 작업의 렌더러나 연결된 펫의 실제 상태는 바꾸지 않는다. 숨기거나 동작 줄이기를 켜면 모든 표현 계층을 멈춘다.

## 근거와 검사

- 같은 가상 상태·창 크기·배율·pointerdown으로 비교한 수정 후 관측은 idle·재생 중 애니메이션 2개다. `docs/changes/31/unassigned-before.png`와 `unassigned-after.png`는 합성 UI이며 실제 설치 앱의 캡처가 아니다.
- `companion-ui.cjs`에 기본 오버레이의 재생/터치·이름/대기 상태·기록/호출 불변·숨김/축소 동작 정지, Enter/Space의 메뉴/인사와 Escape 초점 복귀를 추가했다. 수정 전 실패, 수정 후 기존 작업/완료·A/B·중복/복구·자산 실패·동시 완료 수신과 함께 통과했다.
- 타입 검사·production build·기존 MCPB 패키징 통과. 기존 잠긴 의존성을 재사용해 Node 진입점을 직접 실행했다. 전체 UI/검수 화면/오프라인 검사와 원격 Windows의 최종 결과는 PR에 기록한다.
- 기존 영역 목록의 `home` companion 검사를 대조하고, `PetOverlay.tsx`와 공통 companion CSS는 Issue #31에서 동일 통합 담당이 맡았다. API·DB·라우팅·계정·권한·의존성·CI·기존 이미지 바이트는 변경하지 않았다.

전후 영상은 로컬 원본과 Orca 검토본으로 보존하고 GitHub 첨부 대기다. 비교 영상을 저장소에 넣지 않는다. 이번 실제 AI·이미지 생성·설치·배포는 0회다. 브라우저 합성 검사를 실제 Windows 오버레이·원래 프레임에 없는 보행/관절 움직임·사람의 자연스러움 평가로 확대하지 않는다. 캐릭터 20종 시안 보류도 유지한다.
