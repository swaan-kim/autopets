# AutoPets 행사·캠페인 사용자 검사 키트

2026-10-19 · **준비된 검사 도구이며 참가자 결과는 아직 없다.** 참가자 0/5, 실제 AI 추가 0턴, 기존 누계 71/72턴을 유지한다. 이 문서와 [빈 결과표](campaign-results-template.csv)의 `not-tested`를 관측 없이 통과나 실패로 바꾸지 않는다.

검증할 가설은 **Windows Codex를 쓰는 비개발 마케팅·운영 담당자가, 행사 페이지의 반복 준비와 작업 재개를 AutoPets로 더 쉽게 할 수 있다**는 것이다. 펫의 귀여움, 업무 편익, 방해 여부를 각각 기록한다. 소규모 결과는 시장 수요나 생산성 향상의 증명이 아니다.

## 1. 준비와 모집

### 모집 문안 — 발송하지 않은 초안

> Windows에서 Codex로 행사·캠페인 소개 자료를 만들어 본 마케팅·운영 담당자 5분을 찾습니다. 약 25분 동안 화면 시제품을 사용하고, 작업을 시작하거나 다시 이어갈 때 어려운 점을 알려주세요. 설치·AI 실행·개인 업무 자료 제출은 필요하지 않습니다. 제품 평가이므로 잘하지 못해도 괜찮고 언제든 중단할 수 있습니다. 참여비는 없으며, 후속 실제 사용 검사는 별도로 안내합니다.

실무 AI·마케팅·운영 커뮤니티에서 모집할 문안이다. 이 작업에서는 게시·메시지 발송·참가자 접촉을 하지 않는다. 모집 담당자가 동의한 사람에게만 개별 일정을 안내한다.

| 선별 기준 | 적합 기준 |
| --- | --- |
| 환경 | Windows에서 Codex를 이미 사용하고 있음 |
| 업무 | 개발이 주 업무가 아닌 마케팅·운영 담당자 |
| 최근 사례 | 최근 30일 안에 행사·캠페인 소개 페이지나 자료를 제작·수정함 |
| 다음 기회 | 다음 유사 업무가 있거나 예정되어 있음. 날짜·조직명은 수집하지 않음 |
| 반복·전환 | 두 작업 이상을 오가거나 비슷한 제작을 반복한 사례가 있음 |
| 제외 | AutoPets 개발·디자인 참여자, 기존 검사 화면을 반복해서 본 사람은 본 5명과 분리 |

불편이 있다고 미리 답한 사람만 선별하지 않는다. 준비·재개에 어려움이 없다는 사례도 가설 판정에 필요하다. 스킬 숙련도는 `unfamiliar / sometimes / comfortable`로 기록하고, 스킬 전문가가 표본 대부분을 차지하지 않게 한다.

### 진행자 사전 점검

- [4장면 시제품](http://127.0.0.1:1420/campaign-study.html)을 별도 브라우저 탭에서 연다. 개발 서버가 있는 검사 PC에서만 접근되는 주소이며 배포 주소가 아니다.
- 개발 서버 없이 볼 때는 `work/campaign-study-20261019/site/` 전체를 복사한 뒤 `index.html`을 Chrome/Edge로 연다. 압축본도 폴더 전체를 풀어 사용한다. 설치·로그인·AI 실행은 없으며 이는 Windows 앱 설치 성공 검사가 아니다. [패키지와 재현](campaign-study-20261019.md).
- 시제품의 **모의 체험 표시**와 초기화 기능을 확인하고 참가자마다 처음 상태로 되돌린다. 실제 AutoPets 저장·연결·Codex 전송이 발생하지 않는지 사전 확인한다.
- 화면 크기·배율·소스 식별값·브라우저 버전과 시제품 버전을 기록한다. 기본 992×688, 참가자가 확대하면 그 시점을 기록하고 막지 않는다.
- 비교용 기준은 **같은 스킬·같은 계획/제작 설정을 가진 Codex와 저장된 요청문**이다. 스킬 없는 기본 Codex를 유리한 비교 대상으로 삼지 않는다.
- 이번에는 AI를 실행하지 않는다. 합성 계획·결과를 보여주는 시제품과, 같은 내용으로 준비한 정적 Codex 비교 자료만 사용한다. 비교 자료가 없으면 해당 비교를 `not-tested`로 남긴다.
- 실제 채팅·개인 초안·계정·연락처·회사명은 화면 공유나 기록에 넣지 않는다. 참가자는 P1–P5로만 기록한다. 필요하면 녹화 없이 시간·행동 메모만 남긴다.

진행 전 읽어줄 말:

> 화면을 평가하는 자리이고, 사용자를 시험하는 자리는 아닙니다. 보이는 대로 해보시고 생각을 짧게 말해주세요. 이 화면의 작업과 결과는 예시이며 실제 AI가 실행되지는 않습니다. 개인 자료를 입력할 필요 없고 언제든 멈출 수 있습니다.

## 2. 화면을 보여주기 전: 최근 실제 업무 5분

제품이나 “설정이 번거롭다”는 가설을 먼저 설명하지 않는다. 다음 순서대로 묻고, 해결책을 제안하지 않는다.

1. “최근 만든 행사나 캠페인 소개 자료 하나를 떠올려 주세요. 시작부터 끝까지 어떻게 하셨나요?”
2. “그때 이전 작업에서 다시 가져온 것이 있었나요? 무엇을 어디서 찾았나요?”
3. “다른 일을 하다가 돌아왔을 때 무엇부터 확인했나요?”
4. “잘 이어지지 않았던 순간이 있었다면, 그때 어떻게 해결했나요?”
5. “다음에 비슷한 일을 하면 지금 방식을 그대로 쓰실 것 같나요? 이유는요?”

`setup_pain` 또는 `resume_pain`은 **최근 특정 행동·막힘·현재 해결 방식**이 함께 나온 경우에만 `observed`로 기록한다. 막연한 공감은 `unclear`, 불편 없는 구체적 사례는 `not-observed`다. 현재의 저장 요청문·메모·채팅 검색이 충분히 해결하는 경우도 적는다. 인용은 조직·사람·실제 요청 내용을 제거한 한 문장으로 제한한다.

**5명 중 3명 이상에서 둘 중 하나가 `observed`가 아니면**, 역할이나 기능 확대 전에 대표 과업·타겟을 재검토한다. 5명이 모이기 전의 결과는 `n/완료자 수`와 `n/5`를 함께 표시한다.

## 3. 네 장면 과제: AI 없는 시제품 15분

진행자는 과제 문장만 읽는다. 버튼 이름·메뉴 위치·정답 동선을 말하지 않는다. 처음부터 모션이나 스킬 설명을 추가하지 않는다. 시제품에 없는 행동을 찾으면 “어떻게 될 것으로 예상했는지”만 묻고 한계를 기록한다.

| 장면 | 참가자에게 읽어줄 과제 | 진행자 관측과 성공 기준 |
| --- | --- | --- |
| **1. 처음 맡기기** | “가상 모루대학교의 오픈캠퍼스 소개 페이지를 준비하려고 합니다. 행사 소개, 일정, 신청 안내가 필요해요. 이 화면으로 시작해 보세요.” | 먼저 “무엇을 도와주는 화면이고, 어떤 결과를 기대하나요?”를 묻는다. 맡길 일·편익·다음 행동을 스스로 설명하고 요청을 준비하는지 본다. 복사를 전송·접수로 오해하면 별도 기록한다. 모델 선택을 요구받지 않는지 확인한다. |
| **2. 하던 일로 복귀** | “잠시 다른 업무를 하겠습니다. 아래 일정 중 장소가 겹치는 항목을 찾아주세요.” 이후 “이제 아까 행사 페이지 작업을 이어가 주세요.” | 별도 종이/탭에 `회의 10시/회의실A, 촬영 11시/스튜디오, 면담 10시/회의실A`를 보여주고 60초간 다른 일을 한다. 이후 계획 확인이 필요한 행사 A와 완료된 행사 B가 있는 모의 작업 목록에서 A와 다음 행동을 찾는지 확인한다. 시제품 링크 이동은 실제 Codex 도착 증거가 아니다. |
| **3. 지난 방식으로 새 일** | “이번에는 가상 동아리 체험전 안내 페이지를 새로 준비하려고 합니다. 지난번 작업 방식은 그대로 쓰고, 내용은 새 행사로 바꿔보세요.” | 설정을 다시 고르지 않고 새 요청을 준비하는지, ‘기존 작업 계속’과 구분하는지 본다. 이전 행사 내용·계획 승인·완료 상태가 새 일로 복사되면 실패다. 불편 없이 고칠 수 있어도 처음 혼동은 남긴다. |
| **4. 결과 확인** | “아까 맡긴 행사 페이지가 끝났다는 표시가 있습니다. 결과를 확인하고, 지금 무엇을 할 수 있을지 말해주세요.” | 정확한 작업의 예시 결과를 찾고 다음 행동을 이해하는지 본다. 완료 반응의 반복·방해, 작업 카드 접근, 모의 결과임을 구분하는지 기록한다. 참가자가 원하지 않으면 다음 일을 강요하지 않는다. |

시제품 작업명은 진행자가 넣은 합성 정보다. 앱이 실제 채팅명을 자동 조회하거나 새 작업명을 영구 저장한다고 설명하지 않는다. 과제 실패가 시제품 누락인지 실제 정보 구조 문제인지 `evidence_note`에서 구분한다.

### 시간·행동 기록 규칙

- 시간은 과제를 읽은 뒤 “시작하세요”부터 성공·포기·진행자 구조까지의 실제 초다. 화면 읽기·앱 왕복·복사·기다림을 포함한다. 외부 기술 장애로 멈춘 시간은 별도 메모하며 조용히 빼지 않는다.
- 행동 1회는 클릭·탭·Enter 제출·메뉴 선택 같은 의도적 조작이다. 연속 타이핑은 하나의 입력 행동으로 센다. 타자 수·펫 클릭 수를 생산성으로 해석하지 않는다.
- `help_count`는 참가자의 도움 요청 횟수다. `rescue_count`는 진행자가 경로를 알려준 횟수이며 1회 이상이면 독립 성공이 아니다.
- `stop_count`는 “다음에 무엇을 할지 모르겠다”는 말 또는 10초 이상 행동 없이 탐색이 멈춘 사건 수다. 단순 읽기·결과 감상과 구분해 위치를 함께 적는다.
- 60초 이상 막히면 “지금 무엇을 찾고 있나요?”라고 한 번 묻는다. 120초 이상 계속 막히거나 도움을 요청하면 필요한 최소 안내를 하고 `assisted`로 표시한다. 참가자가 중단하면 `stopped`다.
- 실패한 시간도 그대로 남긴다. 모의 연결 지연을 실제 AI 처리 시간으로 보고하지 않는다. 시간·행동 비교는 **동일한 준비/재개 구간**끼리만 한다.

## 4. 비교와 마지막 질문

### 공정한 비교

비교 조건 A는 AutoPets, B는 같은 스킬·설정과 재사용 가능한 요청문을 준비한 Codex다. 계획·결과 자료도 동일하게 준비한다. P1·P3·P5는 A→B, P2·P4는 B→A 순서로 진행한다. 첫 과제와 두 번째 과제의 이름만 바꾼 동등한 행사 brief를 사용하며 순서·선행 학습을 결과와 함께 남긴다. 5명으로 통계적 우열을 주장하지 않는다.

**이번 AI 없는 비교가 측정하는 것은 요청 준비와 작업 찾기뿐**이다. 실제 결과 품질·라우팅·지침 적용·사용량은 `not-tested`다. 정적 Codex 자료로는 실서비스의 검색·응답 속도를 비교할 수 없다. 실제 호스트 조작을 포함하는 비교는 후속 실사용 단계에서 한다.

| 환경 구간 | 비교에 포함할 것 | 이번 상태 |
| --- | --- | --- |
| 처음 설치한 사용자 | 다운로드·서명 경고·설치·연결 준비·첫 요청·복귀의 전체 부담 | 미검증. 보안 정책 유지 조건이 충족될 때 별도 시행 |
| 이미 준비된 사용자 | 앱 열기·선택·입력·복사·전송 위치 찾기·작업 재개 | 시제품 관측 가능. 전송·도착은 모의임을 명시 |
| 실제 반복 사용 | 같은 방식의 다음 업무, 결과 확인, 오류 복구 | 추가 AI 예산과 배포 조건 확보 후 |

준비된 검사 PC의 성공을 설치 성공으로 계산하지 않는다. 비교 결과에는 설치/준비 시간과 반복 사용 시간을 각각 남기고 하나의 숫자로 합치지 않는다.

### 마지막 질문 — 3분

1. “이걸 다음 어떤 일에 쓰거나, 쓰지 않을 것 같나요?”
2. “현재 쓰는 방식과 비교해 편해진 점과 더 번거로운 점이 있었나요?”
3. “작업할 때 펫을 어떻게 두고 싶나요? 켜두기·줄이기·숨기기 중 이유를 말해주세요.”
4. “펫이 있다는 느낌과, 실제 일을 쉽게 해준 정도를 각각 설명해주세요.”
5. “없애거나 바꾼다면 한 가지만 골라주세요.”

`companion_intent=keep-on`은 “케어해야 할 것 같다”는 부담 없이 켜두겠다고 답한 경우다. `pet_kept_visible`, `pet_hidden`, `distraction_observed`는 실제 시제품 관측이며, 의향과 분리한다. 잠깐 숨긴 이유가 비교·화면 크기인지 방해인지 적는다. “귀엽다”만으로 업무 편익·재사용 성공을 판정하지 않는다.

## 5. 기록·판정·7일 후속

### 결과표 사용법

[CSV](campaign-results-template.csv)는 P1–P5의 빈 행이다. 참가자별 복사본에 관측을 입력한다. 숫자 칸이 비어 있으면 미측정이며 **0이 아니다**. `not-tested`는 기회가 없거나 시행 전, `unclear`는 시행했으나 증거 부족, `observed / not-observed`는 관측 결과다. 과제 결과는 `independent / assisted / stopped / not-tested`로 기록한다. 정확한 작업 재개는 `correct / incorrect / not-tested`, 설정 재사용은 `settings-only / mixed-old-content / reselected / not-tested`다.

`understands_*`, `old_approval_transferred`, `pet_kept_visible`, `pet_hidden`, `distraction_observed`는 `yes / no / unclear / not-tested`를 쓴다. `old_approval_transferred=yes`는 결함 관측이다. `companion_intent`는 `keep-on / reduce / hide / unsure / not-tested`다. `evidence_level`은 `planned / prototype-observed / live-observed / self-report`로 증거를 나눈다. 서로 다른 수준이 섞이면 `evidence_note`에 해당 장면을 적는다.

장면1의 시간·행동은 AutoPets 준비, 장면2는 AutoPets 재개 값이다. 같은 구간의 `baseline_prep_*`, `baseline_resume_*`와 비교한다. `baseline_mode`는 `static / live / not-tested`이며 정적 자료와 실제 조작을 섞어 시간 차이를 계산하지 않는다. `initial_install_*`는 새 설치 환경, `ready_environment_status`는 준비된 환경의 상태다. 이 CSV의 원본을 결과로 덮어쓰지 않는다.

| 타겟의 문제 | 준비 또는 재개 불편이 구체적으로 관측된 사람 ≥3/5 | 미검증, 참가자 0/5 |
| 첫 이해 | 맡길 일·편익·다음 행동 3개를 이해하고 장면1 독립 성공 ≥4/5 | 미검증 |

과제별 성공자/실제 수행자 수와 성공자/목표 5명을 함께 보고한다. 결측자를 실패·성공으로 바꾸지 않으며, 5명 미만으로 완료 판정을 내리지 않는다. 관측된 불편 위치 → 수정 후보 → 재검사 과제를 연결하고 숫자만으로 이유를 지우지 않는다.

### 후속 실사용이 열리는 조건

1. 실제 AI 추가 예산을 별도로 결정하고 부모·자식·재시도 원장을 준비한다. 현재 71/72턴을 넘기지 않는다.
2. 서명·보안 정책을 유지한 설치/배포 경로를 확인한다. 보호 해제를 참가자의 정상 설치 절차로 삼지 않는다.
3. 별도 후속 동의를 받고 참가자가 자기 업무를 할 기회를 갖게 한다. 계정·호스트 신뢰는 본인이 검토한다.
4. 동일 스킬·설정의 Codex 기준선과 실제 결과를 비교한다. 완료 기준·품질·준비/복귀 시간·도움·재작업·설치 부담을 분리한다.

7일 동안 먼저 두 번째 사용을 지시하거나 보상하지 않는다. 합의한 종료 시점에 “그동안 다시 사용했나요? 어떤 상황이었나요?”라고 한 번 확인한다. 추적 자동화·연락은 이 구현에 포함하지 않는다. 실제 사용 시작의 비식별 증거가 없으면 자기보고라고 표시한다.

`day7_status`는 다음 중 하나다. `not-tested`(후속 단계 전), `started-own-task`(자기 업무를 자발적으로 시작), `declined`(기회가 있었지만 사용하지 않음), `no-opportunity`(유사 업무 없음), `no-response`(연락했으나 응답 없음), `blocked-setup`(설치/연결 조건 때문에 못 씀). 모집 5명 기준을 유지하면서 기회 있음/없음/무응답/차단의 수를 별도로 보고한다. `no-opportunity`나 `no-response`를 제외해 3/5 기준을 완화하지 않는다.

### 보관과 다음 결정

이 저장소에는 **빈 양식과 비식별 집계만** 둔다. 실제 답변·화면·진단은 Git에서 제외되는 로컬 `work/` 아래에 보관하고 원본 개인 요청이나 채팅을 저장하지 않는다. 참가자 연락처는 본 검사 데이터와 분리해 모집 담당자가 관리한다. 공개 인용·녹화는 별도 동의가 없으면 사용하지 않는다.

- 귀엽지만 쓸 이유가 약함 → 대표 과업과 준비·재개 편익을 고친다.
- 유용하지만 번거로움 → 설치·복사·앱 전환부터 줄인다.
- 유용하지만 방해됨 → 모션·알림 빈도와 크기를 줄인다.
- 두 번째 실제 사용까지 확인 → 같은 타겟의 홍보글 과업 확대와 유료화 가능성을 검토한다.
