## 사용자 행동과 확인표

이번 검사는 용어·디자인 수정에 앞서 사용자가 실제 결과까지 도달하는지를 본다. 편익의 최소 기준은 다음과 같다.

- 목적을 고르면 펫이 역할·작업 범위·계획 대기 지침을 준비한다. 사용자가 모델 이름이나 긴 지침을 직접 작성할 필요가 없다.
- 계획을 읽고 **“그대로 구현해줘”**라고 보내면 같은 계획을 이어서 결과를 만든다.
- 계획에서 제작으로 넘어갈 때 모델을 다시 선택하지 않아도 저장한 설정이 실제 하위 작업에 적용된다.
- 결과물이 브라우저에서 열리고, 펫에서 그 결과가 있는 정확한 채팅으로 돌아갈 수 있다.

이는 작은 과제의 사용 가능성과 설정 반복 감소를 확인하는 검사다. 비교군 없는 품질 우위·비용 절감률은 주장하지 않는다.

| 단계 | 사용자가 할 일 | 검사 담당자가 확인할 것 |
| --- | --- | --- |
| 1. 펫 선택 | **이 펫으로 시작**, 상세의 제작 설정을 **표준**으로 선택 | 기반 스킬·계획/제작 설정 표시, Figma 꺼짐, 저장된 펫 ID·개정 |
| 2. 준비 | **Codex에 펫 준비** 또는 이미 준비됐으면 **채팅에서 시작하기** | 실제 스킬 준비와 채팅 연결을 구분. 안내 버튼 위에 오버레이 없음 |
| 3. 계획 요청 | **시작 요청 복사** 후 A에 원문 그대로 직접 전송 | 펫 ID·개정·전체 채팅 ID·폴더 일치, 계획 자식 1회, Luna/low, 첫 자식 입력의 지침 |

| 7. 결과 | Codex가 반환한 결과 링크 열기 | 브라우저에서 가상 행사 페이지가 열림. 소개·일정·신청 안내 포함, 데스크톱 및 390px 폭에서 내용 잘림·가로 넘침 확인. 실제 등록/개인정보 수집 없음 |

검토 요청은 **“제작 펫으로 방금 결과를 검토해줘. 파일은 수정하지 마.”**를 사용한다. 꼼꼼하게 설정은 추론 강도이며 읽기 전용 권한을 강제하지 않는다. 따라서 실제 자식 입력에 이 요청이 전달됐는지와 파일 불변을 함께 확인한다.

각 실행 전후 B의 설정·기록이 그대로인지 확인한다. 펫의 계획 중 → 계획 확인 필요 → 제작 중 → 결과 확인 → 완료 표시를 기록하고, 요청값과 호스트 실행 기록·결과 반환이 일치해야 완료로 인정한다. 단계별 소요 시간과 사용자가 별도 설명을 필요로 한 지점도 남긴다.

`auditDelegatedTurn`과 기존 턴 검사는 대상·모델·강도·완료를 확인하며 프롬프트 내용은 반환하지 않는다. 이 검사 성공을 첫 지침 전달 증거로 확대하지 않는다. 첫 입력은 실제 반환된 자식 경로를 정확한 부모·폴더·시각과 연결한 후 해당 기록만 로컬에서 비교한다. 필요한 입력을 호스트가 노출하지 않으면 실행 전 전달은 미검증으로 남긴다.

현재 호스트에서 최초 작업이 암호화된 `agent_message`로만 남는 경우, 부모의 자식 실행 요청 인수와 실제 스킬 읽기·행동을 각각 확인한다. 환경 설명을 담은 첫 `user` 메시지를 작업 지침으로 오인하거나 암호화된 최초 입력의 평문 일치를 확인했다고 기록하지 않는다.

원본 대화는 복사·공개하지 않는다. 지침 대조 결과는 길이·해시·필수 항목 일치 여부와 해당 시험의 요청/자식/턴 식별자를 Git 제외 기록에 보관한다. 계획 프롬프트 이행은 실제 Plan 강제가 아니며 라우팅은 부모 채팅의 설정 변경이 아니다. 호스트 실행 기록이 서버 내부 처리 모델까지 증명한다고 주장하지 않는다.
