# 계획·실행 설정 검수

이 문서는 설치 없이 실행하는 코드·화면 검수와, 이후 별도로 수행할 실제 연결 검수를 나눈다. fixture 통과로 production capability를 켜지 않는다.

[시작 설정 화면](../images/app-workflow-presets.png) · [계획 확인·설정 불일치 화면](../images/app-workflow-task.png). 실제 서비스 연결이 아닌 합성 시나리오로 검수한 구현 화면이다.

## 코드·화면 회귀

1. 기존 선호 JSON과 DB를 열고 설정·기록·펫 배치가 유지되는지 확인한다. 새 정책은 꺼져 있어야 한다.
2. 세 카드와 상세 설정에서 계획/실행 모델·추론을 저장한다. 새 업무만 기본값을 받고 기존 채팅은 그대로 유지된다.
3. 짧은 맞춤법·번역은 바로 처리하고 일반 업무에는 계획 지침만 준비한다. 지침은 UTF-8 3KB 이하이고 별도 모델 호출은 없다.
4. 계획 확인은 채팅·계획 개정·설정 개정에 묶인다. 조건 변경·계획 갱신·설정 변경 후 이전 확인으로 실행하지 않는다.
5. Sol 계획 → Terra 실행인데 관측 모델이 Astra인 fixture에서 제출을 보류한다. 보류된 요청은 실행 시작·지침 전달 완료·펫 배정으로 기록하지 않는다.
6. Astra High → Medium은 모델 일치와 추론 일치를 따로 판단한다. 추론이 관측되지 않으면 전체 설정 확인으로 표시하지 않는다.
7. 이번만 유지 후 동일 요청의 다음 제출 한 번만 예외로 처리한다. 다른 채팅·요청 수정·설정 변경·재시작·중복 이벤트로 예외가 새지 않는다.
8. 꺼진 도움·연결 오류·시간 초과·오래된 관측은 제출을 막지 않는다. 미검증 연결은 보호 완료로 표시하지 않는다.
9. 기존 빠른 카드·필터·되돌리기·삭제·최대 세 펫·정지된 혼란 모션을 회귀 검사한다.

루트에서 `pnpm test`, `pnpm build`, `pnpm test:ui`, `pnpm verify:layout`을 실행한다. Rust·Windows 설치 파일은 Windows workflow에서 검사한다. 테스트 결과는 [상태 파일](../implementation-status.json)의 해당 커밋 증거로 확인한다.

## 5명용 짧은 체험 안내

모델 이름을 먼저 설명하지 않고 다음 과제를 제시한다.

1. 경쟁사 비교 초안을 만들려고 합니다. 시작 설정을 골라보세요.
2. 채팅에 계획이 나왔습니다. 이 계획으로 진행해 보세요.
3. 실행 설정이 다르다는 안내가 나옵니다. 어떻게 하시겠어요?
4. 결과를 확인하고 이번 채팅의 도움을 꺼보세요.

관찰: 선택·확인·불일치 해결·끄기를 수행하는지, 무엇을 설정했거나 실제 확인했다고 이해하는지 기록한다. 마지막에 자신의 업무에서 줄어드는 수고와 방해되는 점을 묻는다. 초심자 3명·숙련자 2명 중 4명이 설명 없이 흐름을 수행하고, 3명이 구체적인 사용 상황을 설명하는지를 탐색 기준으로 삼는다. 모집·발송은 하지 않는다.

## 24개 한국어 사례 평가

기존 `packages/guidance/evaluation-cases.mjs`의 사례를 서비스 기본 설정·평소 방식·AutoPets로 비교한다. 동일 환경·모델 버전·과제·시행 번호를 짝지으며 fixture와 실제 결과를 섞지 않는다.

- 품질: 완료 기준 충족, 사실·출처, 수정 필요량. 실패한 업무 유형은 절약 추천에서 제외한다.
- 효율: 쓸 만한 결과까지 계획·추가 지침·실행·점검·실패·재시도를 모두 포함한다.
- 별도 측정: 총 토큰, 구독 크레딧/한도, 시간, 설정 조작 수, 재작업. 관측 불가 항목은 빈 값으로 두고 다른 단위로 대체하지 않는다.
- 비용 예산은 모델의 단가나 이름으로 추정하지 않는다. 더 낮은 모델도 재시도가 늘면 총사용량이 증가할 수 있다.

평가 결과를 가져오는 도구는 보고서만 만들며 모델 변경 지원이나 절약 프리셋을 자동 활성화하지 않는다.
