# 부드러운 펫 모션·몸통 이동·간결한 오버레이 · 2026-11-07

담당 swaan-kim · 전체 목표 [#27](https://github.com/swaan-kim/autopets/issues/27). [검수 무대](motion-review-20261106.md)로 측정한 **합성 검사** 결과다. 실제 Windows 오버레이·설치 앱·실제 채팅은 아직 확인하지 않았다.

사용자가 확인한 문제는 세 가지다. 자세가 툭툭 바뀌고, 펫 몸통을 잡고 옮길 수 없고, 프레임이 튄다. 같은 검수에서 찾은 문제 두 가지도 함께 고쳤다. 하나는 살짝 끌었다 놓으면 카드가 열리는 것이고, 다른 하나는 받기 시작에 한 프레임 튀는 것이다.

## 원인

| 문제 | 원인 |
| --- | --- |
| 자세가 툭툭 바뀜 | 클립 안의 칸이 `steps(1, end)`로 중간 없이 교체됨. 겹침 페이드는 클립을 바꿀 때만 쓰였고, 같은 시트에서 클립이 이어질 때(예: 눈깜박임 → 기지개)는 그것도 없었다. |
| 프레임이 튐 | 시트 그림의 발 위치가 칸마다 다름. 받기(arrival) 칸은 발 높이가 246–281px, 크기는 기본 자세의 약 80%였다. 노트(계획) 칸은 발이 좌우로 17px 미끄러졌다(320px 칸 기준). 여기에 받기 동작이 `translateX(-12px)`에서 시작했다. |
| 몸통으로 못 옮김 | 이동은 ⠿ 손잡이의 `startDragging`만 있었다. 펫 버튼은 누르고 끌어도 놓으면 클릭으로 처리되어 카드가 열렸다. |

## 바꾼 것

- **칸별 발밑 보정**: 시트에서 칸마다 불투명 영역 하단 20%의 중심과 최하단을 재서, 발이 한 기준선(x 163, y 300)에 놓이도록 [보정값](../../apps/desktop/public/assets/companion-v1/manifest.json)을 저장했다. 받기 시트는 1.2배로 맞췄다. 그림 파일과 이미지 생성은 그대로이며 이미지 생성은 0회다.
- **칸 사이 교차 전환**: 클립 안에서 칸이 바뀌면 나가는 칸이 위에서 칸 유지 시간의 60%(최대 140ms) 동안 사라진다. 클립 사이 전환도 같은 시트에서 같은 방식으로 이어진다. 기존 클립 애니메이션(`backgroundPosition` 키프레임)과 `.companion-previous-pose`는 기존 검사 계약대로 유지했다.
- **몸 전체 스프링**([모델](../../apps/desktop/src/features/pets/petPhysics.ts) · [훅](../../apps/desktop/src/features/pets/usePetPhysics.ts))
  - 시간과 입력을 주입받는 순수 계산이다. 1/240초 고정 단계로 계산하고 남는 시간은 다음 프레임으로 넘겨서, 프레임 속도가 달라도 경로가 같다.
  - 받기·완료의 통통 뛰기, 새 클립의 짧은 가라앉음, 포인터 쪽으로 살짝 기울기, 들렸을 때 늘어남, 끄는 방향 반대로 기울기(최대 14°), 놓은 뒤 착지를 담당한다.
  - 움직이는 동안에만 프레임을 예약한다. 멈췄을 때, 숨겼을 때, 동작 줄이기일 때는 0이다.
- **몸통 제스처**([usePetGesture](../../apps/desktop/src/features/pets/usePetGesture.ts))
  - 5px 이하로 움직이면 클릭으로 처리해 작업 카드를 연다. 그보다 많이 움직이면 기존 `startDragging`으로 OS 창 이동을 시작한다(새 권한 없음).
  - 이동 중 흔들림은 Tauri 창 이동 이벤트 속도로 만든다.
  - 드래그 뒤에 오는 클릭은 무시한다. 키보드 실행(Enter/Space)은 그대로 둔다.
- **간결한 오버레이**
  - ⠿ 손잡이를 없앴다. 펫 몸통이 이동과 카드 열기를 함께 맡는다.
  - ⋯ 메뉴는 펫을 가리키거나 포커스했을 때만 보인다(DOM·이름·키보드 접근은 그대로).
  - 지정 펫 이름표에서 " · Codex"를 빼고 title로 옮겼다.
  - 키보드 첫 정지점이 손잡이에서 펫으로 바뀌어 Tab → Enter로 카드가 열린다.

## 측정 (기존 main 2회 → 개선 2회)

S4H(손잡이 드래그)는 개선판에 손잡이가 없어 "해당 없음"으로 기록했다. 개선판은 기대 동작을 모두 충족했고, 기존 main은 S4·S5·S5K·S6·S8에서 미충족이었다.

- **프레임 간격**: p95는 양쪽 모두 16.7–16.8ms다. 가장 긴 프레임은 양쪽 모두 실행마다 17–67ms로 흔들려 판정에 쓰지 않았다.
- **렌더러 CPU**(헤드리스 전체 페이지): 대기 0.085–0.087 → 0.085–0.094, 탭 0.15 → 0.18, 드래그 0.13–0.15 → 0.22–0.23 CPU초/초. 움직이는 동안 스프링을 매 프레임 계산하는 비용이다. 멈추면 프레임 예약이 0이다. 설치 앱의 CPU·메모리는 아니다.
- **잡음**: 같은 개선판의 첫 실행에서 키보드 시나리오의 교체 지표가 한 번 3.09/초로 튀었다. 이후 4회 실행에서는 재현되지 않았다.

## 검수 도구 보정

- 재생기의 합성 브리지가 이벤트 리스너를 지우지 않아, React 개발 모드의 이중 마운트에서 창 이동 핸들러가 두 번 돌았다. 실제 Tauri처럼 `unlisten`을 처리하도록 고쳤다. 지표는 고친 뒤 기준과 개선판을 모두 다시 측정했다.
- 위치 지표를 그림의 발 위치로 바꿨다. 요소 상자만 재면 보정 이동이 튐으로 보이거나, 스프라이트에 걸린 이동이 빠진다.
- 빌드에서 사라진 조작(손잡이)이 필요한 시나리오는 실패 대신 "해당 없음"으로 기록한다.

## 남은 확인

1. **Windows 네이티브**(별도 시험 세션)
   - 펫 몸통에서 끌기 시작할 때 `startDragging`이 바로 창을 옮기는지 본다.
   - OS 이동 중 `tauri://move` 이벤트가 연속으로 오는지 본다. 오지 않으면 흔들림 없이 들림 자세만 보인다.
   - 놓은 뒤 클릭이 오지 않는지, 투명창 클릭 영역, 배율 100%·150%, 다중 모니터를 확인한다.
2. **눈으로 판단**: 받기 시트의 1.2배 보정과 칸 사이 교차 전환이 겹쳐 보이는지(이중 윤곽)는 영상으로 판단한다. 부족하면 같은 인상으로 부위를 분리한 자산을 검토하는데, 이미지 제작 승인이 필요하다.
3. 작업 카드 내용의 간소화(문구·항목 수)는 이번 범위에 넣지 않았다. 카드 담당 화면과 겹치므로 별도로 정한다.

## 11-10 후속: 끌려다니는 모션

- 펫을 잡으면 앞발을 든 칸(`social` 9·10)으로 바뀌고, 목덜미를 축으로 매달린다(`.companion-motion`, 회전 축 50% 20%). 서 있을 때의 기울기와 눌림은 발을 축으로 하는 별도 계층(`.companion-stance`)이 맡는다.
- 끌 때는 속도 반대쪽으로 늘어지고(최대 8°), 속도가 바뀌는 순간 관성으로 더 흔들린다(최대 12°, 창 폭 안에 머무르도록 제한). 멈추면 앞으로 흔들리고, 놓으면 떨어져 착지한 뒤 인사한다. 누르는 순간 몸이 살짝 눌린다.
- 합성 검사 S4(같은 가상 입력): 잡힘 자세 재생, 흔들림 최대 4.6°, 놓은 뒤 0°, 발 튐 0회. 동반 펫·지정 펫 UI 검사 통과, Node 검사는 기존과 같은 환경 실패 2개 외 통과.
- 실제 Windows 창에서 OS 이동 이벤트로 흔들림이 나오는지는 아직 확인 전이다.

## 2026-11-10 · 매달림·쓰다듬기

- 들린 동안 몸이 멈추지 않도록 느린 진자(0.85Hz, ±2.4°)와 작은 들썩임(1.7Hz, ±0.9px)을 더하고, 끌기 속도 변화에 대한 흔들림을 키웠습니다. S4 최대 기울기 6.1° → 12.1°, 놓은 뒤 0.1°로 가라앉음, CPU 0.15 → 0.17.
- 다른 시트로 바뀌는 자세 전환은 겹쳐 보이는 시간이 짧도록 90ms로 빠르게 넘기고, 같은 시트 안에서는 140ms로 섞습니다.
- 누르지 않고 펫 위를 좌우로 세 번 이상 문지르면(쓰다듬기) 쉬는 중에는 다시 손을 흔들고, 작업 중에는 작게 몸을 흔듭니다. 2.5초 쿨다운. 새 검수 장면 S9: 기존 빌드는 반응 없음(불통과), 개선 빌드는 통과.
