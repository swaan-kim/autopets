# 복붙 없는 펫 연결: 가능한 범위

## 최신 설치형 결과

**2026-10-21: 전용 B에서 스킬 호출 → 앱 직접 적용 → 같은 채팅의 계획·구현 → 결과 복귀·재시작 복구를 확인했다.** 새 6턴(이전 71 포함 77턴), 계획·구현의 실제 자식은 Luna/low이며 선택 스킬 읽기·A/B 격리·중복 실행 없음이 일치했다. [소스·설치본·증거와 제한](copy-free-installed-20261021.md).

시험 요청은 Codex 메시지 도구로 전달했으므로 일반 입력창 자동 훅의 성공이 아니다. 앱 적용은 실제 화면으로 수행했고 지침·펫 ID·모델 설정을 붙여넣지 않았다. 최초 지침 평문 대조·일반 사용자 설치·결과물 품질은 별도 판정한다. 아래 개편 전 미검증 기록은 당시 상태다.

## 2026-10-21 기본 흐름 개편

설치 앱의 기본 행동을 **채팅 연결 → 펫 선택·설정 적용 → 같은 채팅에서 요청**으로 변경했다. 적용 뒤 별도 재조회로 출처·채팅·폴더·개정·저장 펫·역할·모델 프로필을 대조한다. 잘못된 대상, 끊긴 연결, 도움 꺼짐, 미확인 작업, 오래된 응답에는 준비 완료를 표시하지 않는다. 앱의 자유 입력과 복사는 선택형 보조 경로로 유지한다.

- 기본 Node 검사: 245 통과, 조건부 1 제외. 실제 AI와 별도다.
- 화면·Windows·설치형 검사: 이 변경의 소스와 결과가 확정되면 아래 후속 기록으로 추가한다.
- 사용자 승인 시험 예산: **이번 최대 6턴**, 이전 71턴과 별도 계산, 누계 최대 77턴. 계획·구현은 현재 가용 목록으로 확인한 **Luna/low**를 사용한다.
- 시험: 전용 B에서 연결·앱 적용·계획·구현, A는 기존 설정·기록 격리 비교. 복사 여부, 실제 지침·스킬 읽기·하위 작업 모델·결과 반환을 따로 확인한다.

아래는 개편 전 기준이며 설치형 완료를 미리 선언하지 않는다.

2026-10-21 확인. 제품 소스 `5f2a860ae1c4b687a7ba6a26762ea6c36f43b895`, [Windows 검사](https://github.com/swaan-kim/autopets/actions/runs/39416728016). 실제 AI 실행은 추가하지 않았으며 누계 **71/72턴**을 유지했다.

## 결론

**현재 채팅을 먼저 연결하고, 설치 앱에서 그 채팅에 펫 구성을 적용하면 긴 지침·스킬·모델 설정을 복붙하지 않고 다음 펫 작업에 사용할 수 있다.** 이 경로의 코드·격리 검사는 있지만, 정확히 이 순서로 최신 설치본과 실제 AI를 연결한 전체 검사는 아직 없다.

**앱에 적은 자유로운 요청문을 Codex로 자동 전송하는 기능은 없다.** 일반 브라우저 화면도 현재는 미리보기다. 설정 전달, 요청 전송, 모든 대화의 자동 처리는 서로 다른 기능이다.

## 현재 코드로 가능한 사용 순서

1. 설치와 Codex 준비를 마친 뒤, 쓸 Codex 채팅에서 **“AutoPets 스킬로 제작 펫 연결해줘”**라고 요청한다. 호출되지 않으면 AutoPets 스킬을 직접 선택한다.
2. 설치 앱에서 원하는 펫을 고른다.
3. 새 기본 화면에서는 **쓸 Codex 채팅 → 이 채팅에 펫 적용**을 누른다. 이전 공개 미리보기에는 **자세히 → 저장한 구성과 연결 관리 → 저장하고 선택 채팅에 적용**에 있다. 대상이 연결되지 않았거나 미확인 실행이 남아 있으면 적용할 수 없다.
4. 같은 Codex 채팅에서 **“이 펫으로 행사 페이지 계획만 세워줘”**처럼 일을 요청한다.

역할 지침·스킬·모델 선택은 다시 붙여넣지 않는다. 앱에 입력한 할 일 자체는 이 버튼으로 넘어가지 않으므로, 이 경로에서는 할 일을 Codex에 직접 말한다. 설정 적용만으로 AI를 실행하지 않는다.

## 구현과 검사 근거

- [설치 앱 호출](../../integrations/codex/bootstrap/start.mjs): `openInstalledPetApp`은 패키지 무결성을 확인하고 같은 설치의 EXE를 실행한 뒤 `appReady`를 확인한다.
- [현재 채팅 연결과 준비](../../integrations/codex/skills/autopets/scripts/pet.mjs): `connect`는 실제 대상 확인·저장·재조회를 수행한다. `prepare`는 현재 연결의 template/profile에서 지침·스킬·모델을 준비한다.
- [앱 적용 버튼](../../apps/desktop/src/features/pets/UiPetStudio.tsx): `apply()`가 저장 펫과 개정을 대상의 현재 개정과 함께 `apply_pet_link_template`에 전달한다. `task`·`audience`·`message`는 전달하지 않는다.
- [브라우저와 설치 앱 구분](../../apps/desktop/src/bridge/command.ts): 브라우저는 읽기용 빈 미리보기만 제공하고 변경 명령을 거부한다.
- [UI 검사](../../apps/desktop/tests/ui-pet-studio-ui.cjs): A에 저장 구성을 직접 적용하고 표준 설정 및 B 불변을 확인한다.
- [저장소 검사](../../apps/desktop/src-tauri/src/application/tests/pet_links_ui.rs): 적용→준비 시 구성 일치, 잘못된 대상·오래된 개정·진행 중 변경 거부, B 격리와 재시작 보존을 확인한다.
- [HTTP 검사](../../apps/desktop/src-tauri/src/transport/http/tests_pet_template.rs): 인증된 적용→준비 시 스킬 선택을 확인한다. 적용만으로 실행을 생성하지 않는다.
- [기존 실제 실행](installed-core-20261012.md): 스킬 읽기·하위 작업 모델·결과·상태를 확인했지만 시작 요청을 복사해 전달한 검사다. 위 무복사 순서의 실제 실행 증거로 대체하지 않는다.

해당 Windows 검사에서 Node 245개 통과·조건부 1개 제외, Rust 146개 통과·2개 제외, 화면·패키지·설치 연결 준비 검사가 통과했다. 이는 새 PC의 보안 정책이나 현재 사용자 PC 설치 성공을 뜻하지 않는다.

## 남은 검증과 개선

1. 직접 적용을 주 행동으로 옮겼고 별도 재조회도 추가했다. 실제 설치형 화면과 동일 요청의 실행 확인은 다음 관문이다.
2. 전용 B에서 **스킬 연결 → 앱 직접 적용 → 실제 다음 펫 작업**을 검사한다. 클립보드 미사용, 대상·개정·스킬·모델·결과와 A 불변을 확인해야 전체 통과다.
4. 앱의 자유 입력을 보내려면 대상·요청 ID가 있는 전달 계약과 Codex가 이를 읽는 경로가 추가로 필요하다. AI가 이미 대기 중인 명시적 스킬 요청에서 입력을 회수하는 방식은 설계 후보이며 현재 구현된 기능이 아니다. 쉬고 있는 채팅을 외부 앱에서 임의로 깨워 실행하는 성공을 약속하지 않는다.

공식 [스킬·플러그인 문서](https://learn.chatgpt.com/docs/skills-and-plugins)는 재사용 지침과 도구 묶음을 설명한다. 공식 [훅 문서](https://learn.chatgpt.com/docs/hooks#userpromptsubmit)는 `UserPromptSubmit`의 추가 지침 전달을 제공하지만 모델 변경 출력은 문서화하지 않는다. 문서상 가능성과 설치된 AutoPets의 실환경 통과는 별도로 판정한다.
