# 시작 화면과 연결된 펫 사용성 검사

## 2026-10-02 — 즐겨찾기·펫 소개·내 작업으로 시작

기존 `8713c1a` 위에 화면 변경을 추가했다. 로컬 검사 시점의 설치 앱은 이 변경을 포함하지 않았다. 이후 GitHub 개발 미리보기의 정확한 소스·Windows 결과·설치기 해시는 [Release](https://github.com/swaan-kim/autopets/releases)에 기록하며, 설치형 사용자 흐름의 통과와 구분한다.

- UI 제작 펫과 저장한 구성을 즐겨찾기에 넣고, 홈의 **즐겨찾는 펫 → 이 펫 부르기**로 다시 준비할 수 있다. 준비된 Codex와 저장한 구성이 있으면 요청 작성으로 이동한다. 선택만으로 설정을 적용하거나 실행하지 않는다.
- 소개에는 한 줄 설명, 잘하는 일·아쉬운 점 각 한 줄, 흩어진 행사 메모 → 한 장의 웹페이지 예시를 넣었다. 결과 예시는 설명용 화면이며 실제 AI 실행 결과나 효과 비교로 표시하지 않는다. 원본 `frontend-design` 출처 링크는 유지했다.
- 시작 단계에서 **맡길 일**을 한국어 여러 줄로 바꿀 수 있다. 복사 요청에 정확한 펫 ID·개정, 사용자가 적은 작업, 계획부터 제시하고 구현 요청을 기다리는 지침이 들어간다. 예시 체험에만 가상 정보와 `autopets-demo` 폴더 안내가 들어간다.
- 즐겨찾기는 앱 화면의 로컬 저장소 `autopets.pet-favorites.v1`에 펫 참조 ID만 저장한다. DB·연결·모델 설정·작업 내용은 바꾸지 않는다. 재조회 후 오래된 펫 개정을 복사하지 않는 기존 검사는 유지한다. 없는 구성은 호출을 막고 즐겨찾기에서 제거할 수 있다.
- 현재 호출 대상은 Windows 로컬 Codex다. Chat·Work는 준비 중으로 표시한다. 자동 전송, 부모 채팅 모델 변경, 자동 훅 지원을 추가하거나 검증한 작업이 아니다.

화면 전체 검사 57개와 빌드 통과, 페이지 오류 0. Node 222개 통과·조건부 1개 건너뜀·실패 0이며 레이아웃과 문서 링크 검사도 통과했다. Rust 변경은 없다. 새 검사는 즐겨찾기 재로드·재사용·해제, 저장 오류/손상된 목록, 사라진 구성, 빈 입력, 한글 여러 줄 보존, 뒤로 이동, 편집 후 낡은 복사 완료 표시 제거, 기존 채팅 불변을 포함한다. 새 화면 캡처에서는 펫 자산이 로드된 상태도 확인했다.

재현: `pnpm build`, `pnpm test:ui`. 새 기능만 확인할 때는 PowerShell에서 `$env:AUTOPETS_UI_DISCOVERY_ONLY='1'`을 설정하고 `pnpm test:ui`를 실행한다. 원본 화면은 Git 제외 `work/pet-discovery-{introduction,comparison,request,favorites}.png`에 있다. 브라우저의 연결 모형으로 검사했으며, 새 설치본·실제 채팅 입력·모델 실행의 E2E 통과로 계산하지 않는다. 실제 AI 시험은 이번 작업에서 추가로 소비하지 않았다.

## 2026-10-01 — 시작 화면 정리

2026-10-01. Dot 참고 화면의 여백·정보 순서·단일 주 행동을 AutoPets의 기존 흐름에 적용했다. 펫 자산과 역할, 계획 Luna/low 및 제작 세 프로필, Codex 연결과 저장 계약은 유지했다. 화면 개선을 실제 프롬프트 전달이나 모델 실행의 성공으로 계산하지 않는다.

## 설치형 확인과 사용자 흐름

2026-10-01 21:15 KST, 현재 PC에 화면 개편 검증본을 설치하고 실제 앱에서 확인했다. [Windows CI 36856965828](https://github.com/swaan-kim/autopets/actions/runs/36856965828)는 성공했다. 제품 head `928186e`, CI 병합 소스 `c008c82b32f0e92e877e4c2b1fcaf203b57d07e1`의 부모 관계와 산출물 24개 해시를 대조했다. Node 222 pass / 1 conditional skip, UI 55개 / 오류 0, Windows Rust 145 pass / 2 ignored 및 기본 설치·연결 준비·복구·제거 검사를 통과했다. 이전 별도 lifecycle의 개별 펫 메뉴 UIA 실패는 이번 결과로 해소하지 않는다.

설치기 SHA-256은 `6f827f8ecd2375b00ac6cee982c54411fe6a27cedb9d85a158aeff9b0f14fd17`, 크기 243,700,991바이트, 서명 `NotSigned`다. 기존 앱의 정상 종료 후 프로그램·데이터·설치 등록을 백업하고 같은 위치에 설치했다. 설치 21.488초 / 종료 코드 0. 설치 직후 실행 전에는 DB 17개 테이블, 지속 파일 5개와 설치 스킬이 같았고, 앱 실행 및 준비 화면 검사 뒤에도 DB와 스킬이 같았다. 설치된 연결 파일 139개도 manifest와 일치했다. 실행 파일 SHA-256은 `0d0e09386bb374c0d7a2f732df806f91d60a1f44fec587e83bd47977503320c7`다.

실제 앱에서 재방문 카드, 세 단계 시작 화면, 저장한 표준 구성 복원, 뒤로 이동 후 선택 유지, Figma 꺼짐, 동일 펫 ID·개정의 시작 요청 복사를 확인했다. 안내 전경에서는 별도 펫 창이 숨겨졌으며 복사 뒤에도 채팅 연결 대기를 유지했다. 현재 화면 크기에서의 확인이며 125%·150% 실제 배율 전환 검사는 아니다. 새 앱을 실행 상태로 남겼다.

일괄 실행/통신 확인 명령은 자동 승인 검토에서 `blocked by policy`로 실행 전에 거절됐다. 설치된 앱의 일반 실행 항목으로 열었을 때 창 탐색 도구의 초기 대기 시간이 초과됐지만, 재호출 없이 다음 관측에서 같은 앱 프로세스와 실제 창을 확인했다. 이를 앱 시작 실패나 정확한 첫 화면 시간 측정으로 해석하지 않는다. 설치된 읽기 전용 진단 도구는 인증된 로컬 HTTP 응답을 받았고, A/B의 활성 훅 연결은 확인되지 않았다. 사용자에 의해 SAC가 이미 꺼진 조건이며 에이전트는 보안을 변경하지 않았다. 서명·SAC 유지 배포와 실제 Codex 실행은 별도 관문이다.

실제 AI 시험은 [사용자 정상 흐름](oneflow-happy.md)에 따라 별도로 진행한다. 현재 누계 42/55, A의 일반 계획 입력 대기다. 이 화면 작업과 CI에서는 실제 AI 실행을 하지 않았다. 프롬프트·계획 대기·모델/강도·결과물·채팅 복귀의 통과는 실제 사용 기록으로만 판정한다.

원본 UI 캡처와 로그는 Git 제외 `work/mvp-goal/20261001-dot-ui/`에 보존한다. 검사 재현은 `pnpm build`, `pnpm test:ui`, `pnpm test`, `pnpm verify:layout`이며 Windows 설치형 결과는 해당 CI 실행과 설치기 해시로 고정한다.
