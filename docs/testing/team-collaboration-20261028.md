# 세 사람·각자의 AI 공동 규격 검사

2026-10-28, Windows x64·Node v24.14.1·pnpm 11.25.0·Chromium 151.0.7922.34. 저장소 권장 pnpm 버전은 11.19.0이며 CI는 그 버전을 사용한다. 제품·Agentation 소스는 `7de751be533961f051fbdc582f931b343212db5f`, 공동 규격은 이 기록을 포함한 [PR #22](https://github.com/swaan-kim/autopets/pull/22)의 변경으로 식별한다.

## 변경과 확인 범위

- [공동 안내](../development/team-workflow.md), PR 기본 양식, Issue 양식과 AI 시작 규칙을 연결했다. 고정 사람 담당표 대신 작업별 책임자와 다른 사람 한 명의 검토를 사용한다.
- PR 앞에는 사용자 변화·전후 비교·검사·검토 요청, 접힌 부분에는 기준·범위·판단·계약·미완료·다음 행동을 둔다. 기존 긴 채팅 원문은 공유하지 않는다.
- 오래된 8역할 계획·9월 상태 JSON은 삭제하지 않고 역사 기록으로 표시했다. README는 공개 미서명 설치본과 최신 개발 변경을 구분한다.
- [홈·선택·작업 카드의 전후 캡처](../changes/22/README.md)는 동일 가상 데이터의 합성 검사다. 실제 사용자의 이해나 실제 채팅 실행 근거가 아니다.

PR 검사 workflow는 `pull_request`와 읽기 전용 권한을 사용하며 PR 본문을 이벤트 JSON 파일에서 읽는다. 본문을 셸 코드로 삽입하지 않고 AI 호출·자동 병합을 하지 않는다. 양식·근거 존재 확인이며 증거의 진실성·개인정보 제거·사람 승인까지 보증하지 않는다. 검사기와 workflow 자체의 변경도 사람 검토 대상이다.

## 외부 조건과 다음 시작

현재 다른 두 사람의 GitHub 쓰기 권한이 준비되지 않아 main의 타인 승인 강제 규칙은 설정하지 않았다. 계정·권한 준비 뒤 **다른 사람 승인 1개 + 최종 소스의 필수 검사**를 적용한다. 다른 사람을 대신해 승인하거나 PR을 병합하지 않았다. PR 양식 자동 적용은 default branch에 병합한 뒤부터다.

실제 AI·일반 입력·새 설치·서명·실제 Windows DPI·사용자 참여 검사는 추가하지 않았다. 설치형 흐름의 기준은 여전히 [10월 21일 기록](copy-free-installed-20261021.md)이며 현재 시험 예산은 [서비스 검수표](pet-service-readiness.md)를 따른다. 공개 Release·배포 채널도 바꾸지 않았다.

다음 담당자는 PR의 전후 비교와 접힌 인계를 읽고 **복구·격리 → 기본 화면 → 개발 도구의 제품 제외 → 공동 규격** 순서로 검토한다. 원본 진단·백업·전체 테스트 로그는 Git에서 제외했다.
