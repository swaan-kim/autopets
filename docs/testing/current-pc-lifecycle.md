# 현재 PC — 설치·기본 작동 검증

2026-09-25. 사용자가 현재 PC 조작을 허용한 뒤 실제 설치 앱으로 확인했다. **현재 PC 기준 1단계 통과.** 설치 → 화면 표시 → 재호출 → X 숨김·복원 → 실제 종료 버튼 → 재시작 → 제거 → 동일 설치본 재설치 → 실제 화면 표시를 완료했다. 마지막에는 앱을 실행해 사용할 수 있게 남겼다.

## 설치본과 보존

- AutoPets 0.1.0, 제품 소스 `5bc20b01f5a56ed469e18fb9da4bdcaa6168646d`. [성공한 Windows 빌드](https://github.com/swaan-kim/autopets/actions/runs/36117429432)의 설치본을 사용했다.
- 설치기 SHA256 `9fcf14403b9b01fbb4655f078aefa6549cbcb0ef18b590d0375318585129eba1`, 243,253,316 bytes, 서명 `NotSigned`.
- 설치된 EXE SHA256 `18dfc792e895b663fd6141a067d0abf6f7f7595075d81c817efa9d9be7549836`. 설치·재설치 모두 동일하다. 프로그램은 107파일, 111,744,315 bytes이며 번들 Node v24.20.0과 connector payload 104개 무결성을 확인했다.
- 작업 전 프로그램·설치 등록·실행 중 DB의 일관된 SQLite 백업·위치 및 관련 파일을 보존했다. 기존 앱을 실제 종료한 뒤 WebView 캐시를 포함한 데이터 폴더도 추가 백업했다. 백업 총 406파일, 144,878,909 bytes. 원본과 검사 기록은 Git에서 제외된 로컬 `work/install-check/20260925-192425-current-pc/`에만 있다.
- 기존 DB의 12개 테이블은 모두 빈 상태였다. 전후 테이블의 구조·행 digest와 SQLite `quick_check=ok`를 확인했다. 빈 DB만으로 기록 보존 기능을 입증하지 않으며, 비어 있지 않은 기록·설정·펫 배정 보존은 [내부 검사](internal-lifecycle.md)와 [별도 Windows 연속 검사](stage-one.md)의 증거를 함께 사용한다.

## 현재 PC 실측

설치·제거는 현재 사용자용 설치기의 `/S` 실행으로 측정했다. 설치기 호출부터 하위 프로세스 완료까지를 포함한다. UI 조작은 computer-use의 실제 앱 버튼과 창으로 수행했다. 종료 시간은 클릭 호출 직전부터 기존 앱 프로세스 종료 관측까지이며 UI 입력 전달 시간을 포함한다.

첫 설치 직후 실행에서는 도구의 창 탐색 오류와 재관측 지연이 있어 화면 확인 상한만 47.496초로 남았다. 이를 앱의 실제 시작 지연으로 해석하지 않는다. 마지막 재설치 후 실행은 같은 도구 호출 안에서 실행 요청·창 선택·준비 화면 캡처를 연속 수행했으며 2.493초는 최초 픽셀 표시 시각이 아닌 화면 확인까지의 상한이다. 콜드 부팅 벤치마크는 아니다.

## 발견 사항과 범위

기존 설치본에서는 소개 자료 화면의 종료 버튼이 아래에 있어 스크롤이 필요했다. 이미 CI에서 수정·검증한 설치본으로 교체한 뒤 현재 PC에서도 스크롤 없이 종료할 수 있음을 확인했다. 이번 PC 검사에서 추가로 재현된 제품 결함은 없으므로 제품 코드나 데이터 형식을 더 변경하지 않았다.

진단 도구의 첫 레지스트리 JSON 변환은 PowerShell 공급자 객체까지 포함해 메모리 오류가 났다. 등록 값만 선택하고 `.reg` 원본 내보내기를 함께 수행해 백업을 완료했다. 첫 실행·숨김 직후의 창 탐색은 앱 창 생성보다 먼저 반환될 수 있어 다시 관측했고, X 버튼의 접근성 클릭은 위치 정보를 얻지 못해 최신 화면 캡처의 실제 X 좌표로 확인했다. 이러한 도구 오류를 앱 실패나 완료 증거로 계산하지 않았다.

현재 검사 프로세스는 비상승 권한이었다. 관리자 승인·추가 런타임 수동 설치·재시작 없이 전체 과정이 끝났고 별도 다운로드 안내도 나타나지 않았다. 다만 이 PC에는 WebView와 개발 도구가 이미 있고 설치기에는 오프라인 WebView 설치기가 포함돼 있다. 네트워크 전송량을 계측한 것은 아니므로 추가 다운로드 0 bytes라고 단정하지 않는다.

검사 파일에는 `Zone.Identifier`가 없었고 보안 차단이 관측되지 않았다. 브라우저로 새로 내려받은 미서명 EXE에 대한 SmartScreen 동작은 미검증이다. 보안 설정을 변경하거나 차단을 우회하지 않았다. 개발 도구·런타임 없는 다른 PC의 성공, 서명된 공개 배포 완료, 펫 오버레이 상세 동작, AI 연결·훅 활성화·모델 라우팅으로 결과를 확대하지 않는다.

현재 PC와 별도 Windows의 증거를 합쳐 1단계에서 멈춘다. 다음 기능 구간으로 자동 진행하지 않는다.
