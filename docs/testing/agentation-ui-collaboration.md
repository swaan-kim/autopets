# Agentation 개발 검수와 영역별 공동 수정

검사 묶음: `agentation-20261027`. 기존 `d29c26f` 이후 작업 중인 소스에서 수행했다. 커밋·공개 배포·설치본 검증으로 계산하지 않는다.

## 구현한 흐름

- `pnpm dev:feedback`: 브라우저 개발 화면과 loopback Agentation 서버를 함께 실행한다.
- 홈 `home`, 펫 탐색·설정 `pet-selection`, 작업 카드 `task-card`의 에이전트를 나눠 지정 파일만 수정했다. [소유 범위](../development/ui-ownership.json)와 [공동 규칙](../development/ui-collaboration.md)을 AGENTS.md에 연결했다.
- 고정 요소 ID와 가장 가까운 영역을 사용한다. 개발 도구가 하위 본문·이미지에도 담당 메타데이터를 붙여, 안쪽 요소를 눌러도 분류한다. 서로 다른 표식이 충돌하거나 범위가 없으면 통합 담당자가 검토한다.
- 일반 개발 화면은 홈·선택을, `/__review__/tasks`는 명확히 표시한 가상 카드 3개를 제공한다. 실제 채팅·실행·모델 관측을 만들지 않는다.
- 홈은 펫 선택과 Codex 요청 안내, 선택 화면은 저장·대상 적용·재조회, 카드는 상태·정확한 채팅 복귀를 중심으로 정리했다. 작성·복사 예시와 기술 상세는 접힌 영역에서 유지한다.
- `autopets-agentation` STDIO 서버를 Codex에 등록했다. 현재 채팅에 새 도구 목록이 즉시 로드됐다고 판단하지 않는다. 현재 작업에서는 등록한 동일 wrapper를 MCP 클라이언트로 직접 연결해 검증했다. `pnpm feedback:pending` 로컬 조회도 제공한다.

## 수행 결과

환경: Windows x64, Node v24.14.1, Chromium 151.0.7922.34. 개발 의존성은 Agentation 3.1.2와 agentation-mcp 1.3.2로 고정했다.

| 담당 범위 검사 | 담당별 허용 파일, 다른 담당·백엔드·상위 경로 거절, 표식 충돌과 중첩 분류 검사 통과 |

| 개발 서버 | 기본 개발 화면과 피드백 health 응답 200, 로컬 SQLite 사용 확인 |

`pnpm test:feedback`은 현재 소스를 먼저 새로 빌드한 뒤 브라우저 → HTTP → MCP → 브라우저 완료 반영을 검사한다. 테스트 서버는 별도 임시 포트와 메모리 저장소를 사용한다. 시험 의견을 실제 개발 의견 저장소에 남기지 않는다.

초기 검사에서 포털의 빈 wrapper를 visible로 기다리던 검사, 둥근 모서리 바깥 클릭 좌표, 예전 소개 화면 기대값, 대상 교체 후 접힌 설정을 여는 검사 누락을 수정했다. 하위 요소의 담당 표식 누락은 개발 전용 메타데이터 보완 후 세 영역 전달로 재검증했다. 실패를 통과로 숨기거나 대기 시간만 늘리지 않았다.

## 기록과 한계

- 원본 로그·예시 캡처·로컬 설정 백업은 Git 제외 `work/agentation-20261027/`와 `work/agentation-*-test.log`에 있다. 공개 문서에는 개인 경로·인증값·원본 주석을 싣지 않는다.
- 실제 AI 실행은 추가하지 않았다. 기존 77턴·추가 상한 8턴의 원장은 그대로다. 모델 라우팅·설치·실제 사용자 편익의 새 통과가 아니다.
- native Windows DPI·새 PC 설치·서명·Steam·참여자 5명 검사는 이번 검수에 포함하지 않았다.
- 이번 UI 작업에서 공개 API·DB·네이티브 연동을 변경하지 않았다. 브라우저의 가상 snapshot 분기는 개발 플래그와 정확한 예시 경로에서만 동작한다.
- 파일 소유 검사와 공동 규칙은 변경 범위 확인 수단이다. 운영체제 수준의 쓰기 잠금이 아니므로 통합 담당자의 실제 diff 검토도 필요하다.
