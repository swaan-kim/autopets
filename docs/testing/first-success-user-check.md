# 첫 성공과 두 번째 사용 — 진행자 검사표

2026-10-16 준비. **참여자 0/5, 모든 사용자 검사는 미실시.** 대상은 Codex를 사용하지만 스킬·프롬프트·설정에는 익숙하지 않은 사람 5명이다. 이 문서는 모집이나 검사 완료의 증거가 아니다.

검증할 질문은 **“추가 앱을 설치하고 오가는 수고보다 준비와 재사용의 편익이 큰가?”**다. 화면 이해, 실제 결과 도달, 동반감, 재사용 행동을 각각 판정한다. 개발자가 대신 수행한 UI 검사와 녹화 시연은 사용자 검사에 포함하지 않는다.

## 1. 검사 전 준비

- [ ] 참가자에게 관찰 목적과 중단 가능 여부를 알린다. 익명 번호 P1–P5만 사용한다.
- [ ] 앱·Codex 버전, 소스/설치본 식별값, 화면 크기·배율, 선택한 펫·설정, 검사 날짜를 기록한다.
- [ ] 기존 화면과 개선 화면을 같은 PC·992×688 창·배율·계정 준비 상태·연결 기록 조건으로 준비한다. 예시 결과와 과제도 동일하게 유지한다.
- [ ] 3명은 기존→개선, 2명은 개선→기존 순서로 관찰한다. 첫 화면에서 배운 효과를 결과의 한계로 남긴다.
- [ ] 합성 작업과 전용 시험 채팅만 쓴다. 실제 개인 대화·인증정보·전체 입력문·클립보드 내용은 수집하지 않는다.
- [ ] 실제 AI 사용 원장을 확인한다. **현재 71/72턴을 유지하며 이번 준비·화면 관찰에는 0턴을 사용한다.** 다수 사용자의 실제 비교·재사용 시험은 별도 추가 예산이 확정되기 전까지 실행하지 않는다.
- [ ] Windows 설치 성공과 서명·보안 정책은 독립 관문으로 기록한다. 브라우저 화면 검사에 성공해도 일반 사용자 설치 성공으로 표시하지 않는다. 보안 설정은 해제하지 않는다.

## 2. AI 실행 없이 첫 흐름 관찰

진행자는 사용법을 설명하거나 눌러야 할 버튼을 지목하지 않는다. 아래 문장만 한 번씩 읽어준다. 생각을 말해 달라고 요청할 수 있지만 이유를 추측하거나 답을 유도하지 않는다. 참가자가 도움을 요청하면 먼저 그 시점과 요청을 기록하고 필요한 도움을 준다. 도움을 받은 과제는 무개입 성공으로 계산하지 않는다.

| 순서 | 참가자에게 읽어줄 과제 | 관찰할 것 | 중단점 |
| --- | --- | --- | --- |
| 1 선택 | “가상 학과 행사를 소개하는 웹페이지를 만들려고 합니다. 무엇을 맡길 수 있는지 살펴보고 시작해 보세요.” | 웹페이지 역할 선택, 결과 예시·기반 스킬 이해, 첫 행동까지 시간 | 작업 입력 화면 진입 |
| 2 요청·준비 | “행사 소개, 일정, 신청 안내와 휴대폰에서 볼 화면이 필요합니다. 요청을 준비하고, 잠시 다른 화면을 본 다음 돌아와 이어 해보세요.” | 자유 입력, 필요한 보충 정보, 불필요한 설정 탐색, 뒤로 이동 후 초안·설정 보존, 준비 반복 | 구성 저장과 시작 요청 복사까지. 실제 채팅에는 보내지 않음 |
| 3 전달·복귀 | “이어서 어디에서 요청을 보내야 하는지 보여주세요. 준비된 시험 기록에서 계획을 확인할 곳과 결과를 확인할 곳도 찾아보세요.” | 복사와 전송·접수 구분, 정확한 시험 채팅 복귀, 다음 행동 이해 | 전송 직전 또는 읽기 전용 시험 채팅 복귀까지. 새 요청 실행 금지 |

시험 기록은 **이전 검증 기록인지 합성 예시인지 명시**한다. 실제 상태와 구분되지 않는 가짜 성공 화면을 제공하지 않는다. 참가자 초안을 시험 메시지로 덮어쓰지 않는다. 입력할 장소를 보여주는 것과 실제 전송 성공을 서로 다른 결과로 기록한다.

각 과제는 3분까지 관찰한다. 다음 행동을 정하지 못한 상태가 10초 이상 이어지면 ‘멈춤’ 1회로 적는다. 제한 시간에 도달하면 실패로 몰아가지 않고 미완료 이유를 한 줄로 묻고 다음 과제로 이동한다. 이 시간은 제품 성능 목표가 아니라 진행 기준이다.

과제 뒤 아래 질문에 **정확 / 일부 / 모름**으로 기록한다. 버튼 문구를 외우는 대신 흐름을 이해했는지 본다.

1. 이 펫에게 어떤 일을 맡길 수 있나요?
2. 평소 Codex를 쓸 때와 비교해 어떤 준비를 덜 하게 되나요?
3. 여기서 다음에 무엇을 해야 하고, 실제 요청은 어디에서 보내나요?

| 익명·화면 | 과제 | 완료·미완료 | 소요 초 / 첫 행동 초 | 조작 / 되돌아감 / 멈춤 | 도움 횟수 | 초안 손실·연결 준비 반복 | 막힌 이유·개선 후보 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| P_ · 기존/개선 | 1/2/3 | 미실시 | — | — | — | — | — |

‘조작’은 클릭·탭·키보드로 선택하거나 확정한 횟수로 세고 문장을 입력한 글자 수는 세지 않는다. 화면 간 이동과 Codex로 돌아가는 조작도 포함한다. 초안 손실·잘못된 대상·복사를 실행으로 오해한 경우는 별도 결함으로 남긴다.

## 3. 실제 편익 비교 — 추가 시험 예산 확정 후

**현재 미실시·예산 대기.** 기본 Codex, 설치된 스킬 직접 사용, AutoPets의 세 조건에서 각각 15~20분 이내의 작은 과제를 수행한다. 각 조건에 동일한 과제 설명과 완료 기준만 제공하고, AutoPets만 설명하거나 대신 조작하지 않는다. 스킬 직접 사용에는 같은 원본·버전의 스킬을 제공한다.

- 과제는 가상 학과의 **행사 / 세미나 / 전시 소개 페이지** 3개로 준비한다. 제공 사실 수, 소개·일정·신청 안내·모바일 화면 요구, 파일 규모와 수정 난이도를 맞추고 외부 서비스는 요구하지 않는다. 각 참가자에게 서로 다른 주제를 배정해 이전 결과를 복사하지 않도록 한다.
- 버전·가용 모델·실행 설정·기본 프롬프트·평가 기준을 시작 전에 고정한다. 가능하면 동일한 모델·강도 조합을 세 조건에 적용한다. 실제 실행이 다르면 그 차이를 기록하고 UI나 스킬만의 효과로 해석하지 않는다.
- 부모·하위 작업·재시도를 모두 턴 예산에 포함한다. 결과가 불명확하면 기존 실행부터 조회하고 재전송하지 않는다. 예산이 끝나면 남은 조건은 미실시로 유지한다.
- 설치부터의 부담과 이미 준비된 재사용 부담을 분리한다. 실제 설치를 생략한 조건은 ‘준비된 환경’이라고 표시하며 설치 편익을 주장하지 않는다.

| 참가자 | 조건 순서 | 주제 순서 |
| --- | --- | --- |
| P1 | 기본 → 스킬 → AutoPets | 행사 → 세미나 → 전시 |
| P2 | 스킬 → AutoPets → 기본 | 세미나 → 전시 → 행사 |
| P3 | AutoPets → 기본 → 스킬 | 전시 → 행사 → 세미나 |
| P4 | 기본 → AutoPets → 스킬 | 전시 → 세미나 → 행사 |
| P5 | 스킬 → 기본 → AutoPets | 행사 → 전시 → 세미나 |

5명으로 순서·주제 효과를 완전히 균형화할 수 없으므로 조건별 중앙값과 개인별 차이를 함께 보고, 남는 편향을 명시한다. 통계적 유의성이나 일반 절감률을 주장하지 않는다.

**실행 전 고정할 결과 평가표:** 제공 사실의 정확성, 필수 내용 충족, 신청 동선 작동, 모바일 가독성, 요청하지 않은 기존 파일 보존을 각각 충족/미충족으로 평가한다. 가능하면 결과를 만든 방식을 가린 번호로 화면을 보여주고 별도 평가자가 판단한다. 파일 보존은 검사자가 따로 확인한다. 예쁜 정도만으로 품질 통과를 정하지 않는다.

| 익명·조건 | 준비 조작·시간 | 전체 시간 / AI 대기 시간 | 도움 / 재작업 횟수 | 결과 기준 5개 | 결과 도달·다음 행동 | 실제 설정·스킬 근거 |
| --- | --- | --- | --- | --- | --- | --- |
| P_ · 기본/스킬/AutoPets | — | — | — | 미실시 | 미실시 | 미검증 |

역할 지침의 실행 전 전달, 실제 스킬 읽기, 요청한 하위 모델·강도, 결과 반환, 펫 표시, 채팅 격리를 실행 기록과 대조한다. 사람의 이해도 점수로 실행 근거를 대체하지 않는다.

## 4. 동반감과 두 번째 사용

AutoPets 실제 작업 동안 펫 클릭, 숨김·동작 줄이기, 진행 확인, 채팅 복귀를 관찰한다. 완료 뒤에는 “남은 시간은 자유롭게 사용해도 되고 여기서 마쳐도 됩니다”라고만 안내한다. 다음 사용을 권하거나 과제를 지정하지 않는다.

- **귀여움:** 외형·반응이 마음에 드는가? 1–5점과 한 줄 이유.
- **동반감:** 작업을 함께하고 있다는 느낌이 있었는가? 1–5점과 이유.
- **방해:** 집중·입력·화면 이용을 방해했는가? 1–5점, 숨김 여부와 이유.
- **재사용 의향:** 다음에 어떤 일에 쓰거나 쓰지 않을 것인가? 응답을 그대로 요약.
- **재사용 행동:** 참가자가 스스로 떠올린 자기 과제로 새 요청을 실제 접수시켰는가? 예/아니요/예산 때문에 미검증. 기존 구성 재사용과 새 초안을 확인하고 이전 작업 내용·승인을 복사하지 않았는지 검사한다.

버튼 클릭·사용하겠다는 말·녹화 재생은 실제 두 번째 사용으로 세지 않는다. 기록에는 개인 과제 내용을 남기지 않고 작업 종류와 성공 여부만 적는다. 자발적 사용이 없으면 사용 의향 점수가 높아도 별도로 기록한다.

- **이해:** 4/5명이 맡길 일·사용 이점·다음 행동을 모두 정확히 설명하고 진행한다.

- **두 번째 사용:** 3/5명이 자발적으로 자기 과제의 실제 두 번째 사용을 시작한다.

이해가 낮으면 소개·다음 행동을, 이해하지만 이점이 약하면 과제·결과·준비 부담을, 유용하지만 오래 켜두기 싫다면 모션·방해 정도를 먼저 개선한다. 역할·모션 수 확대는 그 뒤에 검토한다.

**현재 판정: 화면 이해 미검증 / 실제 편익 미검증 / 동반감 미검증 / 두 번째 사용 미검증.** 5명의 작은 검사는 개선 우선순위를 정하는 자료이며 시장 수요·일반 생산성·외로움 감소의 증거로 확대하지 않는다. 서명된 배포·다른 PC 설치는 이 표와 별도로 판정한다.
