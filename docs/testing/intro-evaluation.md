# 한 장 소개 자료: 검수와 효과 평가

**자동 검사 성공과 사용자 편익 측정은 다릅니다.** 아래 72개 실행은 평가 계획이며 모델을 자동 호출하지 않습니다.

## 구현 검수

```powershell
pnpm test
pnpm build
pnpm test:ui
pnpm verify:layout
pnpm test:rust
node scripts/prepare-intro-evaluation.mjs
```

마지막 명령은 `work/intro-evaluation`에 합성 한국어 사례, 빈 측정표, 조건을 숨긴 평가표를 만듭니다. 다시 실행해 실제 측정값을 덮어쓰지 않습니다. 모든 값은 미측정·null에서 시작합니다. Rust/설치기 검사는 Windows CI를 근거로 남기고, 실제 AI 환경의 연결 성공으로 해석하지 않습니다.

화면 검사는 합성 채팅으로 양식 선택, 두 채팅 전환, 저장 충돌, PNG 등록, 검수·채택, 수정, 다운로드, 스타일 재사용을 확인합니다. PNG 검사와 로컬 서버 fixture는 실제 이미지 생성의 품질 평가가 아닙니다.

## 한국어 사례와 네 조건

[합성 사례 6개](../../packages/guidance/evaluation/intro-cases.json): 제품 소개 2개·기획 요약 2개·비교 설명 2개. 각 조건을 3회 실행합니다. 총 6×4×3 = 72회입니다.

| 조건 | 제공 방식 | 비교할 차이 |
|---|---|---|
| A | 평소처럼 기존 AI에 요청·자료 전달 | 평소 사용 기준 |
| B | 동일 절차·자료를 정리한 프롬프트 | 지침을 정리한 효과 |
| C | 같은 절차·자료의 스킬 직접 호출 | 스킬 포장의 추가 효과 |
| D | 같은 스킬을 AutoPets로 선택·수정·재사용 | UX의 추가 효과 |

실행 전에 케이스별 사용할 레이아웃·스타일 참고, 지침, 원문, 도구 버전을 고정합니다. B/C/D의 지침·자료는 같은 내용을 사용하고 해시를 남깁니다. B만 모든 참고 파일을 붙이거나 C/D만 추가 자료를 받지 않게 합니다. 같은 모델·추론·이미지 도구·생성 설정을 유지하고, 조건 순서는 교차합니다. 각 실행은 별도 새 채팅에서 시작합니다. 숨은 상위 모델 전환이나 재시도를 넣지 않습니다.

모델이 예외적으로 다른 참고를 읽거나 더 많은 맥락을 받았다면 기록하고 공정 비교에서 별도로 표시합니다. 동일 모델 고정이 불가능한 환경의 결과는 모델 차이를 제거한 인과 증거로 쓰지 않습니다.

## 기록할 것

- **결과 품질:** 핵심 내용 보존, 근거 없는 주장, 한글 가독성, 레이아웃. 각 항목 0(불충족) / 1(수정 필요) / 2(충족), 오류 사례를 함께 기록합니다.
- **사용자 수고:** 받아들일 때까지 걸린 전체 시간, 선택·복사·붙여넣기·설정·다운로드 조작 수, 수정 횟수. 실패·포기도 숨기지 않습니다.
- **부담:** 처음 설치·연결 시간과 두 번째 사용 시간을 별도로 기록합니다.
- **사용량:** 준비·생성·검토·재시도의 관측값을 모두 기록합니다. 하나라도 빠지면 총 토큰은 null입니다. 이미지 과금·구독 한도·토큰을 같은 단위로 합치지 않습니다.

`runs.private.json`의 조건 대응표는 실행 담당자만 봅니다. 평가자는 `judge-sheet.json`과 무작위 순서로 배치한 blindId 이름의 PNG만 받습니다. 파일명·메타데이터·워터마크에 조건을 넣지 않습니다. 가능한 한 조건을 모르는 평가자가 채점하고, 모델 자체 평가는 참고에만 사용합니다.

6개 사례·3회는 탐색용입니다. 평균만으로 일반화하지 않고 조건별 분포·실패 수·사례별 품질과 수고를 함께 봅니다. C−B로 스킬 형태, D−C로 AutoPets UX의 추가 효과를 구분합니다.

## 사용자 과제

초심자 3명·숙련자 2명에게 설명 없이 다음을 요청합니다.

1. 원하는 예시의 펫과 양식을 선택합니다.
2. 자료를 전달하고 초안을 확인합니다.
3. 글을 줄이고 변경 전후를 비교합니다.
4. PNG를 다운로드하고 만족한 스타일을 저장합니다.
5. 새 업무에서 지난 스타일을 다시 사용합니다.

4명이 흐름을 완료하고, 품질을 유지하면서 스킬 직접 사용보다 조작이나 수정 수고가 줄었는지 확인합니다. 단순 호감도·GitHub 스타·모델 점수 상승만으로 만족·절감 효과를 주장하지 않습니다. 이번 변경에는 참가자 모집·발송·평가 실행이 포함되지 않습니다.

## 실환경에서 남은 확인

- 설치·연결된 Windows Codex의 실제 두 채팅에서 관측 binding과 prepare/publishPNG 흐름.
- 한국어·공백 경로, 실제 생성 도구의 이미지 저장 위치와 PNG 형식.
- 조건 수정 중 늦게 도착한 PNG가 잘못된 개정으로 저장되지 않는지.
- 계정/채팅 전환·재시작 뒤 파일과 버전 보존, 수동 파일 등록과 CLI 결과 일치.
- 사용자에게 생성·검사·확인이 구분되고 재생성 필요·추가 비용이 이해되는지.
