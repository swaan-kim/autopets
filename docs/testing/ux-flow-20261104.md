# 설치·작업 복귀·결과 탐색·펫 동작 개선

2026-11-04 · [Issue #25](https://github.com/swaan-kim/autopets/issues/25). 기준은 PR #22가 병합된 `34e27306419a069289fe7ec9e031199f04e863e7`이다. PR #24의 규칙 보완은 아직 미병합이며 이 브랜치에 가져오지 않았다.

같은 날 사용자는 이번 범위를 **협업 전에 소유자가 전체를 정리하는 작업**으로 명확히 했다. 사용성·UI/UX·번거로운 단계 제거·귀엽고 인터랙티브한 펫과 기능성을 우선하며, 공동 사전 합의 절차는 이번 정리를 마친 뒤부터 적용한다. 이 결정을 Issue #25에 기록했고 화면·연결 개선을 진행한다. 팀 전체의 회의나 동료 리뷰 승인이 있었던 것으로 표시하지 않는다.

## 실제 제품 코드와 시제품의 경계

제품 변경은 진입 화면(`Manager`), 연결 안내(`ConnectionGuide`), 프롬프트 예시(`PromptIdeaLibrary`·`promptIdeas`·`PromptArtwork`), 선택·적용(`UiPetStudio`·`PetWorkspace`·`petCatalog`), 펫 모션(`CompanionPet`·`TaskPetArt`)과 각 스타일·검사다. 준비 완료와 현재 채팅 연결을 구분하고, 작업 중 인사로 실행 모습을 덮지 않는다. 완료 반응의 수신 확인·해시·잠금·한 번 재생 규칙은 유지한다.

이미지·영상용 펫은 기존 `research-document` 역할과 고정 `autopets-research-document / 1.0.0` 스킬을 사용해 프롬프트를 정리한다. 새 역할 ID·DB·연결 API를 추가하지 않는다. 선택한 기본 방향은 1536바이트 이내의 기존 지침에 담고 현재 요청을 우선한다. 생성 도구를 호출하거나 생성 결과를 보장하지 않는다. 기존 일반 조사·문서 구성을 이미지 펫으로 잘못 분류하지 않도록 이름이 맞는 경우만 연결한다.

선택 가능한 채팅이 하나면 준비 화면에서 그 대상을 미리 선택한다. 끊김·도움 꺼짐·미확인 실행은 제외하며, 선택 후 새 스냅샷 때문에 다른 채팅으로 자동 전환하지 않는다. 저장·적용의 대상/개정·재조회 검증과 명시적 적용은 그대로다.

## 다른 AI에서 펫 설정 재사용

`/v1/pet-library`는 기존 loopback 인증과 Origin 거부를 그대로 사용한다. 목록에는 이름·ID·개정·역할만, 개별 읽기에는 일치하는 ID/개정의 저장한 펫만 반환한다. 기존 계정/채팅 바인딩과 대화는 포함하지 않으며 상태 변경 이벤트를 내보내지 않는다. 새 DB 테이블이나 기존 API 필드 변경은 없다.

`integrations/mcp`는 목록·선택한 개정 읽기 두 도구만 제공한다. 반환값에서 실행 모델·추론 설정·계정·폴더·인증값을 제외하고, 스킬은 참조이며 실제 읽기 확인이 아님을 표시한다. 구형 앱·오래된 개정·다른 펫 응답·과대 메시지는 실패로 처리한다. 초기화와 도구 목록 조회는 앱이나 연결 파일을 읽지 않는다.

`scripts/package-pet-preferences.mjs`는 소스 다섯 개만 고정 순서로 묶는다. 앱 개발·빌드와 UI 검사 준비 때 생성하며 인증값·로컬 설정·Node 런타임·새 의존성을 포함하지 않는다. 생성 파일은 Git에서 제외한다. 브라우저의 명시적 파일 받기와 실제 Claude 설치·권한 허용·활용은 별도 검증이다. 상세: [MCP 연결](../../integrations/mcp/README.md).

시제품 진입점은 `apps/desktop/tests/ux-flow-preview.html`이며 `src/development/UxFlowPreview.tsx`를 직접 읽는다. 제품 진입점에서 import하지 않아 제품 번들·Tauri·오버레이에 포함되지 않는다. 가상 상태는 시제품 안에서만 바뀌고 실제 채팅, 클립보드, 파일, 연결, 생성 도구에 전달되지 않는다. 구도 그림은 코드로 직접 그린 SVG이며 생성 결과를 보장하지 않는다.

검토 방법:

```powershell
pnpm --filter @autopets/desktop exec vite --host 127.0.0.1 --port 1421 --strictPort
# http://127.0.0.1:1421/tests/ux-flow-preview.html
node apps/desktop/tests/ux-flow-preview-ui.cjs
```

제품 개발 서버와 시제품 검사는 별도 포트를 사용해 기존 서버를 교체하지 않는다. 실제 설치 앱·스킬 실행·모델 요청을 사용하지 않는다.

## 다음 관문

1. 호스트별 공식 연결 수단과 작업 단위의 문맥 전달을 구현·실증한다. 브라우저·로컬·클라우드의 접근 범위를 같다고 가정하지 않는다. 이번 사용자 결정에 포함된 작업이며 팀 회의를 다시 선행 조건으로 요구하지 않는다.
2. 실제 기존 대화에서 예시 설정 적용→요청→결과·복귀의 편의와 설치 이후 단계를 확인한다.
3. 이미지·영상의 실제 예시를 제작하거나 허용된 출처에서 확보하고, 사용 도구·입력·제약·결과의 근거를 대조한다.
4. 최신 일반 입력, 보안 유지 배포, 실제 사용자의 편익을 각각 검증한다. 제품 AI 시험 전 현 원장과 승인 상한을 다시 확인한다.

구현·합성 검사·실환경 연결·병합·배포의 완료는 각각 구분한다. 소유자의 이번 작업 범위 결정을 이후 공동 작업의 일반 예외로 확대하지 않는다.
