# 설치·작업 복귀·결과 탐색·펫 동작 개선

2026-11-04 · [Issue #25](https://github.com/swaan-kim/autopets/issues/25). 기준은 PR #22가 병합된 `34e27306419a069289fe7ec9e031199f04e863e7`이다. PR #24의 규칙 보완은 아직 미병합이며 이 브랜치에 가져오지 않았다.

같은 날 사용자는 이번 범위를 **협업 전에 소유자가 전체를 정리하는 작업**으로 명확히 했다. 사용성·UI/UX·번거로운 단계 제거·귀엽고 인터랙티브한 펫과 기능성을 우선하며, 공동 사전 합의 절차는 이번 정리를 마친 뒤부터 적용한다. 이 결정을 Issue #25에 기록했고 화면·연결 개선을 진행한다. 팀 전체의 회의나 동료 리뷰 승인이 있었던 것으로 표시하지 않는다.

후속으로 소유자가 갤러리 이미지 제작을 무조건 승인하고 이번 작업의 턴 제한을 초기화하여 자유롭게 진행하도록 지시했다. 과거 제품 AI 사용 77턴은 기록으로 보존하며 이전 85턴 상한을 새 작업에 적용하지 않는다. 현재 추가 사용은 **제작용 이미지 4회·제품 AI 0턴**이다. 이후 사용을 두 원장에 구분해 더한다. 승인 결론은 Issue #25에 기록했다.

## 실제 제품 코드와 시제품의 경계

제품 변경은 진입 화면(`Manager`), 연결 안내(`ConnectionGuide`·`PetPreferencesConnector`), 프롬프트 예시(`PromptIdeaLibrary`·`promptIdeas`·`PromptArtwork`), 선택·적용(`UiPetStudio`·`PetWorkspace`·`petCatalog`), 공통 펫 모션(`CompanionPet`·`CompanionFigure`·`Pet`·`TaskPetArt`·`PetOverlay`·`ExplicitPet`), 결과 시안(`ResultSamples`)과 각 스타일·검사다. 준비 완료와 현재 채팅 연결을 구분하고, 작업 중 인사로 실행 모습을 덮지 않는다. 내 작업의 작은 카드에서도 역할에 관계없이 실제 상태를 재생한다. 완료 반응의 수신 확인·해시·잠금·한 번 재생 규칙은 유지한다.

이미지·영상용 펫은 기존 `research-document` 역할과 고정 `autopets-research-document / 1.0.0` 스킬을 사용해 프롬프트를 정리한다. 새 역할 ID·DB·연결 API를 추가하지 않는다. 선택한 기본 방향은 1536바이트 이내의 기존 지침에 담고 현재 요청을 우선한다. 생성 도구를 호출하거나 생성 결과를 보장하지 않는다. 기존 일반 조사·문서 구성을 이미지 펫으로 잘못 분류하지 않도록 이름이 맞는 경우만 연결한다.

선택 가능한 채팅이 하나면 준비 화면에서 그 대상을 미리 선택한다. 끊김·도움 꺼짐·미확인 실행은 제외하며, 선택 후 새 스냅샷 때문에 다른 채팅으로 자동 전환하지 않는다. 저장·적용의 대상/개정·재조회 검증과 명시적 적용은 그대로다.

## 다른 AI에서 펫 설정 재사용

`/v1/pet-library`는 기존 loopback 인증과 Origin 거부를 그대로 사용한다. 목록에는 이름·ID·개정·역할만, 개별 읽기에는 일치하는 ID/개정의 저장한 펫만 반환한다. 기존 계정/채팅 바인딩과 대화는 포함하지 않으며 상태 변경 이벤트를 내보내지 않는다. 새 DB 테이블이나 기존 API 필드 변경은 없다.

`integrations/mcp`는 목록·선택한 개정 읽기 두 도구만 제공한다. 반환값에서 실행 모델·추론 설정·계정·폴더·인증값을 제외하고, 스킬은 참조이며 실제 읽기 확인이 아님을 표시한다. 구형 앱·오래된 개정·다른 펫 응답·과대 메시지는 실패로 처리한다. 초기화와 도구 목록 조회는 앱이나 연결 파일을 읽지 않는다.

`scripts/package-pet-preferences.mjs`는 소스 다섯 개만 고정 순서로 묶는다. 앱 개발·빌드와 UI 검사 준비 때 생성하며 인증값·로컬 설정·Node 런타임·새 의존성을 포함하지 않는다. 생성 파일은 Git에서 제외한다. Windows 앱은 명시적 버튼으로 앱에 포함된 고정 파일을 다운로드 폴더의 AutoPets에 내보낸다. 임의 경로나 바이트를 UI에서 받지 않으며 고유한 파일명·create_new로 기존 파일을 보존한다. 브라우저 미리보기는 일반 다운로드를 사용한다. 파일 저장·실제 Claude 설치·권한 허용·활용은 별도 검증이다. 상세: [MCP 연결](../../integrations/mcp/README.md).

시제품 진입점은 `apps/desktop/tests/ux-flow-preview.html`이며 `src/development/UxFlowPreview.tsx`를 직접 읽는다. 제품 진입점에서 import하지 않아 제품 번들·Tauri·오버레이에 포함되지 않는다. 가상 상태는 시제품 안에서만 바뀌고 실제 채팅, 클립보드, 파일, 연결, 생성 도구에 전달되지 않는다. 공유 `PromptArtwork`는 제작한 정적 이미지와 SVG 구도 예시를 표시하며, 이미지 로딩 실패 시 기존 SVG를 사용한다. 정적 참고 이미지는 영상처럼 움직이거나 재생 버튼을 표시하지 않는다.

이미지는 [제작 기록](../../apps/desktop/public/assets/prompt-gallery-v1/README.md)과 [원문·해시](../../apps/desktop/public/assets/prompt-gallery-v1/manifest.json)를 보존한다. 도구가 반환하지 않은 모델 식별자·seed를 추측해 적지 않는다. 프롬프트를 정리하는 펫의 검증과 이 제작용 이미지 호출은 별개다.

검토 방법:

```powershell
pnpm --filter @autopets/desktop exec vite --host 127.0.0.1 --port 1421 --strictPort
# http://127.0.0.1:1421/tests/ux-flow-preview.html
node apps/desktop/tests/ux-flow-preview-ui.cjs
```

제품 개발 서버와 시제품 검사는 별도 포트를 사용해 기존 서버를 교체하지 않는다. 실제 설치 앱·스킬 실행·모델 요청을 사용하지 않는다.

## 현재 PC 설치와 Codex 등록 전환 · 2026-11-04

설치본은 PR head `feed9cda2d5cbaaea629e548412b3820e6731ff2`를 포함한 CI 검사 병합 `b50d8a2abde368b4c55ab81822360249ad7331a4`의 미서명 검토판이다. 공개 Release나 실제 병합과 다르다. 설치 파일 SHA256은 `b27988a3c627fce86ca221a3f8522ed0758d33e4f485e51f65f4aef37807562e`, 설치된 앱 SHA256은 `7a4e28e6413112be14b48f700843fecd11ae5fb685f55ba4c2fde5bab4cd8df3`이며 CI 측정값과 대조했다. 사용자가 SmartScreen 이후 일반 설치 화면으로 넘어갔음을 확인했고, 보안·신뢰 승인을 자동화하거나 보호 설정을 바꾸지 않았다.

첫 확인에서 표준 Codex의 AutoPets 호출 파일은 다른 설치의 실행 도구를 가리켰고, AutoPets 관리 기록의 소유 경로·해시와도 일치하지 않았다. 그대로 실행하면 새 검토판을 시험했다는 근거가 되지 않는다. **소유자가 새 검토판으로 전환하고 GitHub에 이유와 기록을 남기도록 선택했다.** 결론·이유·범위·결정한 사람·날짜는 [Issue #25](https://github.com/swaan-kim/autopets/issues/25)에 기록했다. 팀 회의나 동료 검토 승인을 대신하지 않는다.

기존 등록·관리 파일을 비공개로 백업하고, 승인 후 원본 해시·앱 해시·설치 패키지 162개 파일의 무결성을 재확인했다. 승인된 기존 AutoPets 등록의 소유 기록을 이관한 뒤 설치본에 포함된 `--installed-resource … --connect --app-executable …` 관리 연결 도구로 갱신했다. 새 등록의 안내·Node 실행 파일·연결 도구가 모두 새 설치본 내부를 가리키며, 등록 내용의 해시와 소유 기록이 일치한다. 오래된 채팅 ID나 Orca 프로필 오버라이드는 하위 프로세스에 넘기지 않았다.

원본 백업은 보존했고 다른 Codex 설정·훅·이전 프로필 등록 파일의 전후 해시가 일치한다. 원래 개발 폴더는 수정하지 않았다. 전환 후 DB를 설치 전 읽기 전용 백업과 다시 대조하여 기존 17개 테이블과 기존 행이 모두 보존된 것을 확인했다. 실제 앱의 인증된 `/v1/pet-library` 읽기는 성공했지만 현재 채팅은 `connecting` / `waiting-for-event`이며 `chatConnected:false`다. 호출 등록 완료를 실제 일반 입력·펫 작업·모델 설정·다른 호스트 활용의 성공으로 표시하지 않는다. 개인 경로·등록 파일 원본·인증값·DB 원본은 Git이나 공개 Issue/PR에 넣지 않는다.

## 펫 모션·결과 카드 후속 개선

소유자가 설치판의 정지 오버레이와 끊기는 자세 전환, 낮은 완성도의 결과 카드를 지적했고 디자인 틀 변경까지 허용했다. 연결 전 오버레이가 일시정지되고, 카탈로그는 마우스를 올리기 전 정지하며, 활동 중에는 적은 자세 그림을 낮은 빈도로 바꾸는 코드를 확인했다. [Code Pet](https://github.com/Xiaooolong/code-pet)의 절차적 SVG 행동과 [ChatGPT Pets](https://learn.chatgpt.com/docs/pets)의 상태 구분·동작 줄이기를 참고했다. 외부 캐릭터·코드·훅은 복제하지 않았다.

- 같은 강아지의 머리·귀·눈·앞발·꼬리를 별도 관절로 그리고 CSS로 연속 재생한다. `Pet`을 포함한 제품 표면이 공통 렌더러를 사용하며 그림 파일을 내려받을 필요가 없다. 연결 전에는 대기 동작만 하고, 실행·계획·대기·오류는 관측된 상태와 구분한다. 작업 중 클릭은 인사로 작업 모습을 바꾸지 않는다.
- 머리의 상태 전환과 꼬리의 대기 동작을 화면 프레임 단위로 표본 관측했다. 새로운 도형 교체 없이 중간 자세가 이어지고, 연결 없는 오버레이에서도 대기 모션이 재생된다. 완료는 새 확인 이벤트 한 번만 반응하며 복구·중복·다른 채팅·숨김·동작 줄이기 검사도 유지했다. 주기적 AI나 프레임별 React 상태 갱신은 없다.
- 플래너·여행·개념 요약·광고·슬라이드 예시를 각각 완성된 시안 구성으로 교체했다. 광고·여행에는 기존 승인 자산을 재사용했다. 카드는 쉬운 출처 표기를 사용하고 원본 이름·링크·라이선스는 상세에 유지한다. 모두 디자인 예시이며 실제 스킬 결과로 표시하지 않는다.
- 갤러리에서 제작 원문을 펼칠 때 사진이 아래로 밀리던 배치를 수정했다. 표시한 기본 조건도 선택한 펫 지침에 포함하며, 영상 참고 이미지가 실패해도 재생 모양으로 바뀌지 않는다.

설치된 기존 검토판의 실제 **Claude용 연결 파일 받기** 버튼도 확인했다. 새 파일 1개, 19,944바이트, SHA256 `f8a820918d9060e25942f5a6ddc6331eb99b609ec35d77f5a0c4adeca023e10c`이며 기존 파일을 덮어쓰지 않았다. 처음 로컬 LF 파일과 비교한 ZIP 해시는 달랐으나, 각 파일의 차이는 Git 체크아웃의 줄바꿈뿐이었다. 커밋된 소스에 Windows 체크아웃 필터를 적용해 같은 ZIP 바이트를 재현했다. 이 내보내기는 실제 Claude 확장 설치·도구 활용의 성공이 아니다.

일반 입력 준비 중 시험용 PowerShell 5 스크립트의 UTF-8 한글이 잘못 해석되어 보내기 전 입력문이 깨졌다. 사용자가 화면을 지적한 뒤 실행 스크립트를 명시적 UTF-8 읽기·UTF-16 명령 전달로 고치고 요청문·한글 폴더의 URI 왕복을 확인했다. 앱 제품 문구가 깨진 원인으로 확대하지 않는다. 사용자가 현재 ChatGPT에서 다른 작업 중임을 확인했으므로 그 입력창이나 진행 중 요청은 덮어쓰지 않았다. 실제 AI 전송 0턴·제작 이미지 4회는 그대로이며 일반 입력 전체 흐름은 미통과다.
