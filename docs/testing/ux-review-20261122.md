# 화면 점검 첫 실행 — 시작 흐름 (2026-11-22)

[화면 점검](../development/ux-review/README.md) 도구를 처음 써 본 기록이에요. 도구가 제대로 동작하는지 확인하고, 다음 화면 수정 PR이 쓸 고칠 목록을 만드는 게 목적이에요. **아무 화면도 고치지 않았어요.**

## 1. 요약

- **범위:** 홈 → 펫 고르기 → 펫 상세 → "Codex에서 시작". 대상은 `origin/main`(PR #97 문구 통일 병합 전).
- **목표 일:** 처음 쓰는 사람이 "다음 주 수업 발표자료 만들기"를 Codex로 시작하기. Codex는 아직 연결 전.
- **근거 수준:** 합성 검사예요. `pnpm test:ui`가 찍은 가상 상태 화면과 코드를 봤고, 실제 앱 실행이나 사용자 관찰은 하지 않았어요.
- **방법:** 다섯 관점을 서로의 결과를 보지 않고 따로 돌렸어요(가벼운 모델). 자동 점검은 `pnpm ux:check`예요.
- **가장 큰 문제 세 가지:**
  1. 시작하기 전에 고르고 이해해야 할 것이 많아요. 시작할 곳(Codex/Claude), 연결 동의, "가볍게"를 처음 보는 말과 함께 마주쳐요. 다섯 관점 중 네 관점이 짚었어요.
  2. 펫 고르기 화면에 다른 일이 섞여 있어요. 펫 6개 아래에 "함께 쓰는 도구" 8개와 이미지·영상 갤러리가 이어져요. 도구의 "발표자료(PowerPoint)"와 발표자료 펫이 같은 목표 앞의 두 길이에요(세 관점).
  3. 확인하지 않은 것을 확인한 것처럼 말해요. 앱은 링크를 열 뿐인데 "요청을 넣었어요"라고 말하고, 카드에 붙은 ✓ 약속("없는 사실은 지어내지 않아요")은 AI에게 부탁한 것일 뿐이에요(정직 관점).

## 4. 하지 않은 것과 이유

- 화면 수정: 이번 PR은 도구만 만들어요. 수정은 PR #97 병합 뒤 별도 PR에서 이 목록으로 해요. 같은 파일을 두 PR이 동시에 바꾸지 않기 위해서예요.
- 회의가 필요한 항목(시작할 곳 기본값, 화면 구조, 저장 흐름)은 Issue에 안건으로 올려요.
- 실제 앱 실행과 사용자 관찰은 하지 않았어요.

## 도구에 대해 배운 것

- 다섯 관점이 같은 문제를 다른 근거로 짚었어요. 겹친 수로 우선순위를 정할 수 있었어요.
- 자동 점검은 말 바꿈만 잡았어요(경고 8). 가장 큰 문제(판단이 많음, 화면이 김, 과장된 표현)는 관점 점검에서 나왔어요.
- 펫 고르기 화면과 펫별 상세 화면은 UI 검사가 찍지 않아 숫자를 못 쟀어요. 점검용 화면 찍기를 UI 검사에 더하는 것이 다음 개선이에요.
