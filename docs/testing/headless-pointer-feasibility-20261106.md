# 실제 마우스를 점유하지 않는 시험 환경 확인

2026-11-06 · 담당 swaan-kim · 인계 작업 [#44](https://github.com/swaan-kim/autopets/issues/44).

사용자가 작업 중인 마우스를 넘겨주지 않아도 펫의 드래그·클릭 반응을 검사할 수 있도록, **별도 헤드리스 브라우저 안의 가상 포인터가 동작하는지** 확인했다. AutoPets 제품의 모션 품질·오버레이·AI 연결을 통과시킨 검사는 아니다.

## 재현하기

저장소의 기존 Node.js 24·pnpm 11.19.0 환경과 잠긴 의존성을 사용한다. 새 라이브러리는 추가하지 않았다. 처음 준비하는 별도 개발 환경에서만 다음 설치가 필요하다.

```powershell
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
```

이미 준비된 환경에서는 다음 명령 하나로 실행한다.

```powershell
node scripts/probe-headless-pointer.mjs
```

이 명령은 새 헤드리스 Chromium과 비영속 컨텍스트를 만든다. 페이지는 `about:blank`의 합성 도형·버튼뿐이고 오프라인 설정과 페이지 요청 차단을 함께 사용한다. 설치 앱, 실제 AI, 계정, 사용자 브라우저 프로필에는 연결하지 않는다.

실행마다 `work/headless-pointer-probe/sample-…/`에 `result.json`과 합성 화면 `fixture-after.png`를 남긴다. 이전 결과를 덮어쓰거나 자동 삭제하지 않는다. 실패하면 같은 폴더의 `failure.json`을 먼저 읽고 원인을 확인한다. 원본 오류에는 개발 환경 경로가 포함될 수 있으므로 공개 기록에는 필요한 요약만 옮긴다.

## 관찰 결과

로컬 Node.js 24·Playwright 1.62.1·Chromium 151.0.7922.34에서 다음을 확인했다. 이 인계에 포함한 재현 스크립트로도 같은 조건을 검사한다.

| 확인 항목 | 결과 |
| --- | --- |
| 가상 포인터 이동 | 31개 이동 이벤트 관찰. 요구 조건은 30개 이상 |
| 누르기 → 드래그 → 놓기 | 각 1회, 합성 도형 위치가 `(120, 100)`에서 `(340, 190)`으로 이동 |
| 합성 카드 버튼 | 1회 클릭, `Fixture card open` 표시 |
| 페이지·입력 | `about:blank`, 헤드리스 브라우저의 `page.mouse`와 페이지 버튼 사용 |
| 물리 입력과 실제 제품 | 스크립트에서 네이티브 자동화·클립보드 API 사용 없음, 설치 AutoPets 변경 없음 |
| 제품 AI·이미지 생성 | 추가 0회 |

물리 커서 위치를 전후 측정한 보안 감사가 아니라, **네이티브 입력 경로를 사용하지 않는 독립된 브라우저 실험**이다. 사용자가 보고 있는 Windows 화면이나 실제 펫을 시험한 것으로 해석하지 않는다.

## 무엇을 이어서 만들까?

이 스크립트는 입력 가능성만 재현한다. 다음 제품 검수 화면은 기존 제품 렌더러를 그대로 사용하고, 시간·가상 포인터·합성 작업 이벤트를 주입하도록 만들어야 한다. 시험용 펫 동작을 따로 다시 구현해 통과시키지 않는다.

1. 같은 입력 기록으로 대기·시선·접촉·들기·놓기·작업 전환을 전후 비교한다.
2. 자세의 연속성과 실제 프레임 지연을 따로 본다. 평균 fps나 영상 인코딩 fps 하나로 자연스러움을 판정하지 않는다.
3. 포인터 취소, 드래그 뒤 클릭 방지, 숨김, 동작 줄이기, 완료 반응 한 번과 A/B 격리를 유지한다.
4. 실제 Tauri 창 이동·투명창 클릭 영역·배율·다중 모니터는 별도 Windows 시험 세션에서 확인한다. 브라우저 성공으로 대신하지 않는다.

[Vercel agent-desktop의 Windows 지원표](https://agent-browser.dev/desktop/platforms/windows)에 따르면 의미 기반 조작과 실제 포인터 조작의 범위는 다르다. 이 도구는 선택적인 네이티브 검사 후보이며 현재 설치하거나 시험하지 않았다. 기본 검수를 물리 입력 모드로 자동 전환하지 않는다.
