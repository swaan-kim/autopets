# AutoPets 화면 기준

기존 앱의 차분한 바탕, 입체 강아지와 읽을 수 있는 결과 예시를 유지한다. 이 문서는 현재 CSS와 확인해 둔 화면에서 재사용할 원칙을 추린 기준이다. 외부 라이브러리·유료 서비스·레퍼런스 검색을 작업의 필수 조건으로 추가하지 않는다.

## 먼저 재사용할 것

실제 값의 기준은 [앱 바탕과 글꼴](../../apps/desktop/src/app/style.css), [관리 화면](../../apps/desktop/src/app/manager.css), [펫 상세와 시작](../../apps/desktop/src/features/pets/pet-composer-simple.css)이다. 새 화면에서도 기존 컴포넌트·선택자를 먼저 사용하고 값이 다르면 해당 CSS의 현재 선언을 따른다.

| 요소 | 현재 기준과 적용 방법 |
| --- | --- |
| 색 | 흰 바탕, `--surface`의 `#fafafa`, `--tint`의 `#f3f4f5`로 면을 구분한다. 본문은 `--ink` `#292c31`, 보조 글은 `--muted` `#656b74`, 경계는 `--line` `#e8eaed`를 우선한다. |
| 글 | Pretendard와 기존 대체 글꼴을 사용한다. 본문·선택 항목은 14~16px, 상세 제목은 기존 22~26px 위계를 따른다. 긴 설명을 작고 흐린 글자로 줄이지 말고 내용을 덜어낸다. |
| 간격·모서리 | 관련 항목 사이는 8~12px, 묶음 사이는 16~24px를 우선한다. 입력·버튼은 기존 12px 안팎, 카드·말풍선은 14~16px 안팎의 모서리를 재사용한다. 기능마다 새 모양을 만들지 않는다. |
| 행동 | 한 작업 영역의 주요 행동은 하나를 먼저 보인다. 기존 시작 버튼의 진한 중립 바탕을 사용하고 보조 행동은 텍스트·중립 버튼으로 둔다. 새 주요 버튼은 높이 44px 이상을 확보한다. |
| 상태 | 이름·짧은 문장·아이콘으로 전달한다. 오류·경고·성공의 의미가 있을 때만 기존 상태색을 쓴다. 단순 추천·복습·준비 중에 새 파란색이나 보라색을 배정하지 않는다. |

장식용 유색 상단선·유색 외곽선·색 그림자·강한 그림자는 사용하지 않는다. 일반 카드는 그림자 없이 면·얇은 중립 테두리·여백으로 구분한다. 떠 있는 말풍선에 깊이 표현이 꼭 필요하면 기존의 약한 중립 그림자 하나만 쓴다.

## 고르기에서 시작까지

- 목록은 **펫 이름 → 맡길 일 한 줄 → 읽을 수 있는 결과 예시**로 훑어본다. 같은 카드에서 같은 뜻의 ‘선택·살펴보기·시작’을 반복하지 않는다. 목록·상세·확대는 같은 펫과 결과 자료를 사용한다.
- 상세는 결과 예시 옆에 입력과 주요 행동을 모은다. 390px처럼 좁은 창에서는 입력·시작이 큰 미리보기보다 먼저 나온다. 출처·고급 설정·추가 예시는 기존 `details/summary`로 펼친다. 결과를 제한하는 조건은 시작 곁에서 읽힌다.
- 참고 사진처럼 없어도 되는 자료에는 **(선택)**을 붙인다. ‘추천받기·아직 모르겠어요’가 유효한 선택이면 제공한다. 이미 입력한 조건을 다시 묻거나, 선택 자료가 없다는 이유로 시작을 막지 않는다.
- 형식·디자인 추천은 같은 작업 흐름에서 고치고 확정한다. 화면에 긴 전문가 설정표를 늘리지 않는다. 공부·복습처럼 특화 기능은 사용자가 고른 펫의 상세 안에서만 하위 화면으로 들어가며, 다른 펫의 메뉴·채팅 연결·입력을 바꾸지 않는다. 뒤로 가면 입력·설정이 유지된다.

## 반응과 접근성

마우스 반응은 배경의 작은 변화나 펫의 자연스러운 기울임으로 보여 준다. 상세 등장 동작은 한 번 뒤 멈추고, 동작 줄이기에서는 정지 상태로 읽을 수 있어야 한다. 기존 펫의 상태 관측과 움직임을 장식 개선 때문에 중단하지 않는다.

키보드 `:focus-visible` 표시는 기존 중립색 외곽선으로 유지한다. 테두리를 줄이라는 규칙이 초점 표시를 지우는 이유가 되지 않는다. 기본·포인터·키보드 상태를 구분해 확인하고, 펼친 내용과 뒤로 가기에서도 초점이 이어져야 한다.

## 추린 레퍼런스와 남길 원칙

| 근거 | AutoPets에 남기는 원칙 |
| --- | --- |
| Agensi의 스킬 상세, Base44의 예시와 시작 카드, Notion의 갤러리·상세 구분. [기존 관찰 기록](../product/ui-reference-library-20261115.md)과 #125에서 확인한 배치 | 결과를 보고 같은 자리에서 시작하며, 출처·보조 설명은 아래에서 펼친다. 타사의 색·화면 전체를 복제하지 않는다. |
| [Fluent 2 색상](https://fluent2.microsoft.design/color) | 중립색으로 위계를 만들고 의미 있는 상태색을 장식에 쓰지 않는다. Fluent 라이브러리나 새 색상 체계를 도입한다는 뜻은 아니다. |
| [GOV.UK 질문 화면](https://design-system.service.gov.uk/patterns/question-pages/) | 선택 자료는 항목명에서 알리고, 필요한 정보만 한 번 묻고 뒤로 돌아가 수정할 수 있게 한다. 질문마다 새 앱 페이지를 만들지는 않는다. |
| [WAI 펼치기 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) · [키보드 초점](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html) | 보조 내용의 열림 상태와 키보드 조작, 보이는 초점을 보존한다. |

위 공식 자료는 2026-11-27 확인했다. Agensi·Base44·Notion은 저장소의 기존 관찰에서 채택한 원칙이며, 구독 화면에 다시 접속해야 적용할 수 있는 규칙이 아니다. 참고 화면은 실제 AutoPets 사용성 검증과 구분한다.

화면 검증은 기존 [공동 검사와 전후 비교](team-workflow.md#pr-설명-작성하기)를 따른다. 새 필수 도구나 검사표를 추가하지 않는다.
