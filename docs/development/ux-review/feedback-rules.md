# 쌓이는 점검 규칙 — 사람이 말한 불만이 다음 점검의 기준이 돼요

화면을 보고 누군가 "이건 어려워요", "이건 필요 없어요"라고 말하면, 그 말이 한 번 고치고 끝나지 않도록 **규칙 한 줄**로 남겨요. 다섯 관점은 점검할 때마다 이 파일을 함께 읽어요. 자동으로 셀 수 있는 규칙은 `pnpm ux:check`에도 넣어요.

## 규칙을 더하는 순서

1. **말 받기** — 팀원(또는 사용자 관찰)이 화면에 대해 한 말을 그대로 적지 말고, 무엇이 문제인지 한 줄로 줄여요. 대화 원문이나 개인 정보는 남기지 않아요.
2. **규칙 한 줄로** — "앞으로 이렇게 해요"의 형태로 써요. 예: "버튼 옆 설명이 버튼과 같은 말이면 빼요."
3. **어느 관점인지** — 처음 사용·문구·덜어내기·숫자·정직 중 하나를 붙여요.
4. **자동으로 셀 수 있나** — 셀 수 있으면 `scripts/check-ux-copy.mjs`에 규칙을 더하는 일도 같은 PR에 넣어요. 셀 수 없으면 관점 점검이 읽는 규칙으로만 남겨요.
5. **PR로** — 이 파일과(필요하면) 점검 명령을 고친 PR을 올려요. 다른 한 사람이 승인하면 규칙이 돼요. AI는 규칙을 제안할 수 있지만 스스로 확정하지 않아요.

규칙이 쌓여 서로 부딪히면 정직 관점이 우선이고, 오래된 규칙은 PR로 고치거나 지워요.
