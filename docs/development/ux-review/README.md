# 화면 점검: 누구나 같은 기준으로

AutoPets는 AI를 잘 모르는 사람이 쓰는 앱이에요. 화면은 **쉬운 말, 짧은 문장, 꼭 필요한 것만** 보여 줘야 해요. 이 점검은 사람의 감 대신 같은 기준을 쓰기 위한 도구예요. 팀원 누구나, 자기 AI(Codex·Claude Code)로 똑같이 돌릴 수 있어요.

**언제 쓰나요?** 화면(`apps/desktop/src`의 `.tsx`·`.css`·문구가 든 `.ts`)을 바꾸는 PR을 열기 전에요. 큰 화면 개편 전에 현재 화면을 진단할 때도 써요.

## 한 번에 돌리기

AI에게 이렇게 말하면 돼요.

```text
ux-review 스킬로 <바꾼 화면이나 파일>을 점검해줘.
```

- Claude Code: `.claude/skills/ux-review`와 `.claude/agents/ux-*` 에이전트를 써요.
- Codex: `.agents/skills/ux-review`를 써요. 각 관점은 하위 작업으로 나눠 돌려요.
- 두 스킬은 같은 내용이고, 관점별 기준은 모두 이 폴더의 [personas](personas/)에 있어요. 기준을 고칠 때는 이 폴더만 고치면 돼요.

## 순서

1. **범위 정하기** — 바꾼 화면과 사용자가 그 화면에서 하려는 일 한 가지를 적어요. 예: "상세 화면에서 Codex로 시작하기".
2. **자동 점검** — `pnpm ux:check --files <바꾼 파일...>`로 문구를 점검해요. 화면 이미지는 `pnpm test:ui`가 `work/after-*.png`에 남기거나, `pnpm dev`로 띄워 찍어요.
3. **다섯 관점으로 따로 보기** — 아래 다섯 관점을 서로 결과를 보지 않게 따로 돌려요. 같은 화면을 다른 눈으로 봐야 놓치는 것이 줄어요.
4. **합치기** — 같은 문제는 하나로 묶어요. 두 관점 이상이 짚었거나 숫자로 확인된 문제를 먼저 고쳐요. 순서는 공동 안내와 같아요: **작업을 막는 문제 → 잘못된 상태 → 불필요한 조작 → 보기 좋음**.
5. **고치고 다시 재기** — 담당 범위 안에서만 고쳐요(`pnpm ui:scope <담당> <파일...>`). 고친 뒤 같은 숫자를 다시 재서 전후 표를 만들어요.
6. **PR에 남기기** — [보고서 양식](report-template.md)의 요약 표와 전후 화면 이미지를 PR의 "사용 흐름과 전후 비교"에 넣어요.

## 자동 점검이 보는 것 (`pnpm ux:check`)

| 항목 | 예 | 수준 |
| --- | --- | --- |
| 증명할 수 없는 약속 | "사용량을 절감해요", "모델을 바꿔 드렸어요" | 실패 |
| 어려운 말 (주요 화면만) | MCP, 훅, 세션, 프롬프트, 토큰, 개정 | 경고 |
| 긴 문장 | 한 문장 50자 초과 | 경고 |
| 같은 뜻 다른 말 | 대화 → 채팅, 누르세요 → 눌러 주세요, 클릭 → 누르기 | 경고 |
| 딱딱한 말투 | ~습니다, ~십시오 | 경고 |

- 이미 있던 문구는 [기준선](copy-baseline.json)에 있어요. **새로 생긴 것만** 실패로 알려요. 고쳐서 줄면 `pnpm ux:check --update-baseline`으로 기준선을 줄여요. 기준선을 늘리는 갱신은 PR에서 이유를 적어요.
- `pnpm test`에서는 검사기의 동작을 확인해요. 화면 문구 점검은 필요할 때 직접 실행해요. 설정·실험 화면(`features/settings`, `workflow` 등)은 어려운 말 검사를 하지 않아요.
- AI에게 넘기는 요청문("…해줘", `petId=`)과 사용자 말 예시는 화면 문구가 아니라서 건너뛰어요.
- 자동 점검은 글자만 봐요. 화면이 실제로 쉬운지는 다섯 관점과 사람의 검토로 판단해요.

## 말한 불만이 기준이 되게

화면에 대한 불만이나 개선 요청은 한 번 고치고 끝내지 않고 [쌓이는 점검 규칙](feedback-rules.md)에 한 줄로 남겨요. 다섯 관점은 점검할 때마다 이 규칙을 함께 읽어요. 규칙은 PR로 더하고, 다른 한 사람이 승인해야 확정돼요.

## 지켜야 할 것

- 점검 결과는 AI의 판단이 섞여 있어요. 사람의 검토와 승인을 대신하지 않아요.
- **실제 실행 / 합성 검사 / 디자인 예시**를 구분해 적어요. 숫자는 어떻게 쟀는지(자동 / 화면을 보고 셈)를 함께 적어요.
- 점검용 화면 이미지와 보고서에 개인 경로·대화 내용·계정 정보를 넣지 않아요.
- 다른 담당의 파일은 합의 없이 고치지 않아요. 기능을 빼는 제안이 흐름·데이터를 바꾸면 [사전 회의](../team-workflow.md#큰-변경은-먼저-회의) 대상이에요.
