# 제작 펫 사용하기 — 명시적 호출 MVP

현재 검증 대상은 Windows 로컬 Codex다. 설치된 AutoPets와 기존 Codex 채팅을 연결하고, 사용자가 맡긴 작업만 펫의 설정으로 하위 작업에 전달한다. 일반 대화의 모델은 그대로다. 실제 설치 검증 결과는 [가능성 기록](../testing/mvp-feasibility.md)을 확인한다.

## 시작

1. AutoPets를 열고 **연결 설정 → 이 AI 연결하기**를 누른다. 설치된 연결 도구와 AutoPets 스킬을 준비한다. 이 방식은 새 훅 허용을 요구하지 않는다.
2. 사용할 Codex 채팅에서 **제작 펫 연결**이라고 보낸다. 연결 확인과 앱의 해당 채팅 카드가 모두 나타나야 한다.
3. 카드에서 다음 펫 작업 설정을 선택한다. **가볍게 / 표준 / 꼼꼼하게** 중 고를 수 있다. 지원 모델이 확인되지 않으면 새 작업을 실행하지 않는다.
4. **제작 펫으로 … 해줘**처럼 작업을 맡긴다. 이번 요청만 다른 설정을 원하면 **이번만 꼼꼼하게**라고 덧붙인다.

스킬을 찾지 못하면 Codex의 스킬 목록에서 AutoPets가 나타나는지 확인한다. 기존 작업을 마친 후 앱을 다시 열어 스킬을 새로 읽을 수 있다. 스킬이 준비됐다는 표시만으로 실제 채팅 연결을 완료 처리하지 않는다.

## 계획하고 구현하기

**제작 펫으로 … 만들 계획만 세워줘. 아직 파일은 수정하지 마.**

펫이 계획을 반환하면 **계획 확인 필요**가 된다. 같은 채팅의 현재 계획을 검토한 뒤 **그대로 구현해줘**라고 요청한다. 계획이나 설정이 바뀌면 어떤 계획을 실행할지 다시 확인한다. 이 과정은 계획 프롬프트이며 Codex의 실제 Plan 모드 강제가 아니다.

## 상태와 복구

- **실행 요청 / 작업 중:** 펫에 맡긴 작업이 준비됐거나 실제 실행을 확인했다.
- **계획 확인 필요:** 계획 작업이 끝났고 사용자의 구현 요청을 기다린다.
- **완료:** 해당 하위 작업의 결과 반환과 실행 기록을 대조했다. 전체 프로젝트 완료를 뜻하지 않는다.
- **확인 필요:** 앱 재시작, 연결 끊김 또는 기록 누락으로 현재 실행을 확인하지 못했다. 같은 채팅에서 **펫 상태 확인**을 요청한다. 기존 작업을 다시 실행하지 않는다.
- **도움 끄기:** 새 펫 작업을 막는다. 이미 실행 중인 Codex 작업은 계속되며 결과 확인은 가능하다.
- **추적 정리:** 복구할 수 없는 작업의 펫 추적만 종료한다. 실제 Codex 작업을 취소하지 않는다. 원래 작업 상태를 확인한 뒤 새 요청을 보낸다.

창의 X는 숨김이며 앱의 **AutoPets 종료**가 정상 종료다. 다시 연결하면 저장한 작업 설정을 재사용한다. 채팅 연결을 직접 해제하면 그 채팅의 연결 설정도 해제된다.

## 지원 범위

모델·강도는 펫이 맡은 하위 작업에 적용된다. 부모 채팅 설정 변경, 일반 요청 전체의 자동 위임, 실제 Plan 강제, Work, Jev, 공유 사이트는 이번 MVP에 포함하지 않는다. 실행 확인은 로컬 Codex 기록을 대조하며 서버 내부 처리 모델을 독립적으로 증명하지 않는다. 부모 턴과 하위 작업의 사용량이 함께 발생한다.
