# 구현 순서와 검증 관문

2026-09-21 승인 방향은 [제품 정의](../product/direction.md)다. 기존 M0–M6의 추적 번호는 보존하되, 실제 연결 관문은 **활성화·출시 주장**에 적용한다. 설치 없이 기능 코드와 격리 테스트를 구현하는 것은 허용된다. 실제 M1 관문을 통과했다고 표시하지 않는다.

| 단계 | 구현 결과 | 남은 관문 |
| --- | --- | --- |
| M0 기반 | 정식 체크아웃·제품 문서·GitHub 추적 | 후속 기능은 각 단계 관문에서 검증 |
| M1 연결 실증 | Codex 준비/기록 helper, Chrome 확장·Native Messaging, dry-run 설치 도구 | 실제 두 채팅 전달·계정 전환·설정 적용 증거 |
| M2 구조 | apps/desktop·서비스별 연결·공통 규칙과 내부 모듈 분리, 기존 데이터 경로 유지 | Node·UI·Rust·NSIS 회귀 검사 통과. 통합 기록은 M2 #3 / PR #8에서 추적 |
| M3 핵심 도움 | 선호·채팅 기록·수정·끄기·삭제·짧은 지침 | 실서비스에서 자동 전달·정상 턴 기록 검증 |
| M4 펫 경험 | 작은 작업 카드·상세 3탭·개별 숨김/종료·18프레임 연결 | 네이티브 DPI/모니터/포커스 실제 검증 |
| M5 알파 | 검수용 빌드·연결 ZIP·24개 평가 자료 | 최초 설치 흐름, 서명, 실제 PC 실행·복구·제거, 사용자 5명 검증 |
| M6 확대 | 환경별 capability와 독립 adapter | 다른 브라우저·ChatGPT Desktop/Work·타사 AI 검증 |

개발 순서는 연결 실증 → 준비·기억·설정 → 검증된 자동 선택 → 결과 점검·효율 평가 → 설치·알파다. 모델 자동 변경·추론 수준 변경·추가 응답 보완은 코드 정책/검증 경로가 있어도 실제 연결 검증 전 비활성이다.

## 정정과 현재 제한

- 과거 WindowsApps 경로 진단은 접근 거부였지만 이후 일반 Codex CLI로 읽기 전용 진단은 실행됐다. 당시 hooks/list는 비어 있었고 원인은 미확정이었다. 이것은 실제 Desktop 전달 증거가 아니다.
- 기존 설치 앱은 이전 빌드다. 이번 변경은 사용자 PC의 앱·hooks/trust·브라우저에 설치하지 않는다.
- UI fixture, Node/Rust 테스트, Windows CI 빌드와 실제 ChatGPT/Codex 연결 증거를 나눈다.
- 브라우저 확장은 계정·모델·전송이 검증되지 않아 실제 페이지를 수정하지 않는다. 상태 조회는 빈 작업 기록도 생성하지 않는다.
- 보안 설정을 끄지 않는다. Windows 개발 빌드 실행 차단은 CI로 검수하되 사용자 PC 실행 허용과 서명을 별도로 확인한다.

기존 [Milestones](https://github.com/swaan-kim/autopets/milestones)와 [M1 Issue](https://github.com/swaan-kim/autopets/issues/2)는 실제 관문 통과 전 닫지 않는다. 단위 테스트 통과로 기능 지원표를 자동 승격하지 않는다.

독립 개발의 역할·파일 소유권·복사할 요청은 [병렬 개발 인계](parallel-development.md)를 따른다.
