# 구현 순서와 검증 관문

사람·AI의 작업 분담과 인계는 [공동 작업 안내](../development/team-workflow.md)를 따른다. 이 문서의 날짜가 있는 실행 묶음과 M0–M6는 당시 범위·이력이며 현재 작업의 담당·완료 기준은 Issue, 실제 변경과 검사는 PR·검수 기록에서 확인한다.

## 현재 실행 묶음 · 2026-10-23

**Codex에서 호출 → 앱에서 펫 선택·정확한 채팅에 적용 → 같은 채팅의 작업 → 결과 복귀·재사용**을 기본으로 정리한다. 할 일은 Codex에서 입력하고 앱의 기존 작성·복사는 보조 기능으로 보존한다. 아래 M0–M6와 과거 설치 제한은 당시의 기록이며 이번 사용자 승인 범위는 [최신 제품·배포 기준](../product/distribution.md)을 따른다.

1. 대상·개정이 있는 연결 해제, 원자적 실행 예약, 모델 목록과 복구의 분리, 파일 저장 재시도와 호스트 기록 호환성 검사를 우선한다.
2. 펫·연결할 채팅·다음 행동 중심 화면과 선택적 표시 별칭을 연결한다. 실행 완료·스킬 확인·결과 품질은 각각 근거를 유지한다.
3. 설치 안내·스킬·소개 웹을 같은 사용 흐름과 배포 식별 기준으로 맞춘다. 공개 파일·일반 설치·서명·Steam은 각각 별도 관문이다.
4. 영향받는 Node·UI·Windows 검사를 수행한다. 일반 입력의 대표 흐름은 승인된 낮은 모델 시험 범위에서 진행하며, 현재 원장·예산·수행 조건은 [서비스 검수표](../testing/pet-service-readiness.md)를 따른다.
5. 타겟 사용자 검사 자료를 현행 흐름으로 갱신한다. 참여자 **0/5**를 임의 통과로 바꾸지 않는다. 실제 편익·7일 재사용·새 PC 보안 정책 검증은 외부 조건으로 남긴다.

최신 실제 실행 근거: [2026-10-21 설치형 검사](../testing/copy-free-installed-20261021.md). 내부 메시지 도구 검사와 일반 입력, CI와 현재 PC 설치, 실행 완료와 품질을 구분한다. 외부 계정·신뢰 승인·등록·결제·문의 발송은 소유자의 별도 단계다. [현재 검수표](../testing/pet-service-readiness.md).

## 이전 단계와 추적 번호

최신 배포 방향은 [전용 앱·두 입구](../product/distribution.md)이며, 설치와 AI 호출을 동등하게 지원한다. 연결 실증 → 시작 경험 통합 → 서명된 소규모 베타 → Store/AI 디렉터리 → 다른 AI 연결 순으로 공개한다. 구현과 격리 검수는 진행하되 실제 설치·공개 배포는 이번 범위에 포함하지 않는다.

2026-09-21 승인 방향은 [제품 정의](../product/direction.md)다. 기존 M0–M6의 추적 번호는 보존하되, 실제 연결 관문은 **활성화·출시 주장**에 적용한다. 설치 없이 기능 코드와 격리 테스트를 구현하는 것은 허용된다. 실제 M1 관문을 통과했다고 표시하지 않는다.

| 단계 | 구현 결과 | 남은 관문 |
| --- | --- | --- |
| M0 기반 | 정식 체크아웃·제품 문서·GitHub 추적 | 후속 기능은 각 단계 관문에서 검증 |
| M1 연결 실증 | Codex 준비/기록 helper, Chrome 확장·Native Messaging, dry-run 설치 도구 | 실제 두 채팅 전달·계정 전환·설정 적용 증거 |
| M2 구조 | apps/desktop·서비스별 연결·공통 규칙과 내부 모듈 분리, 기존 데이터 경로 유지 | Node·UI·Rust·NSIS 회귀 검사 통과. 통합 기록은 M2 #3 / PR #8에서 추적 |
| M3 핵심 도움 | 선호·채팅 기록·수정·끄기·삭제·짧은 지침 | 실서비스에서 자동 전달·정상 턴 기록 검증 |
| M4 펫 경험 | 작은 작업 카드·상세 3탭·개별 숨김/종료·18프레임 연결 | 네이티브 DPI/모니터/포커스 실제 검증 |
| M5 알파 | 검수용 빌드·연결 ZIP·24개 평가 자료 | 최초 설치 흐름, 서명, 실제 PC 실행·복구·제거, 사용자 5명 검증 |
| M6 확대 | 환경별 capability와 독립 adapter | 다른 브라우저·ChatGPT Desktop/Work·타사 AI 검증 |

개발 순서는 연결 실증 → 준비·기억·설정 → 검증된 자동 선택 → 결과 점검·효율 평가 → 설치·알파다. 모델 자동 변경·추론 수준 변경·추가 응답 보완은 코드 정책/검증 경로가 있어도 실제 연결 검증 전 비활성이다.

## 계획·실행 설정 후속 작업

[승인된 제품 범위](../product/planning-execution.md)에 따라 로컬 설정·단계별 지침·제출 보호를 추가한다. 세 프리셋은 평가 후보이고, 보호 관문이 통과되기 전 자동 설정 변경·제출 보류는 활성화하지 않는다.

| 순서 | 결과물 | 완료 증거 |
| --- | --- | --- |
| 1 설정·UX | 세 카드, 상세 단계 설정, 계획 확인, 독립 확인 상태 | 화면 fixture·기존 UI 회귀 |
| 2 규칙·저장 | 버전이 있는 별도 저장, 짧은 지침, 개정별 확인·일회성 예외 | Node/Rust 격리 검사 |
| 3 제출 보호 | 관측·준비 훅의 동일 판정, 보류 시 실행 시작 기록 없음 | 훅·브리지 fixture; 실제 보호는 미검증 |
| 4 자동 변경 실증 | 기존 Codex 창에서 모델/추론/Plan 각각 변경·다음 제출 확인 | 별도 실제 환경 검증 필요 |
| 5 평가·확대 | 한국어 24개와 5명 체험 자료 | 실측 후에만 효과·지원 범위 갱신 |

[검수 절차](../testing/planning-execution.md). 이번 구현에서는 설치·신뢰 변경·계정 변경·실제 연결 활성화를 하지 않는다.

## 정정과 현재 제한

- 과거 WindowsApps 경로 진단은 접근 거부였지만 이후 일반 Codex CLI로 읽기 전용 진단은 실행됐다. 당시 hooks/list는 비어 있었고 원인은 미확정이었다. 이것은 실제 Desktop 전달 증거가 아니다.
- 기존 설치 앱은 이전 빌드다. 이번 변경은 사용자 PC의 앱·hooks/trust·브라우저에 설치하지 않는다.
- UI fixture, Node/Rust 테스트, Windows CI 빌드와 실제 ChatGPT/Codex 연결 증거를 나눈다.
- 브라우저 확장은 계정·모델·전송이 검증되지 않아 실제 페이지를 수정하지 않는다. 상태 조회는 빈 작업 기록도 생성하지 않는다.
- 보안 설정을 끄지 않는다. Windows 개발 빌드 실행 차단은 CI로 검수하되 사용자 PC 실행 허용과 서명을 별도로 확인한다.

기존 [Milestones](https://github.com/swaan-kim/autopets/milestones)와 [M1 Issue](https://github.com/swaan-kim/autopets/issues/2)는 실제 관문 통과 전 닫지 않는다. 단위 테스트 통과로 기능 지원표를 자동 승격하지 않는다.

현재 역할·파일 소유권·PR·다음 AI 인계는 [공동 작업 안내](../development/team-workflow.md)를 따른다. [옛 병렬 개발 인계](parallel-development.md)는 당시 역할표의 보존 기록이다.
