# AutoPets 개발 경로 재검토

후속 결정: 사용자는 기존 Codex 작업과 독립 AutoPets 펫 하나를 먼저 완성하는 경로를 선택했다. 현재 실행 범위와 중단점은 [작은 MVP 실행 계획](mvp-execution.md#현재-범위--펫-하나와-기존-codex-작업-2026-09-26)을 따른다. 아래 대안은 비교 이력이며 새 작업 입구/웹 확장/자체 채팅 구현 승인이 아니다.

검토일: 2026-09-26. 사용자 요청에 따른 대안 분석이다. 기존 목표의 승인된 변경이나 새 경로의 구현 완료를 뜻하지 않는다. 원래 목표는 펫으로 역할·스킬·모델 설정을 쉽게 이해하고 재사용하며, 실제 적용과 진행을 확인하는 것이다.

## 판단

현재 가장 큰 위험은 펫 렌더링이 아니라 **다른 앱이 소유한 기존 작업을 외부에서 정확히 제어하는 일**이다. 이 조건을 제품 전체의 선행 관문으로 두면 펫의 가치 검증까지 호스트 내부 연결 문제에 묶인다. 기존 작업 유지와 자동 설정 적용 중 무엇이 필수인지 먼저 선택해야 한다.

현재 실증은 Codex/Work 로컬 metadata 조회, 별도 CLI 훅 수신, Work 클라우드·Chat 웹의 선택값 변경과 계획 프롬프트 이행이다. 기존 Desktop의 실제 훅 수신과 배포 가능한 모델/Plan 제어는 미통과다. UI 자동화가 한 번 성공한 것과 일반 사용자에게 배포할 수 있는 연결은 다르다.

## 비교

아래 난이도와 유지보수 평가는 현재 코드·실증·문서에 근거한 개발 판단이며 실측 개발 기간이나 성공 확률이 아니다.

| 경로 | 강점 | 핵심 한계 | 추천 용도 |
| --- | --- | --- | --- |
| 기존 Desktop 외부 제어 + 독립 펫 | 기존 작업을 유지하는 원래 경험에 가장 가까움 | 공유 실행 제어 미확보, 접근성 불일치, 버전·포커스 의존. 훅은 모델 선택 변경 API가 아님 | 연구 경로로 제한. 새 근거 없이 주 개발 일정 전체를 걸지 않음 |
| 기존 공식 펫 + 역할/스킬 플러그인 | 오버레이·진행·복귀를 재사용, 적은 구현으로 역할 도움의 가치 시험 | 커스텀 펫 외형 선택은 실행 방식을 바꾸지 않음. 펫 선택과 역할 설정 자동 연결은 별도. 자동 라우팅 증거 없음 | 가장 작은 사용자 가치 검증 |
| ChatGPT 웹 확장 + 페이지 펫/사이드패널 | 기존 채팅 유지. DOM에서 대상·선택기·입력창을 다루며 OS 포커스 문제를 줄일 수 있음 | 웹에 한정. 페이지 변경에 대응 필요. 실제 서버 모델·native Plan·첨부 원문은 별도 관문 | 기존 채팅 유지가 최우선일 때 첫 제품 후보 |
| 공식 MCP 플러그인 + 대화 안 펫 카드 | 역할 선택·저장·설명·결과 확인 UI를 호스트 안에 배치 | iframe 범위. 전체 앱 모델/Plan 제어, 다른 채팅 감시, OS 오버레이를 제공하는 API로 해석할 수 없음 | Chat/Work에 역할 도구를 전달하는 경로 |
| AutoPets 작업 시작 + Codex App Server/SDK | 자신이 만든 작업의 모델·추론·지침·이벤트를 직접 관리. 자체 제출/승인 흐름 구성 가능 | 별도 작업 입구가 생김. 기존 Chat/Work 대화를 그대로 제어하는 기능 아님. 권한·중단·기록 UI를 책임져야 함 | 자동 라우팅이 필수일 때 기술 실증 우선 후보 |
| 별도 모델 API 기반 서비스 | 실행 흐름을 가장 직접적으로 설계 | 별도 비용·인증·호스팅과 채팅 제품 부담. 기존 구독/기존 채팅 목표와 멀어짐 | 현재 제약에서는 제외 |

## 공식 기능과 함의

[공식 Pets](https://learn.chatgpt.com/docs/pets)는 Windows/macOS 부유 펫, 입력 필요·진행·완료·오류 표시, 작업 목록과 대화 복귀를 설명한다. 선택한 펫은 외형을 바꾸며 작업 수행 방식을 바꾸지 않는다고 명시한다. 따라서 AutoPets의 차별점은 캐릭터/상태 표시보다 역할·설정·작업 절차의 재사용과 실제 적용이어야 한다. 계정·워크스페이스별 가용성은 별도 확인한다.

[공식 플러그인](https://learn.chatgpt.com/docs/plugins)은 Chat/Work/Codex 지원 표면에서 스킬과 MCP 도구를 배포하는 경로다. 훅은 실행 환경에 실제 파일이 있어야 하며 웹에서 설치하는 것만으로 스크립트가 배치되지 않는다. [MCP UI](https://developers.openai.com/plugins/build/chatgpt-ui)는 대화 안 iframe, 도구 호출, 후속 메시지, 모델에 보이는 문맥 등을 제공한다. 이 문서에서 호스트 모델 선택기나 native Plan 제어 API를 확인하지 못했으며 서비스 전체의 불가능 판정은 아니다.

Chrome [content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)는 DOM 읽기·변경을, [sidePanel](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)은 브라우저 패널을 제공한다. 따라서 첫 버전은 확장만으로 페이지 펫·역할 선택·초안 준비를 실증할 수 있다. 독립 데스크톱 펫이 필요하면 이후 [Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)으로 기존 Tauri 앱과 연결할 수 있지만 설치 구성은 늘어난다. DOM 경로는 ChatGPT의 공식 모델 제어 API가 아니므로 별도 호환성 검사가 필요하다.

[App Server](https://learn.chatgpt.com/docs/app-server)는 자체 클라이언트를 위한 인증·작업 이력·승인·스트리밍 이벤트를 제공하며 턴별 모델·추론·협업 모드 인자를 문서화한다. ChatGPT 관리 로그인도 제공하므로 별도 유료 API 키가 반드시 필요한 설계는 아니다. 실제 사용 가능한 계정·모델·한도·배포 조건은 별도로 확인해야 한다. 로컬 stdio를 우선 시험하고 실험적/production 미지원으로 표기된 WebSocket 경로를 안정된 배포 연결로 간주하지 않는다. [SDK 문서](https://learn.chatgpt.com/docs/codex-sdk)는 작업 자동화와 자체 클라이언트의 App Server 용도를 구분한다.

이 경로는 자체 대화 서비스 전체를 만들 필요 없이 **작업 요청·계획 확인·상태·결과를 담은 작은 작업 카드**부터 시작할 수 있다. 그래도 AutoPets가 별도 작업의 입력과 권한을 책임진다는 제품 변경은 남는다. Codex 런타임에 ChatGPT로 로그인하는 것을 ChatGPT Chat/Work 전체 제어로 표시하면 안 된다.

## 추천하는 다음 결정 실험

기존 Desktop 제어는 근거가 생기면 재개하는 연구 항목으로 두고, 다음 두 후보를 같은 최소 과제로 비교하는 것을 제안한다. 아직 실행하지 않았으며 사용자 선택 전 새 AI 턴이나 설정 변경을 하지 않는다.

1. **기존 채팅 후보:** 브라우저 확장 한 개로 정확한 A/B 식별 → 역할 1개 → 모델 선택값 변경/재조회 → 원문 보존 → 계획 응답 → 펫 상태. 다른 채팅 변경 0건을 확인한다. 첫 시험은 텍스트만, 자동 재전송은 끈다. 서버 모델을 관측하지 못하면 표시값 확인까지만 판정한다.
2. **직접 실행 후보:** 기존 Tauri의 작은 카드에서 전용 Codex 작업 시작 → 가용 모델 조회 → 모델/추론 변경 3회 → 실행 전 역할 지침 → Plan/실행 전환 → 이벤트·결과 표시. 계획 중 합성 파일 변경 0건과 확인 후 의도한 변경을 별도로 검사한다. native Plan과 파일 쓰기 권한 제한은 구분한다.
3. **가치 비교:** 두 역할 중 하나로 같은 결과물을 만들고 추가 설치 수, 설정 조작 수, 준비 실패, 계획/실행 경계, 잘못된 작업 영향, 복구 가능성을 비교한다. 효과를 일반 절감률이나 수요 입증으로 확대하지 않는다.

실제 AI 예산은 이미 사용한 보수적 13/30, 이번 상한 18/30에서 유지한다. 남은 5회 안에서 성립 여부를 볼 수 있는 시험만 먼저 설계하고 부족하면 범위를 줄이거나 별도 결정을 받는다. 기존 코드의 펫 자산·역할 저장·계획 개정·SQLite·설치 검사는 재사용 가능하다. 새 경로 선택을 이유로 전면 재작성하지 않는다.
