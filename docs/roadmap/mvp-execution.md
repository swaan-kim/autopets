# AutoPets 전체 기능 최소 실증 실행

## 기존 작업 제어 우선: 최신 중단점 (2026-09-26)

현재 우선순위는 **창 자동 조작보다 훅 연결**이다. 새 작업 프롬프트 채우기, 자체 채팅, 펫 연출은 진행하지 않는다. 실제 AI는 추가 호출 없이 **6/30턴**이며 이번 묶음의 상한 18/30을 유지한다.

1. **준비 검사 완료:** 제품 소스 `28d1f6c`의 Node 173건·화면·Windows Rust 116건 통과. 최초 bootstrap 실패는 같은 설치본 재검사에서 재현되지 않았다. 하네스 `7369338`의 [재검사](https://github.com/swaan-kim/autopets/actions/runs/36208436056)에서 bootstrap과 별도 깨끗한 Windows의 설치 수명주기·데이터 보존을 통과했다. 최초 실패 원인까지 해결했다고 표시하지 않는다.
2. **훅 연결 우선:** A/B의 프로젝트 계층 활성, 훅 기능 기본값 `true`, 관측 정의 각 8건, 모두 `untrusted`, 오류 0. 설치 AutoPets는 appReady=true, chatConnected=false다. 신뢰 검토는 사용자가 정확한 정의를 확인하는 단계이며 대신 승인하지 않는다. Desktop에서 실제 검토할 정의가 나타나는 경로부터 확인해야 한다. 현재 8개는 관측 전용이므로 지침 전달 성공으로 세지 않는다.
3. **다음 최소 실험:** 신뢰가 확인된 뒤 A 한 턴에서 시작·도구·완료 수신을 확인하고 B 격리를 검사한다. 그다음 별도 동기 UserPromptSubmit 훅으로 3KB 이하 지침 전달 시점을 확인한다. 화면을 열거나 모델을 자동 호출하는 동작이 훅 수신의 필수 조건이라고 가정하지 않는다.
4. **모델/Plan은 별도:** 별도 App Server의 기존 A metadata 조회는 성공했지만 `thread/settings/update`는 `not-loaded` 상태에서 -32600으로 거절됐다. 원래 모델·추론은 그대로다. 공유 Desktop 제어 경로가 확보되기 전 자동 라우팅과 native Plan을 활성화하지 않는다. 오류 10050 경로는 반복하지 않았다.
5. **UI 경로 보류:** 별도 시험 창은 만들 수 있었다. 그러나 접근성 정보 지연/이전 작업 반환 및 편집 포커스 확인 실패가 남아 제출하지 않았다. 사용자의 훅 우선 질문에 맞춰 화면 조작을 보류했다. 시험 A 창은 빈 입력 상태로 남아 있고 모델·추론·Plan·사용자 초안은 변경하지 않았다. 기존 전용 훅 준비 상태도 이번 실행에서 변경하지 않았다.

상세 판정과 설치본 SHA는 [최신 실증 기록](../testing/mvp-feasibility.md#기존-작업-제어-우선-재검사-2026-09-26)에 있다. 이 중단점은 핵심 외부 제어 통과나 전체 MVP 완료가 아니다.

## 재개 범위: 외부 연결 0–3 (2026-09-26)

사용자가 승인한 이번 묶음은 미완성 코드·패키지 정리 → 실제 연결 → 모델/추론 변경 → 첫 지침·native Plan·계획 프롬프트·제출 보호까지다. 이후 펫 연출이나 꾸미기로 자동 진행하지 않는다. 실제 AI 누계 6/30에서 추가 최대 12턴(이번 종료 시 최대 18/30)을 사용한다. 현재 작업 정보 조회는 기존 채팅 제어·실시간 구독의 증거가 아니다.

- Codex 로컬, Work 로컬, Work 클라우드, Chat 앱, Chat 웹을 각각 판정한다. 공식 외부 인터페이스, 배포 가능한 플러그인/확장, UI 자동화 순으로 확인한다.
- `thread/settings/update`는 로컬 프로토콜에 존재하는 시험 후보다. 별도 서버에서만 바뀌거나 내부 Codex 도구로만 성공하면 외부 Desktop 제어는 미통과로 남긴다.
- 첫 지침은 새 빈 시험 작업에서 첫 모델 실행 전에 전달돼야 한다. native Plan 상태/실행 제한과 계획 프롬프트의 전달/이행을 별도 판정한다.
- 동일 원인 수정 후 최대 두 번 재시험한다. 로그인·신뢰·보안 검토는 사용자 몫이며, 막힌 기능의 독립 코드 검사는 계속한다.
- 0단계에서 새 runtime/조회 CLI의 설치 패키지 누락을 수정하고, 메타데이터 가져오기·계층 표시·Work 상태 격리 검사를 보완했다. 전체 Node 173건, UI(pageErrors 0), 빌드·레이아웃은 통과했다. Windows 검사 결과는 해당 커밋에 별도로 연결한다.

## 환경별 독립 판정

사용자 추가 확인: Codex뿐 아니라 **ChatGPT Work와 일반 ChatGPT Chat**도 실제 가능성을 확인한다. `provider=openai`라는 공통점만으로 설정이나 지원 상태를 공유하지 않는다.

| 대상 | 구분해서 확인할 항목 |
| --- | --- |
| Codex Windows 로컬 | 작업 식별·이벤트·모델/추론·Plan·지침·제출·복귀 |
| ChatGPT Work 로컬 | 같은 항목을 별도 작업/호스트에서 확인. Codex 결과 전용 금지 |
| ChatGPT Work 웹/클라우드 | 로컬 Work와 별도 연결 수단·접근 조건·실행 범위 |
| 일반 ChatGPT Chat 웹 | 실제 로그인/작업/모델 식별, 확장과 입력 보존, 가능한 설정 범위 |
| 일반 ChatGPT Chat 앱 | 웹/Work와 분리해 UI 접근·작업 식별·설정/지침·복귀 확인 |

모든 환경의 실제 시험은 기존 총 30턴 한도 안에 포함한다. 기본 Work 2턴을 유지하되 Chat 실증은 사용하지 않은 핵심·복구 예산을 사전 재배분해 기록한다. GUI 중단 상태에서는 코드·공식 문서·연결 계약 검사부터 계속하고 로그인/GUI 실증을 통과로 처리하지 않는다.

Work·일반 Chat의 연결 가능성 조사는 9단계까지 미루지 않는다. 2단계에서 각 환경의 공식 연결 경로·대상 식별을 먼저 판정하고, 가능한 경로에만 3–4단계의 모델/추론·지침·Plan·제출 검사를 적용한다. 같은 OpenAI 계정이나 공통 런타임을 사용하더라도 다른 환경의 통과 결과를 상속하지 않는다. 일반 Chat에 native Plan이나 훅이 없으면 해당 기능은 별도로 미지원/미확인으로 기록하고, 계획 지침 제공과 구분한다.

## 예산과 증거

실제 AI 시험은 최대 **30턴**(Codex 핵심 16, 비교 10, Work 2, 복구 2). 재시도·계획·실행·시험 자식도 포함하며, 미사용분은 전용할 수 있다. 개발 검사·빌드·읽기 전용 RPC는 AI 턴이 아니다. 실제 요청 전에 로컬 원장에 예약하여 불확실한 전송도 이중 사용하지 않는다.

원본 진단과 턴 원장·재개 위치는 Git에서 제외한 `work/mvp-goal/20260925-minimum/`에 둔다. 전체 대화나 인증값은 보고서에 포함하지 않는다. [판정 기록](../testing/mvp-feasibility.md)은 환경·버전·커밋·입력·예상·실제·증거 수준·다음 조건을 구분한다.

## 완료 기준

각 항목에 최소 실험 결과 또는 구체적인 외부 차단 조건이 있고, 실행 가능한 검사와 관련 회귀 검사가 끝나야 한다. 미검증 클라이언트가 지원 상태를 올릴 수 없어야 한다. 사용 가능한 앱, 검토 가능한 코드, 재현 명령, 다음 시작 지점을 남긴다. 최소 실증 완료와 공개 제품 완성을 구분한다.
