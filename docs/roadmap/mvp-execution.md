# AutoPets 전체 기능 최소 실증 실행

## 진행 중 — 설치형 명시적 호출 MVP (2026-09-27)

최신 승인 목표는 **설치 앱 → 일반 Codex 입력의 제작 펫 연결 → 계획 → 명시적 구현 → 실제 펫 표시 → 정상 종료/재시작 후 재사용**이다. 시간제한 대신 완료 조건을 사용한다. 실제 AI 시험은 기존 25턴 + 추가 최대 20턴으로 누계 45턴을 상한으로 한다. Work·훅 자동화·Jev·공개 배포는 제외한다.

- 설치 연결은 스킬 준비와 명시적 펫 통신을 사용한다. 새 훅 정의나 신뢰 변경을 요구하지 않는다. 기존 훅은 유지한다.
- 진행 중 도움 끄기는 새 작업만 막고 결과 관측은 유지한다. 재시작 후 같은 자식의 기록을 다시 확인하며 불명확한 실행을 재전송하지 않는다.
- 앱에서 프로필을 선택하고 요청/관측 설정을 구분한다. 미확인 실행은 명시적인 추적 종료로 정리할 수 있으나 실제 Codex 작업 취소를 뜻하지 않는다.
- 기존 설치/데이터를 백업한 뒤 현재 PC의 전용 A/B에서 검사한다. CI 전용 설치·제거 도구는 사용자 PC에서 실행하지 않는다.
- 변경된 Node·UI·Windows Rust·설치본 검사를 마치고 실제 일반 입력과 오버레이를 검증해야 완료다. 현재 구간은 **구현/검사 중**, 실제 설치 통합 통과를 주장하지 않는다.

원본 진단·예산·재개 위치: Git 제외 `work/mvp-goal/20260927-installed-mvp/`. 아래 기록은 이전 완료 체크포인트다.

## 현재 체크포인트 — 명시적 연결 MVP (2026-09-27)

승인된 작은 흐름을 구현했다: **기존 채팅의 스킬 → 제작 펫 연결 → 설정에 맞는 native 하위 작업 → 결과 대조 → 펫 상태**. 화면 조작, 별도 AI 실행기, 부모 모델 변경 없이 실제 전용 Codex 작업에서 시험했다. 이후 훅 자동화는 독립 관문이다.

| --- | --- | --- |

| 지침·스킬 | 짧은 역할 지침과 고정 스킬 경로를 위임 입력에 전달 | 자식의 스킬 읽기 호출 및 파일 계산 도구 사용 확인. 효과·품질 우월성 평가 아님 |

Node **205/205**, 화면 빌드·UI, Windows Rust **119 passed / 2 ignored** 및 설치·연결·복구·제거 검사 통과. 재현된 설치 탐색 5초 중단은 15초의 유한 대기로 보완했다. 전체 native 종료/재시작 검사와 설치 GUI의 펫 통합은 별도다. 최종 Windows 검사와 설치본 식별은 [가능성 기록](../testing/mvp-feasibility.md)에 기록한다. AI 예산은 기존 17 + 이번 부모 4/자식 4 = **25/30**이며 추가 실행은 중단했다. 원본 진단은 Git 제외 `work/mvp-goal/20260927-explicit/`에 보관한다.

### 재현·지원 조건

- 배포된 스킬의 [명시적 연결 절차](../../integrations/codex/skills/autopets/references/explicit-pet.md)를 사용한다. 번들 Node와 연결 도구는 개발 소스와 분리한 패키지 복사본으로, 다른 전용 시험 폴더에서 호출했다.
- 실제 시험은 Windows 10.0.26200, Codex Desktop 26.917.6896.0 / runtime 0.155.0-alpha.16이다. native 도구의 모델·강도 인수와 로컬 작업 색인/기록 형식이 있어야 한다. 다른 버전은 재검증한다.
- UI 없는 격리 실행은 실제 Rust 저장소·HTTP 코드를 실행했지만 설치 GUI 앱은 교체하지 않았다. 설치본 전체의 사용자 PC 통합 성공으로 확대하지 않는다.
- 새 요청만 native 실행한다. 결과 반환만으로 완료 표시하지 않으며 부모/자식/턴/설정 기록을 대조한다. 불확실한 요청은 재전송하지 않는다.
- 사용자가 명시적으로 요청한 펫 작업 경로다. 한 번 연결했다고 모든 일반 요청을 자동 위임하지 않는다. 스킬을 호출하는 부모 턴과 자식 실행 비용이 함께 든다.

### 다음 한 구간과 중단점

이번 구간은 **조건부 연결 경로의 구현·실증 완료**다. 자동 훅 라우팅 또는 공개 MVP 완성으로 판정하지 않는다. 다음에는 새 설치본에서 스킬 발견 → 일반 입력의 “제작 펫 연결” → 실제 오버레이 표시 → 정상 종료/재시작을 한 번 연결해 검사한다. 현재 설치 앱/데이터를 바꾸는 작업은 이 체크포인트에 포함하지 않았다. 그 뒤 Desktop 훅 수신 실패 원인을 조사하고 자동화 여부를 결정한다. Work/MCP/Jev/공유 사이트로 자동 진행하지 않는다.

아래 절은 이전 관문·진단의 시간순 이력이며 최신 상태는 위와 같다.

## 현재 실행 — 펫 하위 작업 라우팅 MVP (2026-09-26)

최신 사용자 선택은 **원래 채팅의 모델을 유지하고, 펫이 맡은 하위 작업의 모델·강도를 선택하는 방식**이다. 최초 연결에서 역할·스킬을 설정하고 이후 저장된 기본값을 적용한다. “이번만 가볍게/표준으로/꼼꼼하게”는 해당 요청에만 적용한다. 모든 요청에 계획을 강제하지 않는다. 화면 조작·자체 채팅·추가 판단 모델·Jev·Work 확대는 이번 실행에서 제외한다.

실제 AI 예산 누계는 **17/30**(기존 재시도 예산 포함), 최신 승인 상한은 **30/30**이다. 이번 관문에 부모 시험 3회와 자식 1회를 사용했다. 기본 Luna/low, 모델 변경 Sol/low, 같은 모델 강도 검사는 Sol/medium까지만 사용한다. 가용 조합을 먼저 조회하며 없으면 임의 대체하지 않는다.

1. 공식 custom agent와 부모·자식 훅의 실제 Desktop 수신을 먼저 검증한다. 설정 파일 발견이나 별도 CLI 성공은 Desktop 통과가 아니다.
2. 통과 후 기존 연결 대기를 재사용해 펫 설정을 저장하고 라우팅 호출·지침·스킬을 연결한다. 부모가 실제 위임하지 않으면 미실행으로 기록한다.
3. 부모/자식/요청/설정 개정을 분리한 저장·수신 계약을 추가하고 기존 펫 상태를 연결한다. 기존 strict 이벤트 계약은 유지한다.
4. 계획·구현, 기본 적용, 모델·강도 변경, A/B, 재시작·끄기·오류를 실제 시험한다. Node·UI·Windows 및 영향받는 보존 검사를 완료한다.

현재 구현: 자식 훅이 부모 관측·지침·계획 보호를 변경하지 못하도록 분리했고, 형제 자식별 중복 키를 분리했다. 순수 프로필 선택/생성 및 별도 자식 메타데이터 관측 도구를 추가했다. 별도 관측 도구는 **격리 수신기 실증용이며 설치 앱의 위임 API·자동 라우팅·펫 통합은 아직 없다.** 일반 설치의 훅 정의를 자동 변경하지 않는다.

전용 A에 네 프로필(light/standard/careful/plan)과 `AutoPets pet delegation gate v1` 정의 7개를 준비했다. 사용자의 검토 후 **새 7개와 기존 11개 모두 trusted**, 오류 0을 확인했다. 추가 신뢰 검토는 필요하지 않다. 원본·백업·패키지 해시·원장은 Git에서 제외한 기존 run 폴더에 보관한다.

소스 `3952703`의 실제 시험 결과는 다음과 같다.

- 전용 프로필 선택: 현재 Desktop에 노출된 도구에는 `agent_type` 선택 인수가 없어서 자식 실행 없이 종료했다. TOML 발견을 실제 선택으로 계산하지 않는다.
- 별도 native 호출: `spawn_agent`에 Luna/low를 명시한 요청과 자식 결과 반환을 확인했다. 자식 실행 기록의 모델·강도, 프로필 자동 선택, 스킬 적용은 아직 미검증이다. 내부 도구 호출 성공은 외부 AutoPets 연동 성공이 아니다.
- 실제 일반 입력: 사용자가 전용 A 입력창에 한 번 제출했고, 일반 사용자 메시지와 응답 표식·완료를 확인했다. AutoPets DB의 A 세션/이벤트는 없고, 실행 중인 앱의 대상 조회는 HTTP 404 `task-not-observed`다. 후속 재검토에서 custom_tool_call 형식의 도구 호출을 확인했다. 당시 수집기 누락이며 훅 미수신 판정은 유지한다. 신뢰 완료와 이벤트 수신을 구분한다.
- 내부 시험 발송은 도구 응답 형태로 기록됐다. 이를 일반 입력 훅의 증거로 쓰지 않는다. 자식 관측기는 지정 프로필의 자식만 받으므로, 그 수신 0건만으로 모든 훅이 실행되지 않았다고 단정하지 않는다.
- [Windows CI 36243544358](https://github.com/swaan-kim/autopets/actions/runs/36243544358) 통과: Node 195, UI/빌드, Rust 116(1 ignored), NSIS 및 bootstrap 검사. 별도 native lifecycle 재검사는 실행되지 않아 이전 간헐 재시작 문제는 미해결이다.

**중단점:** 신뢰 검토는 끝났지만 Desktop 실제 이벤트 전달과 외부 자동 위임 연결은 미통과다. 다음에는 새 AI 요청을 반복하기 전에, 기존 요청에서 Desktop이 훅을 실행했는지와 실행됐을 경우 실패 위치를 구분할 호스트 진단이 필요하다. 그 뒤 실제 자식 실행 설정·스킬과 수신을 대조한다. 별도 CLI 실행기로 전환하거나 설치 앱의 자동 라우팅·펫 통합을 활성화하지 않았다.

첫 관문이 막히면 원인과 다음 조건을 기록하고 독립 검사를 끝낸다. 완성 MVP라고 보고하거나 별도 실행기로 자동 전환하지 않는다. 아래 무화면 기존 채팅 제어 계획은 이전 목표의 진단 이력이다.

## 현재 범위 — 화면 조작 없는 연동 MVP (2026-09-26)

사용자가 승인한 최신 범위가 아래 과거 계획보다 우선한다. **기존 Codex 작업에서 펫을 한 번 연결한 뒤, 이후 같은 요청의 첫 모델 실행부터 설정·지침·스킬을 적용하고 펫으로 진행을 표시한다.** 화면 클릭, 입력창 자동 조작, 새 작업 시작 보조, 자체 채팅은 연결 경로에서 제외한다. 과거 UI 결과는 참고 이력이며 복원 클릭도 재개하지 않는다.

제작·구현 펫 하나, 역할 지침 하나, autopets-build-implementation@1.0.0 하나를 사용한다. 고정 표식은 “계획: …” → gpt-6-astra/xhigh, “구현: …” → gpt-6-astra/high다. 이번 가용 목록에서 두 조합은 발견됐지만 **설정 적용 증거는 없다.** 모호한 요청은 단계를 바꾸지 않는다. 계획 프롬프트는 실제 Plan 모드와 구분한다.

| 순서 | 만들거나 확인할 최소 동작 | 통과 기준 | 현재 상태·다음 조건 |
| --- | --- | --- | --- |
| ① 통신 | 실제 Desktop 소유 서버·기존 작업 식별, 공식 외부 인터페이스 → 배포 가능한 플러그인 | 기존 작업 조회와 설정 명령 전달이 같은 소유 서버에서 가능 | **핵심 차단.** Desktop 자식 서버는 stdio, 해당 PID TCP 수신 0. 설치 코드의 로컬 공용 daemon 경로는 Windows 제외. 별도 서버의 A/B 조회는 가능하나 작업 상태 not-loaded. 외부 제어 주소 미확보 |

모든 환경의 실제 시험은 기존 총 30턴 한도 안에 포함한다. 기본 Work 2턴을 유지하되 Chat 실증은 사용하지 않은 핵심·복구 예산을 사전 재배분해 기록한다. GUI 중단 상태에서는 코드·공식 문서·연결 계약 검사부터 계속하고 로그인/GUI 실증을 통과로 처리하지 않는다.
