# 명시적 제작 펫 연결

설치된 bundled Node와 이 스킬의 `scripts/pet.mjs`를 사용한다. 호스트가 제공한 `CODEX_THREAD_ID`와 실제 작업 폴더를 유지한다. 다른 ID로 환경변수를 덮어쓰거나 `--thread`를 만들어 전달하지 않는다. 현재 호스트의 Codex 실행 파일 절대 경로를 확인하고 `--codex`로 전달한다. 알 수 없다면 경로를 추측하지 않는다.

모든 호출에 `--codex <현재 호스트 실행 파일>`과 필요하면 `--connection <앱의 연결 파일>`을 붙인다. 인증 파일 내용은 출력하지 않는다. 도구는 작업 ID/폴더를 호스트 정보와 대조한다. 현재 연결은 Windows 로컬 Codex만 지원한다.

## 연결

`pet.mjs connect`는 명시적 호출 때 설치된 앱을 열고 정확한 현재 채팅을 연결한다. `ok:true`, 같은 작업 ID, `link.connected:true`가 반환돼야 연결 완료다. 연결 도구가 저장 후 재조회한다. 이미 연결됐다면 재사용하며, 꺼진 도움을 임의로 켜지 않는다. 훅 신뢰는 이 연결의 선행 조건이 아니다. 앱이 응답하지 않으면 자동 설치나 원래 요청 재전송을 하지 않는다.

`pet.mjs status`로 현재 설정을 읽는다. `settings --profile light|standard|careful|plan`은 사용자가 요청한 기본값 변경에만 사용한다. 기본 light=Luna/low, standard=Sol/low, careful=Sol/medium, plan=Luna/low이며 현재 가용 목록에서 확인돼야 한다. `disable`, `enable`, `disconnect`는 해당 채팅에만 적용한다.

## 요청한 펫 작업 한 번

1. 현재 실제 native 하위 작업 도구가 모델·추론 강도 지정과 결과 반환을 지원하는지 확인한다. 미지원이면 여기서 멈춘다. 별도 CLI/서버나 새 채팅으로 대신하지 않는다.
2. `pet.mjs prepare`를 호출한다. 사용자가 이번만 가볍게/표준으로/꼼꼼하게/계획만을 지정했을 때만 해당 `--profile`을 붙인다. 이 선택은 저장된 기본값을 바꾸지 않는다.
3. `dispatchAllowed:true`인 새 요청만 실행한다. 반환된 `requestId`, `requestedModel`, `requestedEffort`, `instruction`, `skillPath`를 사용한다. 요청이 이미 예약됐거나 응답을 잃었다면 조회만 하고 다시 실행하지 않는다.
4. 실제 native 도구에 모델·강도와 반환된 `taskName`을 명시하고, 반환된 지침과 필요한 작업 입력을 전달한다. 전체 대화를 복사하지 않는다. 선택 스킬을 읽고 적용하며 추가 위임은 하지 않도록 전달한다. 원래 채팅의 모델은 변경하지 않는다. 자식 경로가 반환되면 즉시 `spawned --request <ID> --agent-path <반환된 경로>`로 저장하고 아래 `observe`로 시작 기록을 한 번 확인한 뒤 호스트의 대기 도구를 사용한다. 아직 기록이 없으면 실행 요청 상태를 유지하고, 작업을 다시 만들지 않는다. 경로 저장 실패도 재위임의 이유가 아니다.
5. 결과가 돌아오면 `pet.mjs returned --request <ID>`를 호출한다. 이는 결과 반환 보고이며 실제 실행 설정 확인이 아니다. 도구의 명시적 실패에는 `failed --request <ID>`를 사용한다. 단순 시간 초과는 실행 실패/취소로 단정하지 않는다.
6. `observe --request <ID>`로 저장된 자식 경로의 기록을 대조한다. 경로 저장 전 실패했다면 native 도구가 실제 반환한 `--agent-path <경로>`를 전달할 수 있다. 현재 버전의 로컬 작업 색인을 읽기 전용으로 조회해 부모·경로·시각이 일치하는 유일한 자식 기록만 대조한다. 이 연결은 로컬 기록 형식에 의존하는 조건부 지원이다. 호스트에서 UUID와 기록 경로를 직접 제공하면 대신 `--child <UUID> --turn <UUID> --record <절대 JSONL 경로>`를 사용할 수 있다. 이름이나 ID를 지어내지 않는다. 부모 관계·시작 시각·설정을 확인할 수 없으면 미확인으로 남긴다. 대화 내용은 전송하지 않는다.

계획 프로필은 계획을 제시하고 확인을 기다리라는 지침이다. 실제 Plan 모드 강제를 주장하지 않는다. 같은 채팅의 현재 펫 계획 직후 사용자가 “그대로 구현해줘”처럼 명시적으로 실행을 요청하면 펫 작업의 후속 요청으로 처리한다. `status`로 연결·도움·현재 계획을 다시 확인하고 저장된 기본 프로필로 새 작업을 한 번 준비한다. 이전 계획의 원문과 확정 조건만 전달한다. 계획·설정이 바뀌었거나 어떤 계획인지 불명확하면 이전 확인을 재사용하지 않는다. 자식 결과 반환이나 완료는 그 펫 작업의 결과이며 사용자 전체 목표 완료가 아니다.

## 상태 확인과 복구

“펫 상태 확인” 요청에는 `recover`를 사용한다. 같은 현재 채팅의 연결을 재확인하고 저장된 자식의 실행 기록만 다시 읽으며 새로운 AI 실행은 만들지 않는다. 도움을 꺼도 이미 시작한 작업의 관측은 가능하다. 앱이 종료돼 있으면 명시적 요청에 따라 먼저 `connect`로 연 뒤 `recover`한다. 자식 경로가 없으면 도구가 실제 반환한 경로를 찾을 수 있는 경우에만 전달한다.

미확인 작업을 임의로 실패 처리하거나 다시 실행하지 않는다. 사용자가 추적 종료를 명시적으로 요청한 경우에만 `close-tracking --request <ID>`를 사용한다. 앱 카드의 “추적 정리”도 같은 동작이다. 이는 펫의 추적만 종료하고 실제 Codex 작업은 중단하지 않는다. 새로운 작업을 맡기기 전 원래 작업 상태를 확인하도록 안내한다.

현재 훅 자동화와 직접 모델 제어는 활성화하지 않는다. 명시적 펫 작업에 필요한 위임만 수행한다. 사용자가 다른 작업을 요청한 경우 펫 연결 사실만으로 추가 AI 실행을 만들지 않는다.
