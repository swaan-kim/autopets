# 명시적 제작 펫 연결

설치된 bundled Node와 이 스킬의 `scripts/pet.mjs`를 사용한다. 호스트가 제공한 `CODEX_THREAD_ID`와 실제 작업 폴더를 유지한다. 다른 ID로 환경변수를 덮어쓰거나 `--thread`를 만들어 전달하지 않는다. 현재 호스트의 Codex 실행 파일 절대 경로를 확인하고 `--codex`로 전달한다. 알 수 없다면 경로를 추측하지 않는다.

모든 호출에 `--codex <현재 호스트 실행 파일>`과 필요하면 `--connection <앱의 연결 파일>`을 붙인다. 인증 파일 내용은 출력하지 않는다. 도구는 작업 ID/폴더를 호스트 정보와 대조한다. 현재 연결은 Windows 로컬 Codex만 지원한다.

## 연결

`pet.mjs connect` 실행 후 `ok:true`, 같은 작업 ID, `link.connected:true`가 반환돼야 연결 완료다. 연결 도구가 저장 후 재조회한다. 이미 연결됐다면 재사용하며, 꺼진 도움을 임의로 켜지 않는다. 앱이 응답하지 않으면 자동 설치나 원래 요청 재전송을 하지 않는다.

`pet.mjs status`로 현재 설정을 읽는다. `settings --profile light|standard|careful|plan`은 사용자가 요청한 기본값 변경에만 사용한다. 기본 light=Luna/low, standard=Sol/low, careful=Sol/medium, plan=Luna/low이며 현재 가용 목록에서 확인돼야 한다. `disable`, `enable`, `disconnect`는 해당 채팅에만 적용한다.

## 요청한 펫 작업 한 번

1. 현재 실제 native 하위 작업 도구가 모델·추론 강도 지정과 결과 반환을 지원하는지 확인한다. 미지원이면 여기서 멈춘다. 별도 CLI/서버나 새 채팅으로 대신하지 않는다.
2. `pet.mjs prepare`를 호출한다. 사용자가 이번만 가볍게/표준으로/꼼꼼하게/계획만을 지정했을 때만 해당 `--profile`을 붙인다. 이 선택은 저장된 기본값을 바꾸지 않는다.
3. `dispatchAllowed:true`인 새 요청만 실행한다. 반환된 `requestId`, `requestedModel`, `requestedEffort`, `instruction`, `skillPath`를 사용한다. 요청이 이미 예약됐거나 응답을 잃었다면 조회만 하고 다시 실행하지 않는다.
4. 실제 native 도구에 모델·강도와 반환된 `taskName`을 명시하고, 반환된 지침과 필요한 작업 입력을 전달한다. 전체 대화를 복사하지 않는다. 선택 스킬을 읽고 적용하며 추가 위임은 하지 않도록 전달한다. 원래 채팅의 모델은 변경하지 않는다. 자식 경로가 반환되면 아래 `observe`로 시작 기록을 한 번 확인한 뒤 호스트의 대기 도구를 사용한다. 아직 기록이 없으면 실행 요청 상태를 유지하고, 작업을 다시 만들지 않는다.
5. 결과가 돌아오면 `pet.mjs returned --request <ID>`를 호출한다. 이는 결과 반환 보고이며 실제 실행 설정 확인이 아니다. 도구의 명시적 실패에는 `failed --request <ID>`를 사용한다. 단순 시간 초과는 실행 실패/취소로 단정하지 않는다.
6. native 도구가 반환한 정확한 작업 경로를 `observe --request <ID> --agent-path <반환된 /root/... 경로>`에 전달한다. 현재 버전의 로컬 작업 색인을 읽기 전용으로 조회해 부모·경로·시각이 일치하는 유일한 자식 기록만 대조한다. 이 연결은 로컬 기록 형식에 의존하는 조건부 지원이다. 호스트에서 UUID와 기록 경로를 직접 제공하면 대신 `--child <UUID> --turn <UUID> --record <절대 JSONL 경로>`를 사용할 수 있다. 이름이나 ID를 지어내지 않는다. 부모 관계·시작 시각·설정을 확인할 수 없으면 미확인으로 남긴다. 대화 내용은 전송하지 않는다.

계획 프로필은 계획을 제시하고 확인을 기다리라는 지침이다. 실제 Plan 모드 강제를 주장하지 않는다. 확인 후 구현은 사용자가 새로 요청한다. 자식 결과 반환이나 완료는 그 펫 작업의 결과이며 사용자 전체 목표 완료가 아니다.

현재 훅 자동화와 직접 모델 제어는 활성화하지 않는다. 명시적 펫 작업에 필요한 위임만 수행한다. 사용자가 다른 작업을 요청한 경우 펫 연결 사실만으로 추가 AI 실행을 만들지 않는다.
