# Codex 자동 도움 연결 코드

이 연결은 새 설정·SQLite API와 공통 작업 규칙을 사용한다. 기존 `probe/`는 과거 M1 재현용이며 동시에 준비 훅을 설치하지 않는다. 관측 훅과 준비 훅은 계속 분리한다.

현재 배포 capabilities는 미검증이다. 일반 모드에서는 추가 지침을 출력하지 않는다. 실제 검증 담당자가 프로젝트에 `--validation`으로 명시적으로 연결했을 때만 진단용 지침이 나온다. 본 변경에서 사용자 환경에 설치하거나 trust를 바꾸지 않았다.

## 검증 준비

1. 새 빌드의 앱을 테스트 환경에서 실행하고 추천 설정을 켠다.
2. `node integrations/codex/assistance/setup.mjs --project <절대 경로> --connection <connection.json 절대 경로> --validation`으로 변경 계획을 확인한다. 기본은 dry-run이다.
3. 별도 승인된 설치 단계에서 같은 명령에 `--apply`를 넣는다. CLI `/hooks`에서 정확한 정의를 검토한다. 기존 M1 준비 훅은 해당 제거 도구로 제거하고 관측 훅은 유지한다.
4. 스킬 호출 없이 두 실제 Codex 채팅으로 요청, 조건 변경, 재개, 압축 복구를 검증한다. 훅 stdout·전송 receipt와 실제 모델의 지침 수신 증거는 구분한다.
5. 제거는 `--project <경로> --remove --apply`. 타인의 훅·기록·신뢰 설정은 삭제하지 않는다.

## 기록과 부담

- 세션 ID의 해시를 계정 미확인 범위로 사용해 채팅끼리 내용을 공유하지 않는다. 이는 로그인 계정 확인 증거가 아니다.
- 요청 원문은 메모리에서 규칙 분류에만 사용한다. 훅 이벤트와 API에는 원문·도구 출력·대화 기록을 전달하지 않는다.
- 준비 지침은 UTF-8 3KB 이하. 설정·기록·절차·복구 상태가 같으면 추가 지침을 생략한다.
- 응답 길이는 기본 `concise`, 결과 형식은 기본 `adaptive`다. 최신 사용자 요청을 우선하고, 작업의 `workStyleOverride`가 있으면 전역 작업 방식보다 우선한다. 답변 길이·형식은 작업에서 임의로 덮어쓰지 않는다.
- `settingsRevision`을 준비 요청에 함께 보내 설정 변경과 경쟁한 오래된 지침을 거절한다. 적용할 설정과 문맥 개정 번호가 바뀌면 중복 판정을 다시 한다.
- 3KB 안에 저장 문맥을 전부 넣을 수 없으면 `contextPartial`과 `includedContextKeys`를 보내고 지침에도 일부 생략을 명시한다. 키 목록은 해당 필드 전체가 포함된 경우만 가리킨다. 필요한 누락 조건은 기존 실행에서 `inspect`로 읽고, 확인할 수 없으면 추정하지 않는다.
- 기존 실행 모델이 조건이나 결정의 의미 있는 변경을 기록할 때만 `inspect`/`record`를 사용한다. 기록 파일은 `.local/autopets-assistance/records/` 안의 짧은 구조화 JSON이며 Git에서 제외된다.
- JSON 파일은 임시 입력이다. 경로를 검증해 소비한 파일은 성공·실패에 관계없이 제거하며 재시도 시 새로 작성한다. 소비 전 연결 검사 실패나 프로세스 강제 종료로 남은 파일은 이 정리의 보장 범위가 아니다. 영구 업무 기록은 앱의 SQLite에서 관리한다.
- `record`는 CODEX_THREAD_ID, 프로젝트, 현재 관측 턴과 개정 번호를 검증한다. 새 모델 호출이나 반복 요약을 만들지 않는다.
- 현재 턴 종료만으로 목표 달성·모델 변경·전달 확인을 주장하지 않는다. 추가 지침은 현재 사용자 요청과 모드·권한을 우선한다.

정식 자동 지원 표시는 실제 두 채팅 검증 이후 코드의 capability 정책을 검토해 바꾼다. 임의 클라이언트 요청으로 capability를 활성화할 수 없다.
