# 쓰던 AI에서 저장한 펫 구성 읽기

이 연결은 Windows의 AutoPets에 저장한 **사용자가 선택한 펫 한 개의 작업 방식**을 MCP 도구로 읽는다. 지침을 채팅에 다시 붙여넣지 않고 같은 설정을 참고하는 경로다. 새 연결 준비의 검사와 실제 채팅에서의 사용은 구분한다.

## Codex에서 준비하기

1. 이번 기능이 포함된 검토 설치본에서 **연결 설정 → 이 AI 연결하기**를 누른다. 기존 연결에는 **연결 복구**를 사용한다.
2. 호출 스킬과 함께 저장한 펫을 읽는 로컬 도구를 준비한다. Codex Windows 앱이나 `codex.exe`를 찾지 못하거나 기존 설정과 충돌하면 설정을 보존하고 기존 스킬 경로를 유지한다.
3. 도구가 아직 보이지 않으면 하던 작업을 마친 뒤 사용자가 Codex를 재시작한다. AutoPets가 실행 중인 채팅을 종료하거나 요청을 전송하지 않는다.
4. 쓰던 채팅에서 “AutoPets에 저장한 펫을 찾아줘”라고 요청하고 사용할 펫을 고른다. 이 읽기는 펫의 지침 재사용이며 작업 상태 연결·정확한 채팅 복귀·스킬 실행의 확인은 별도다.

설치·앱 시작·AI에서 앱 열기만으로 MCP를 등록하지 않는다. 등록 준비와 실제 사용 성공도 다른 상태다. Orca 개발 대화의 실제 읽기 근거는 [연결 기록](https://github.com/swaan-kim/autopets/issues/29#issuecomment-6666295039)에 있으며, 이번 버튼 경로를 쓴 새 설치/일반 입력은 아직 확인 전이다.

## Claude에서 준비하기

## 사용 흐름

1. 이번 소스의 읽기 기능이 포함된 AutoPets 앱을 실행하고 원하는 펫 구성을 저장한다.
2. 앱의 연결 설정 → 다른 AI에서도 펫 설정 쓰기 → **Claude용 연결 파일 받기**를 누른다. Windows 앱은 다운로드 폴더의 AutoPets에 고유한 이름으로 파일을 저장하고, 브라우저 미리보기는 일반 다운로드를 제공한다. 받은 `.mcpb`를 Claude의 확장 설치 화면에서 선택하고 사용자가 권한을 확인한다.
3. 기존 대화에서 “AutoPets에 저장한 펫을 찾아줘”라고 요청하고 이름·개정을 보고 사용할 펫을 고른다.
4. AI가 `autopets_read_pet`으로 그 펫의 정확한 개정을 읽고 현재 요청에 참고한다. 모델·실행 강도·Plan 모드를 바꾸지 않는다.

`autopets_read_pet`의 `routing`은 저장한 계획·구현 단계를 [공통 라우팅 표](../../packages/contracts/data/routing-profiles.json)로 바꾼 **호스트별 추천**이다(`applied:false`). 저장된 모델 문자열을 그대로 내보내지 않으며, 목록 밖 조합이면 `null`이다. 호스트 설정을 바꾸거나 적용을 확인했다고 주장하지 않는다.

동일 이름의 펫이 여러 개면 임의로 고르지 않는다. 개정이 바뀌면 목록을 다시 읽는다. 이 연결은 저장한 역할 지침과 스킬 **참조**를 제공하며 스킬을 실제 읽거나 실행했다고 주장하지 않는다. 대화 본문·대상 채팅 ID·폴더·계정·토큰을 반환하지 않는다. 앱 ID와 기존 DB·데이터 위치는 그대로다.

## 진행 상황 알리기 (`autopets_report`)

AI가 펫으로 일을 할 때 **어디까지 왔는지**를 이 PC의 AutoPets 앱에 알리는 도구다. 훅이나 스킬 스크립트가 실행되지 않는 환경에서도 화면 위 펫이 "질문이 있어요 / 작업 중 / 다 됐어요 / 문제가 생겼어요"를 보여줄 수 있게 한다. 근거는 [M0 기준선](../../docs/testing/m0-baseline-20261112.md)이다.

- 보내는 것: 상태(`asking`·`working`·`done`·`failed`), 80자 이내의 일 이름, 선택한 펫 ID, 끝났을 때 결과 폴더·파일의 절대 경로. 어느 AI인지는 MCP 클라이언트 이름으로 정한다.
- 보내지 않는 것: 대화 내용, 채팅 ID, 계정, 토큰. 목록에 없는 인수는 거부한다.
- 첫 호출이 `jobId`를 돌려주고, 이후 호출은 같은 `jobId`를 넣는다. 다른 AI가 남의 일을 고쳐 쓸 수 없다.
- 앱은 기록만 한다. 메모리에만 두며(하루, 최대 12건) DB를 바꾸지 않고, AI 작업을 시작·중단·변경하지 않는다. 결과 경로는 실행하지 않고 그 폴더를 탐색기로 보여줄 때만 쓴다.
- 알리지 못해도 도구는 오류 대신 "기록하지 못함"을 돌려준다. 구버전 앱에는 이 기능이 없다는 안내를 준다. 어느 경우에도 AI의 작업은 계속된다.
- 읽기 도구 두 개는 그대로 읽기 전용이다. 실제 AI가 안내대로 이 도구를 부르는지는 아직 실제 실행으로 확인하지 않았다.

## 제작과 검사

```powershell
node --test scripts/tests/pet-preferences-mcp.test.mjs
node scripts/package-pet-preferences.mjs
```

확장에는 Node 소스와 필요한 기존 브리지 모듈만 들어간다. 새 라이브러리·원격 코드·인증값·로컬 설정을 포함하지 않는다. 실행 시 이 PC의 기존 `local.autopets.desktop/connection.json`을 읽으며 인증된 loopback `/v1/pet-library`만 호출한다. 환경 변수 `AUTOPETS_DATA_DIR` 또는 `AUTOPETS_CONNECTION_FILE`은 별도 개발·시험 경로에만 사용할 수 있으며 MCP 도구 인수로 파일 경로를 받지 않는다.

표준 STDIO MCP를 제공하므로 지원하는 로컬 클라이언트에서는 `node <서버의 절대 경로>/main.mjs`로 연결할 수 있다. `main.mjs`는 경로 표기(대소문자·구분자)와 관계없이 항상 서버를 시작한다. Claude Desktop 0.1.0 확장이 소문자 경로로 실행돼 응답하지 않던 문제(2026-11-10, Request timed out)를 막기 위한 진입점이다. 실제 호스트 설정·신뢰·확장 설치는 자동으로 바꾸지 않는다. 구형 앱에 읽기 경로가 없으면 기능 미지원으로 응답하며 다른 경로로 우회하지 않는다. 앱에서 명시적으로 선택한 Codex 연결 외에 다른 호스트 설정·신뢰·확장 설치를 바꾸지 않는다. 구형 앱에 읽기 경로가 없으면 기능 미지원으로 응답하며 다른 경로로 우회하지 않는다.

Codex의 명시적 연결은 [공식 CLI](https://learn.chatgpt.com/docs/extend/mcp)를 비공개 임시 프로필에서만 사용한다. 빈 프로필에서 생성한 AutoPets 항목을 원래 설정 뒤에 추가하고, 기존 설정의 모든 바이트와 다른 MCP 항목이 보존되는지 확인한 뒤 반영한다. 한글·공백 경로, BOM·Windows 줄바꿈을 유지한다. 같은 이름의 타인 설정과 사용자가 수정한 항목은 덮어쓰지 않는다. 백업·소유 기록·임시 프로필은 로컬에만 두며 계정 인증 파일을 복사하지 않는다. 기존 인라인 테이블처럼 항목을 안전하게 덧붙일 수 없는 형식은 보존하고 수동 확인을 안내한다.

읽기 도구와 Node는 해시별 보관본으로 실행하므로 설치 업데이트로 사용 중인 파일을 덮어쓰지 않는다. 같은 Node 버전은 재사용하지만 처음에는 약 94MB의 별도 실행 파일 보관 공간이 필요하다. 연결 해제는 소유한 항목만 제거하고, 이미 열린 관리 도구의 다음 읽기도 로컬 연결 상태 파일로 차단한다. 사용자 수정 때문에 설정을 남겨야 해도 자동으로 호스트를 종료하지 않는다. 사용 중일 수 있는 보관본과 백업은 자동 삭제하지 않는다.

`AUTOPETS_MCP_ACCESS_FILE`은 앱이 관리하는 Codex 도구에만 지정하는 로컬 연결 상태다. 도구 인수로 받지 않으며, 파일이 없거나 꺼져 있으면 앱에 읽기 요청을 보내지 않는다. Claude 확장처럼 이 환경 변수가 없는 기존 읽기 경로에는 영향을 주지 않는다. AI 호출이나 주기적 조회는 추가하지 않는다.

개별 메시지는 64KiB로 제한하고 느린 호스트의 응답 수신을 기다린다. 정상 연결은 누적 메시지 수 때문에 종료하지 않는다. 600개 상태 확인을 처리하는 회귀 검사를 포함하며, 상태 확인 자체는 앱·연결 파일을 읽거나 AI를 실행하지 않는다.

## 지원 경계

Claude 파일 저장은 앱에 포함된 고정 자산만 내보낸다. UI에서 임의 파일·바이트·저장 경로를 받지 않고 기존 다운로드를 덮어쓰거나 확장을 설치하지 않는다. Tauri 자산은 [공식 AssetResolver](https://docs.rs/tauri/latest/tauri/struct.AssetResolver.html)로 읽는다. 개발 모드에서는 먼저 `pnpm build`로 frontendDist를 준비해야 한다. 실제 Claude 설치·활용 검증은 사용자 요청으로 후순위다.

Claude Desktop 로컬 확장과 Claude Code의 지원 표면은 공식 문서와 실제 설치에서 따로 확인해야 한다. ChatGPT 웹·Work 클라우드에는 로컬 STDIO 확장만으로 연결되지 않는다. 원격 서버와 계정 연결 또는 해당 호스트의 로컬 연결 수단을 별도로 구현·검증하기 전 지원을 켜지 않는다. 현재 다른 호스트의 `connectAvailable`과 전체 채팅 공유·자동 훅·부모 모델 변경은 활성화하지 않았다.

이 기능은 펫 설정 재사용을 위한 준비이며 전체 작업 맥락 공유·작업 상태 관측·정확한 다른 AI 채팅 복귀를 완료한 것은 아니다. 생성 도구나 실제 AI를 호출하지 않는다.
